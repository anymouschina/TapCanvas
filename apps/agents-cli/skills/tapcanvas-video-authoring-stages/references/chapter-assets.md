# 共享资产合同

按当前共享资产 artifact 与动态 schema 提取实际入镜对象，供逐 Clip 作者引用。来源、表达与同链修订见 [SKILL.md](../SKILL.md)。只规划资产，真实媒体由 Workflow 节点执行。

## 对象与已有素材

objectRegistry 的 objectId 在本次注册表内唯一且稳定；同一身份跨 Clip 共用对象，不按措辞或显示名重建，不把不同对象机械合并。区分故事对象 objectId、物理身份 physicalIdentityKey 与真实媒体 assetId。新媒体身份、物化任务和幂等键由执行器分配，作者不拼接。

从完整故事及实际入镜需求登记人物、场景、道具与其它主体。回忆、插入画面及可见的系统形象按实际空间和身份登记，不能错用现场对象代演；回忆不自动意味着新地点，同一空间是否复用依据来源与视觉状态。只有声音或仅被提及的对象不进入视觉注册表，可见形象则按真实设计登记，不预设系统外形。

selectedAssetIds/selectedAssetSnapshot 表示本轮显式选择，保留精确引用与用途；没有手选不代表项目无资产。图片原有 referenceType、canonicalName 和角色卡格式记录历史用途，不替代本轮用户对图片中对象的明确绑定。用户已指定图中人物或物件作为故事对象时，由作者结合该指令和真实图片事实确定身份与用途，直接复用可用原图，不为统一卡片版式另画替代身份。查询结果、名称、旧 prompt 不等于视觉观察，复用相关成功理解，必要时在当前授权内读图；未知外貌或地点不能凭空补成事实。

## 跨章复用（大纲）

大纲作者拿到 projectAssetCatalog：项目里已有、可直接复用的图片（assetId、canonicalName、referenceType、look 旧图的外观要点、已知 physicalIdentityKey），以及 selectedAssetSnapshot 中本轮显式选择的精确图片身份。复用前结合本轮用户绑定、本章原文与章节序列核对真实图片事实。色卡、每个场景、每个对象都必须填 reuseAssetId：

- 本章出现的对象与目录或显式选择的图片是同一身份，且原图适用，就填它的精确 assetId 原样复用。已建立的故事身份名称保持稳定；用户明确给图片中对象指定故事身份时采用该名称，不把图片文件名或历史用途名当作必须照抄的角色名。
- 目录里也有前面章节只规划、尚未出图的节点（只交付节点的一键成片），它们与已出图的图片一样是该身份的资产：同一身份直接填它的 assetId 复用，不重复规划；只有状态或外观变化才按下面几条新建或写 states。
- 人物受伤、赤膊、湿透仍复用目录身份卡，把变化写进 states，宿主从身份卡编辑出状态图。
- 场景同理：同一个空间到了黄昏、夜里、下雨，或灯灭了、门窗被砸，复用这个场景的底图，把时段与光照写进场景 states（look 写主光从哪来、什么色温、哪些灯亮着），宿主从同一张底图编辑出来，墙、门窗和家具位置不变。重新生成会得到另一间屋子，前后两场看起来不是同一个地方。
- 外观在本章有可见变化（换装、不同年龄段、空间被改建成另一副格局）或目录里没有这个身份，才填 null 新建；新建时 name 写出与旧图的区别。例：look 写着“一身赤红劲装”，本章原文写她“身着一袭青色官袍”，就新建“沈清秋·青色官袍”。
- 同一章里前后两种造型（前半场仍是赤红劲装，后半场换了官袍），两项都登记：旧造型复用，新造型新建，逐 Clip 作者按场次选用。
- 本章延续上一章的整体色调就复用目录里的色卡；色调明显变了（白天转夜战、换季）才新建。
- state 与上面不同：没有 null。projectStateCatalog 以 assetId、canonicalName、referenceType、stateName、physicalIdentityKey、thisChapter 描述已有状态图；按同一物理身份、本段故事时点和外观核对，适用就在该 state 写 reuseAssetId 精确 assetId 原图复用，不因状态名措辞不同另画。目录没有所需外观就新建：这个 state 只写 name、look、clipIds，整个不写 reuseAssetId 字段（写 null 或 "null" 都会被拒）。本章标记与保存时间不证明它是当前剧情状态。
- 背景底图没有复用槽位，按本章镜头需要照常列出。
- 若上下文有 inFlightProjectAssets：这是项目里其他章节此刻正在规划、还没进目录的人物、场景、道具（canonicalName、kind、brief）。本章出现的是其中同一个人、同一个地方、同一件东西，就沿用它的 canonicalName 作为 name，reuseAssetId 仍填 null；不要另起别名。宿主会把同名条目合并成一份，名字对上才合得上。不确定是不是同一个就按本章原文判断，原文里不是同一个，就用能区分开的名字。

逐项作者收到的复用种子只能写 reuse，assetIds 已由宿主钉死，只需如实写 identityInvariant 与 referenceRole。复用了状态图的 state 不需要再写编辑提示词。

人物对象写 voice：这个人说话的声音，性别、年龄段、音质与说话习惯，十到二十字，如沈清秋“二十余岁女声，清亮偏冷，吐字干脆”。视频模型听不懂名字，只靠参考图说明里写的声音配音——只写名字时女百户被配成了男声。按原文身份写，同一个人全片一个声音；复用的人物若已有 voice，宿主会钉死，照写即可。非人物对象没有 voice。

此处人物音色只属于这个人物，不覆盖独立旁白或其它纯声音来源。章稿已声明的独立声音身份与 delivery 音色继续由发声事件传递，不为旁白造一张可见人物卡，也不把它并入主角 voice。新角色音色设计同时参考章稿的声音分工，使独立叙述者与角色可听辨；已有确认音色保持原样，发现冲突由作者依授权修订声音设计。配音卡节点存在不等于视频已消费参考音频，实际输入以提交清单为准。

## 会动手的人物：打法写进身份

逐 Clip 作者只看得到资产名册里每个对象的名字和 identityInvariant，人物用什么兵器、怎么打、能力长什么样，要是不写在这里，每段就各编一套：上一段刀光是青的，下一段成了红的；两个对手都写成“快剑”，打成一团分不清谁是谁。

- 本章有打斗、追逐或能力对决的人物，大纲在他的 brief 里加一句打法：兵器、打法、有没有能力（原文怎么写就怎么定）。同一场的对手打法要分开，力量对速度、长兵对短兵、远程对近战，原文已定的照原文。
- 逐项作者在这个人的 identityInvariant 末尾写一句战斗身份，六十字以内：兵器（哪只手、什么形状、多长、什么颜色、平时收在哪）、打法（一两个词，如“力量型，抡锤硬砸”“速度型，贴身短打”）、能力外观（从哪个部位发出、什么形状、什么颜色，按本文“状态与特效写成画得出来的样子”一节写具体）。不写境界、功法名、招式名。例：“战斗：右手长柄战锤，锤头比人头大一圈、黑铁色，平时扛在右肩；力量型，抡砸横扫；不用能力。”“战斗：双手反握两把小臂长的短刃，刀身暗青；速度型，贴身划刺；出招时刀身泛淡青光，刀上花纹仍看得清。”
- 平时随身的兵器就是这个人的标志物（见 face-design.md 的“标志”），身份板上收在鞘里、背在背上或挂在腰间，不拿在手里摆招式。兵器有刻纹、缺口等要在特写里看清，并且多段用到，另登记一个 prop。
- 有固定形状、在多段出现的能力（召唤出来的兽、飞剑阵、护体光罩、法相），登记一个 kind=vfx 对象：brief 写谁发出、什么样，图里只画这个效果本身的定格一瞬，不画人物、不画场景。贴着人走的效果（火焰缠臂、刀身发光、眼睛发光）写进人物的战斗身份就够了，不另建 vfx。
- 不打斗的人物不写这一句。

## 冻结资产匹配

本轮提供 frozenAssetMatch 时，用 tapcanvas_workflow_execution_inspect 的 executionId、view=asset_match 与 match 查询冻结范围。match 含 referenceType，并含 assetId/physicalIdentityKey/canonicalName/assetReuseKey 至少一项，assetPurpose/stateKey 仅在已知且需要时传入；查询值来自当前来源或真实回执，不新造键。该确定性只读查询不按 prompt 猜身份或向量排序。

matched 是唯一精确媒体身份；candidates 需按本次用途选择，不能同名即同身份或默取首张。采用已有图时原样保留精确 ID 与 physicalIdentityKey。需要详情再用 view=assets + assetIds 读相关项，不展开无关全库。no_match 只说明这些条件未命中，依据具体证据核对条件，不能声称项目无素材或原样循环。

有合用已有图就 reuse；需要新版本或没有适用旧图就 generate，并把适用参考作为输入。缺工具如实保留能力限制，不伪称搜索完成、不把查询缺失变成用户生成门禁。规划阶段完成来源选择，执行器只执行精确引用。

## imageSource 与计划

每个实际入镜主体按本轮合同有复用或生成计划；两种 imageSource 互斥：

- reuse：{mode:"reuse",assetIds:[精确已有图片ID]}，这些图就是最终输出。
- generate：{mode:"generate",referenceAssetBindings:[{assetId,role}],plan:{本类型生图字段}}，已有图仅作明确用途输入，不能把需要改布局或人物的新图写成 reuse。

生成输入 role 仅 identity/content/layout/style，不需要参考写 []。plan 不重复 objectId，根级无 assetPlans，registry 不提交 referenceAssetIds/referenceImageNodeIds 或 mode=none/referenceRole=none。输入参考不自动进入视频输出引用；执行器在成功物化后绑定真实输出。

kind 为 character/scene/prop/vfx/palette/composition；referenceRole 为 identity/wardrobe/prop/environment/palette/composition/vfx。对象用途枚举与供应商输入 role 属于不同合同，不混填。复用人物图及 identity 参考的已知 physicalIdentityKey 与对象一致；不同身份不能伪标 identity，缺事实只记未核验，不按名字合并。根级共享 schema 定义按精确引用读取。

新建人物的长相在大纲 castDesign 里按脸、发型、体型、体态、主色、标志六格整章一起定，并与项目目录里已有的人物逐格比开，逐项作者照写进身份板，方法与范例见 [face-design.md](face-design.md)；不写“五官俊秀、鼻梁挺直、高挑挺拔”这类对谁都成立的词。颜值按戏份定：主角、感情线人物和主要对手是全章最好看的一档，骨相从好看的一侧取并在脸格末尾写一句颜值定位，路人与市井人物才按生活写普通与粗糙（见 face-design.md 的“颜值按戏份”）。人物身份、家世与衣着按原文明说的写，“侍立”“垂手”“伺候”这类动作不等于仆从身份：原文写“大户人家的孩子，锦衣玉食”的少女是家族小姐，不是“贴身侍女，衣料质朴”（10-30 剑主 ch1 秦灵芝案）。原文没交代的就按她在场的位置与人物关系推断，并在 brief 里写明依据。人物、场景和道具分别按需读 tapcanvas-character-card、tapcanvas-scene-card、tapcanvas-prop-card。同一画面里有三人或以上同框的镜头，就为这一帧登记一张 composition（referenceRole=composition，physicalIdentityKey=null），有名字的人物也算：participants 列出同框的本章角色名（一张最多 5 人，更多按小组或前后景拆成几张），匿名护卫、仆从、围观者写进 brief。宿主在这些角色的身份卡出图之后再画群像，并把身份卡作为身份参考，所以群像里是同一张脸；群像图不替代身份卡，每个参与者仍单独登记 character。只有匿名人群的群像 participants 写 []。例如拱门外送别，秦道之、秦安、秦平、秦灵芝与四名护卫同框：四人各登记 character，再登记「秦府门前送别群像」，participants 为这四人，brief 写清谁跪谁立、护卫站在后排。群演设计按 character-card 的 references/cast-tiering-and-crowd-design.md，不在此复制方法。

图片执行器追加项目风格全文与参考图；plan.prompt/sceneCard.spacePrompt 写本资产身份、构图、版式及具体材质，不整段重抄风格。提示词用自然语言表达视图，不念 schema 枚举。会随剧情变化的读数、损伤或表情明确首次使用状态，旧图后期状态只作外形参考时说明用途；逐 Clip 承担后续变化。

identityInvariant 只写用于识别同一对象的稳定事实；首次出场已有的伤损、污迹、开合、填补或修复结果同样是可变状态，不因它出现在基态图中就成为全片不变量。基态按首次使用时的真实状态准备，图片计划说明该时点，后续状态按有序事件承接；状态的 clipIds 表示可能用到它的片段，look 写变化及其依据，不把“本段会发生”写成“开场已发生”。已有图包含其它时点的状态时，说明可取的身份、空间或材质事实及不适用的状态。逐 Clip 作者依据当前状态选择图并声明 referenceFacts/referenceUsage，不把共享图的初态机械传遍全片；状态种类和字段服从动态 schema。

当前状态计划覆盖 character、scene 与 prop，分别由对应资产 Skill 处理。大纲按 schema 的 states 描述所需外观与适用 Clip；逐实体作者按已分配 stateId 编译编辑差量，不重复发明身份或时序。状态图是可复用参考，不要求每段、每镜或每次变化都生成一张；共享基图与实际状态图由执行器绑定真实资产后消费。值得建状态的是看一眼就换了样子的变化：人物整体换装、变身、受了看得见的伤、体型变了；场景换时段（白天、黄昏、夜里）或被毁成另一副样子。瞬间表情、某一镜的姿势、换个机位、一阵雨这类，交给逐 Clip 提示词，不建状态图。

## 场景与道具怎么写

场景：
- 先定朝代。整部作品先定一个具体朝代或年代，原文是架空的也写它像哪一朝（“明代风格的县城”“民国上海的弄堂”），不写“古代”“架空”。模型拿到“古代”只会画它最熟悉的影楼风，各场景之间对不上。
- 旧不旧要定下来：这个地方是天天有人用、有人打理（漆面完整、地面扫过），还是用旧了没人管（漆皮剥落、墙角积灰），二选一写清楚，不写成“古朴”。
- 写三到五个画得出、认得出的锚点：门在哪面墙、主位后面挂着什么、窗外看得见什么。同一个地方换一张图、换一个角度，靠这几样认出来是同一处。
- 光照只写本章实际用到的那几个时段，从用到它的 Clip 反推；不列早中晚全套。

道具：
- 不是每样东西都要建卡。下面三条都满足才单独登记：有特写、在不止一个 Clip 里出现、它丢了坏了剧情就接不上。只是摆在桌上的茶壶、路过的轿子，写进场景或镜头里就够了。
- 写清有多大，按手持、桌面、家具三档写，再拿常见物件比一比（“一掌长的铜钥匙”“半人高的樟木箱”）。不写尺度，模型常把钥匙画得像剑一样长。
- 道具图画在干净的浅色背景上，不出现人，也不出现手。拿着道具的手是道具图最常见的污染：视频里谁拿它，就会长出那只手。

## 状态与特效写成画得出来的样子

states.look、状态编辑 prompt 和 vfx/道具资产里的视觉效果（发光、火焰、印记、气场、法相、异变的眼睛、神兵外观）都写成图片模型照着能画的东西，不写名号、境界和气质词。每个效果交代五件事：长在哪里（贴着哪个部位、从哪里发出）、什么形状、什么颜色、多大（拿身体部位或常见物件比，如“一掌高”“两步宽”）、多亮（跟周围比亮多少、挡不挡住底下的东西）。

- 名号与气质词不是画面：“剑仙之态”“神龙木鞘”“剑辉”“神情笃定”换成看得见的样子（鞘身什么颜色、刻了什么纹；嘴唇闭着、眉头不皱、平视前方）。
- “若隐若现”“边缘虚化”“隐约”等于让模型别画；要画就写清楚，不想让它抢戏就写小、写淡，并说明底下的东西仍看得清。
- 发光写上限：眼睛发光要写“瞳孔黑点仍清楚、亮度只比眼白略亮”，否则会画成两颗白灯泡、整张脸跟着失真。
- 尺寸要和取景对得上：全身像里眼睛只有指甲盖大，瞳孔里的图案画不出来；这类细节放在特写状态图里，或者干脆不写。
- 状态图是一张静止画面：“缓慢旋转”“流动”“明灭”这类过程交给逐 Clip 视频提示词，图里写成定格的一瞬（火苗向上卷、披风向两侧展开）。
- 效果颜色和项目画风的主色冲突时（冰蓝画风里的赤红火焰），写清火焰的颜色和它照到哪里，不靠画风去调和。

例（11-02 姜望剑仙状态，原写法出图成白眼、脚下印记没画、剑鞘画成木棍）：

- 改前：剑仙之态：双眸中剑光照耀，清亮的剑辉自瞳孔里透出，光中浮着两尾若隐若现的黑白阴阳鱼，缓慢旋转、边缘虚化；脚下石面上浮现青云印记，纹路环着他的立足处；身外有赤红色火焰流动……腰间神龙木鞘长剑已握在左手。神情平静、笃定。

## 背景与色彩

依据实际场景转换，把每段空间和光照状态映射到共享场景及 backgroundPlans。实际不同空间不能只因同属室内复用；同一空间可在适合状态下共享。每个所需无人俯视底图状态有对应计划，同状态跨 Clip 复用，不让下游选择错误近似底图替代缺项。

backgroundPlans.objectId 是背景计划身份，与注册表场景 objectId 分属不同域，不要求同名。不同底图状态使用不同计划 objectId 与 plan.assetId，保持空间结构；runtime 按冻结 assetId 投影稳定唯一 ID，下游用精确投影值，不用列表序号。逐 Clip 站位图不能替代人物身份参考。

本 artifact 由大纲 palette 槽位产生一个 kind=palette/referenceRole=palette 色彩锚，承载本章色彩和光影状态；不承载人物、文字或可辨认空间，不在 prompt/negativePrompt 中另行规定或否定宿主媒介。色卡画成抽象的色块与光影渐变色板（几块主色、明暗过渡、冷暖对比），不画地面、街道、雨幕、天空这类有纵深的风景：视频模型会把像场景的图当成一个镜头演出来（49bf5a09 ch3 每段开头都演成了这张色卡）。
