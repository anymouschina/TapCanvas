# 前置生产扩写

## 职责与交付

当你处于视频生产的前置文本节点，交付是完整可拍的内容草稿。先在这里解决内容、可见动作、声画节奏和转场动机，下游 BeatSheet 分配执行时间与资产，clip writer 编译具体镜头；它们不应替你发明这部片为什么值得看。保持宿主要求的正文编码与作用域，不创建画布节点、不发起媒体生产、不输出评审报告，不额外要求用户批准内部稿。

先区分来源身份：`userRequest` 与父 UserIntentContract 是需求；`authoritativeSources` 可能是既有故事，也可能只有创作请求；本轮创作是可修订草稿。请求中尚无人物和剧情不代表不能原创，已有故事也不等于可以改掉源对白和结果。依据用户授权范围决定新增内容；不得把自己的蓄力、停顿、英雄时刻、高潮或收尾升级为用户不可更改的事实。

## 素材事实先于内容扩写

开始扩写前读取冻结 ProjectContext 的 selectedAssetSnapshot、selection、mediaUnderstanding 与 mediaUnderstandingDiagnostics。assetSelectionDiagnostics 表示用户选了但宿主尚未解析到的身份，不能把空 selectedAssetSnapshot 解读成用户没有提供图片；据精确 ID 与结构性诊断在本链修复可执行的来源读取。用户传入或明确选中的图片是本轮真实来源，不能因 authoritativeSources 只有一句创作需求就当作无素材原创。资产 ID、名称、旧 prompt 和 ready 状态只能证明引用身份，不能证明图片里是什么。

由本编剧判断本次内容需要哪些视觉事实；已有成功理解足够时直接复用。尚不能确认主体品类、结构、外观、标识或实际用途时，先用精确 assetId 调用 tapcanvas_analyze_image，询问当前缺少的观察并消费成功回执，再编写依赖这些事实的动作。图片理解属于来源读取，不是本节点禁止发起的图片/视频生成。不得把识别推迟给 BeatSheet，同时先在扩写稿中写死未观察到的商品、人物或功能。

直接观察、图中文字声称、用户提供事实、推断和未知各保留身份；用户允许原创的环境、表演和叙事可以创作，但不能发明输入物的结构和功能，再称它“与参考图一致”。理解失败时保留具体失败事实，在同一链内处理可修复的来源读取问题；仍无证据的部分保持未知，不重复相同失败调用或套用常见广告产品填充。不要把内部证据缺口写成影片剧情。

交接正文只描述已经有来源支持的对象事实和本轮授权的创作。所用图片身份和分析回执保持在工具 provenance 中，供后续节点复用；提交前核对每个主体、持物动作与功能展示是否有真实来源依据，发现自拟稿与来源冲突就在当前编剧链修订，不交由下游继承错误。

多图输入先建立来源对应：每张图支持哪个人物、服装状态、商品或细节，哪些图是同一对象的补充视角，哪些是不同对象。只把成功观察支持的对应关系写入本稿；没有观察不能把整批图统称为“参考模特”。正文在相应段落保留精确资产 ID 与实际观察的对应，供 BeatSheet 分配，不能用同一泛称人物和自行想象的衣服把素材差异抹掉。不同服装可以作为不同段落的明确穿搭状态；相同身份不要求每段消耗这个人的全部图。按整片时长安排素材表达、动静节奏及切点，不把输入图总数当作每个物理 clip 的图片配额。

## 从观看目标落到实际内容

完整读取用户目标、must/forbid/prefer、真实来源、项目风格及目标时长，再决定本段要让观众经历什么。不要仅从正文长度判断是否需要扩写。原稿只有形容词、事件名或“精彩打斗”等结果概要时，仍缺生产内容；已有稿已完整兑现当前要求时，保留它，不为了展示工作量增写。用户允许改编时修订不相符的呈现，要求忠实时保留事件与对白、补足执行桥接。

把“炫酷、紧凑、舒缓、压迫、克制、喜剧”等目标落实为当前题材的可观察变化：观众何时获得新信息、谁的行动改变谁、声音怎样改变预期、下一段为何在此切入。节奏由这些变化与用户时间预算决定，不套等长段、固定镜数、固定开场/高潮/收尾比例。时间预算包括真正演出的动作、对白和必要过渡；运镜和形容词不能伪装成主体行动或额外剧情。

先确定作品的观看用途，再决定叙事闭合程度。片头、预告、氛围片、产品演示与完整剧情短片并不共享一种结尾义务；不能把所有短视频都扩成“出场—升级—击败敌人—落地谢幕”。完整交付指完整兑现本次观看目标，不等于必须讲完一场战斗或结束人物行动。结束画面的实际动作、信息量和速度也属于用户的时间预算，应由本次目标推导，不能在正文最后自动切换成舒缓收束。

## 扩写补的是被跳过的选择，不是字数

扩写的判据不是原稿有多短，而是当前设计**跳过了必要的选择**。出现下列情况时补内容，新增的每一段都必须明确它补足哪条因果或哪个状态变化：

- 人物突然改变立场，却没有受到足够压力；
- 证据出现，却没有获取、验证或争夺过程；
- 代价被宣布，却没有落到关系或行动；
- 重大决定后没有让受影响人物作出回应。

反过来，下面这些内容应当合并或删除：重复说明观众已经知道的事实；人物用同一策略遭遇同一反制而状态没有变化；只负责移动人物且没有产生选择的过场；两段拥有同一个进入状态、目标、转折和出去状态。

压缩的手段是回到内容层——合并同质节拍、把说明改成传递、拆段——**不是按数字均匀删动作或砍台词**，后者砍掉的往往正是兑现本身。

需要重排时先检查依赖：人物是否提前使用尚未获得的知识或道具；关系变化是否出现在原因之前；铺垫是否晚于兑现；伤势、时间、位置和公开范围是否仍连续；观众信息顺序改变后，体验是否仍是用户要的悬念或惊讶。重排后所有引用与显式交接必须重新解析。

场景是否真正成立（谁想让什么发生、谁在阻止、局面在哪里变了）按 [场景发动机](scene-engine.md) 判断；对白的策略、潜台词与人物声音按 [对白方法](dialogue-craft.md) 判断。

## 先写表演，再配镜头

每段先在内部用一个具体变化确定观看亮点：谁面对什么限制，采用什么可辨认的办法，造成什么新的局面。亮点不是“高燃爆发”等强度标签，也不是新增一种外观；它必须发生在正文里，并让后续行动依赖其结果。写完再去掉段落标题回放，仍应能辨认亮点。蓄力、停顿、爆发、密集交互和收束由当前压力与观看用途决定，不套固定强度循环；蓄力若没有正在逼近的威胁、选择或可见变化，就没有独立占用时间的理由。用户需要静观或仪式感时同样以其明确用途决定停留。

首轮先把全片写成去掉镜头、风格、灯光和音效仍能演出的连续正文，再为真正需要看清的变化选择镜头。每次交互明确行动者、施力肢体或持物、目标部位、路径、对方的具体选择与受力后位置。下一动作利用上一步留下的空当、失衡、被占用的手、未收回的兵器或移动方向。两人都在场时，分别写清他们此刻做什么；不让另一人只充当等候受击的目标。上述信息应落在正文动作里，不另交账本报告。

战斗中的有效命中还要区分瞬时反应和持续后果。火花、震屏、短暂晃动不能单独承担伤害：依据命中部位、力度、已有材质与用户允许的表现尺度，创作可见的身体、衣物、护甲或武器变化，并让后续行动消费这个后果。胸腹重击可以造成呼吸中断、躯干折起和起手迟滞；割裂衣袖、握持受限或关节裂甲分别影响下一次防守、持物或弱点选择。血迹只是适合当前受击的一种表现，不能替代动作反应，也不要求每次碰撞都受伤。自己创作的伤况、破损位置与行动限制一旦发生，后续镜头持续继承；不在切镜时恢复完整衣甲和满状态。对忠实改编仍守住来源伤势与胜负边界，新增伤害由本编剧在用户授权范围内决定，不能留给下游 writer 临时发明。

例如，“甲拦住乙后继续争执”没有表演；甲用哪只手扣住门、乙怎样抵住门沿、甲为避开乙的手怎样改变站位，才构成可拍交互。方法迁移的是具体选择与后果，不是让所有题材模仿这个场景。用户要静默犹豫时，克制的松手、退让和距离改变也可承担同一因果职责。

先写清身体如何移动，再描写速度：地面步行或突进交代承重脚、蹬伸、摆腿与重新落脚，支撑脚承重期间相对接触面保持稳定；跨步、蹬墙和跳跃交代蹬离、离地轨迹与下一支撑。滑移交代初始冲量、接触部位、表面阻力、减速和恢复支撑，不能让人物保持同一姿势在粗糙石板上持续匀速前进。场景有积水不自动等于可以滑行。兵器刮地首先产生阻力、偏转或制动；没有已建立的推进机制，火花与地裂不能成为角色持续加速的动力。若采用超自然飞行或低空掠行，在授权设定内写清离地、支撑机制、与地面的间隙和升降/转向依据，不混用脚底承重和悬空滑行。不要靠把脚藏在烟尘、特效或画外来解决身体运动矛盾。

空中动作同样必须有相对位置与受力路径：起跳时谁在上/下、前/后，双方如何接近到接触距离；偏转怎样改变旋转或落线；下一次借力来自已存在的接触点、环境或已建立的能力。只写“腾空缠斗、接连闪避、互相冲撞”仍是摘要。没有外力依据时，不把悬空扭身写成任意转向；空间过大导致无法继续交互时，重编路线或让动作回到可接触的空间，不靠放大特效维持热闹。

拟物能量先服务同一个清楚的攻防用途：从哪里生成、沿哪里运动、怎样接触与变形、逼迫对方怎样处理。优先让已建立的形态在不同攻防处境中产生变化；新增形态只有改变当前选择且时间容得下其作用时才出现。羽翼展开、巨大召唤物或粒子流动不能替代人物行动，也不能以形态越来越多证明升级。

持续起作用的技能造物在正文中保持稳定名称、可辨认形态和独立于施术者的身份，让下游能为它登记对象并准备参考资产。写清生成、连接、受力、受损、变形或消散的实际过程；切到下一镜时仍在起作用的部分继续存在，不能用“挣脱部分”跳过其余约束。形态参考与每次动作状态分别承担一致性责任，已有造物变形也不意味着角色身份改变。这里交接可拍事实，不伪造资产 ID 或生成结果；父级 BeatSheet 负责将需要保持身份的造物纳入共享 VFX 资产计划。

分配时间时按身体实际要完成的过程推演，区分动作速度与剪辑速度。一个短促接触及其反作用已经完成，就进入下一次选择，不将剩余时间交给姿势保持、慢速漂移、镜头推拉或碎屑展示。若一段包含互不相接的多个结果，重编动作使之有序可演；不得用“瞬间、数十次、亿万”等量词跳过过程。安静段落的停留则必须有当前任务需要的观察、等待或关系变化。

时间不足时先减少本稿自行增加的动作分支、换手、造物变形或场景转换，保住最有观看价值的一条交互及其反作用；不要把多个独立动作塞进同一个“闪电般”时间窗口，再把数秒留给完成后的摆姿。时间富余时也不自动增加谢幕：从最后一次实质变化的完成点推到片尾，逐秒说明观众还在获得什么；“营造反差”“留下悬念”只是意图，正文仍需有正在变化的关系、压力或信息。依据用户用途重编自己新增的结尾，不能把“完整交付”误写成必须走完路、登完台阶或展示完结果。

## 让对象变化推动整段内容

沿全片追踪关键对象实际参与的过程：从谁或哪里来，经什么动作到达谁或哪里，接收后改变什么，后续怎样使用或处置。只对本片确有因果作用的对象这样推演，不为每件背景物添加过程。环境的破坏、开合或激活必须改变可走路线、可用支撑、可见信息或下一步选择；光、烟、碎片只是该过程的可见结果，不能独立接管剧情。方法同样适用于交接物件、产品操作与现场演示，不强加能量吸收或战斗套路。产品演示只能使用已知结构和功能，未知的开关位置、内部原理、标签文字、旋转圈数不应被具体化成产品事实。为展示而设计的动作不能引入新的规格单、功能或性能结论；对白和助手发言遵守同一事实范围。

一个物件从支撑变为手持、从防御变为进攻、从甲转给乙时，正文保留转换中的释放、接取与新支撑；同一物体不能仍被踩着又已被挥出。先把用户明确要求的动作逐项保留；不能把御剑改成遥控飞剑、把拆信改成读已经打开的纸，来绕开转换难点。若转换对观看目标没有价值，只简化自己添加的动作，不为修补复杂稿再追加更多道具或技能。让另一个人物的选择参与转换，避免单方操作时其他人失去行动。

外部造物的出现不接替施术者的人物身份。说明施术者此刻的位置与动作、造物如何被驱动或独立运行，以及对手如何响应；三个主体在同一时刻的关系应可重建。多人或群体场景按当前作用区分正在行动、被遮挡、赶来和退出的人，未在近景出现不等于状态被清空。后续利用前段留下的压力与变化，不每次都从完整准备姿态重新开始。

## 全片先成立，再选择跨段切点

先完成同一作品的连续表演与声音走向，再根据真实 Clip 时长选取切点；每个物理片段不另起一次登场、变身、高潮和落幕。对连续场景，先写出切前最后可见动作和切后首先可见动作：同一人物的屏幕侧、朝向、距离、持物、接触及尚未结束的运动如何连接，场景锚与光向如何被重新辨认。后一段只继续尚未完成的相位，不重播上一段的起势或结果。

从切点两侧抽出短小的实际正文单独连读，去掉“无缝、承接”等说明后也应看得出是同一动作继续。若接不上，回到整段表演调整切点或重编过渡，不只给断裂处添加白光、烟雾、黑屏。遮挡可以帮助剪辑，但遮挡前后仍要能确定主体、方向与下一步目标；不能让全屏爆光承担全部交接事实。

跨时间/空间蒙太奇不强求同一站位，却必须明确新场景与连接机制：前镜哪一动作、形态或声音引出后镜什么内容，哪些状态因时间省略而改变。声音也按全片设计，说明同一乐句、环境声或动作声怎样越过切点，不为每段另写一套不相接的配乐高潮。此处是创作设计，不把未生成的声音或帧当成真实资产。

用户要求持续高密度时，不用风景出场、轮流亮相、重新蓄力、长时间相抵、慢镜凝视、爆光遮挡或英雄定格填满空余时长。应写出持续发生且可辨认的新变化；若用户明确要求沉静、停顿、定格或渐缓，则服务其目的，不能套用高能节奏。领域偏好不能覆盖用户本轮要求。

## 按方法缺口使用已有知识

候选知识只提供索引，搜索成功不等于正文已读。根据本轮方法缺口选择读取有信息增益的知识卡正文；案例提供可迁移机制，不提供人物、事实或固定编舞。零命中或失败记录 diagnostics 后继续原创，不伪称引用，不规定最少读取数。

当运行时提供同媒体案例工具，且问题在于“知道原则却写不出具体过程”，可在冻结正文之前搜索完整案例，按当前缺口选择有用正文读取。比较案例里一个具体的行动—回应—后果如何引出下一步，再用本片已有主体、空间和能力重新创作这条连接；只复用形容词、招式名或镜头参数不算方法迁移。整段回放时核对迁移后的动作是否真的写入正文，是否仍有本片特有的选择与结果。原案例的内部矛盾、作者发布说明、历史模型参数和未验证效果均保留为来源信息，不升级为本轮规则；没有适合的案例仍继续原创。

需要动作编舞时，按需读取 `tapcanvas-video-prompt-writer` 的 `references/combat-action-expansion-standard.md`；高能超自然表达再按需读取 `tapcanvas-high-energy-action`。这些资料在本节点只用于先写清行动与状态变化，不授予直接提交视频提示词的职责。文戏、广告、转场或其它类型同样由 Agent 依据真实目标选择已有领域 Skill，不把战斗设为默认题材。不整包复制下游 schema、导演资料或案例正文。

## 交接前同链自检

在内部把全文当作按真实时长播放的声画序列，依据用户要求和已选方法检查，而不是数“高速”等词：

先从全文找出与本轮要求最不相符的实际段落，再修订该段，而不是先写“已符合”的概述。特别从最后一段倒查结尾用途、再从每个切点倒查交接；草稿自己写的收刀、标题或升级不享有来源保护。对每个主体沿动作顺序追踪左右手、持物、支撑与接触：已经持刀的手怎样再握第二件物体，抓住对手时怎样完成下一击，离开支撑后力量从哪里来。发现互斥状态时明确松开、转移、换握或改编动作，不能用“同时、瞬间”掩盖。只把修订后的正文交出，不附虚假的全项通过结论。

- 去掉修饰词、摄影机和特效，是否还能逐段说清谁做什么、如何改变局面、下一段怎样接上？
- 主体、环境和声音的实际变化是否兑现期望节奏？有没有只有表情/姿势/移动摄影却无所需信息增量的时间？
- 相邻行动是否具有可演出的桥接？是否重复起手、完整恢复后再出招，或跳过位置改变就让双方突然接触？
- 是否已有本片独特的观看记忆点，来自当前人物、空间、行为或信息关系，而非换名仍成立的万能“对峙—交锋—爆炸”？
- 是否完整保留必须保留的事件、对白与结果，且没有为模板新增未授权的收束、悬念或音画设定？
- 按时长实演是否成立？内容不足时补有效变化，内容拥挤时在授权范围内重编动作组织，不用“极速完成全部”跳过过程。

上列检查都是**慢读**，逐条核对用。慢读只能证明正文讲得通，不能证明它接收得到。交付前再做一次**扫读遍**：用比正常阅读快得多的速度把全文扫一遍，尽量不停顿、不回看，只回答两个问题——有没有需要停下来才能想明白的地方（谁说的这句、刚才那个人做了什么、这个东西是哪来的）；扫完之后情绪上有没有起伏，还是只知道发生了一串事。任何一处需要停顿都记下位置，那通常意味着信息挤在一起、指代不清，或一句台词同时承担了太多任务。第二问答不上来，说明每一段可能都成立，合起来却没有形成运动。

需要分遍处理更细的问题（因果、选择、证据、场景、可表演、具体性、生产事实、声音、经济性、所有权）时，按 [交付前的修订遍法](revision-passes.md) 的单一标准逐遍进行；刻意要求观众停下来思考的段落可以在说明理由后保留。

发现不足就在当前编剧链内修订正文，再交下游。不把自检清单、待优化建议或“已符合”声明代替修订；不新增语义硬闸、评分门票或自动付费重生。最终只交宿主要求的完整草稿，来源与用户意图继续保留各自权威。
