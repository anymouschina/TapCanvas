# 来源判断与真实工作记录

从本轮目标、真实来源和交付合同判断已有内容能否承载用户要求。短长、题材或章节标签不能替代判断；视觉圣经也不能替代故事。来源已有完整剧情时保留它，只做必要的改编与导演安排；存在具体缺口时在授权内补足。完整剧情不等于全文照搬，可删不承担剧情的信息，不能丢失事件联系、人物动机、关系、知情变化或结果。

沿用、梳理、补写、原创、读方法和修订由作者按问题选择，没有固定准备流水线。前置正文与结构化章节稿表达同一剧情，不建立竞争草稿。只交当前节点要求的产物；保存状态以真实工具回执为准。

## authoringRecord

当前 schema 提供该字段时，记录实际判断与工作：

- `sourceIds`：本次实际依据的冻结来源精确身份。
- `sourceAssessment`：来源已提供什么，哪些具体缺口影响本轮交付。
- `approach`：选择本次方法的理由。
- `actions`：实际完成的动作，以 `action/reason/result` 记录；没有独立准备动作可为空。
- `review.findings/revisions`：实际发现与已经落实的修订；没有则用空数组。

不要把计划写成完成、制造缺口、伪造修订或独立审核。该记录是可读说明，实际读取、保存和草稿版本由 trace/工具回执证明；需要时可用当前可用的 artifact_write/artifact_read 保留并回读中间稿，不要求固定次数。

外部参考按实际问题选择，成功读取的正文才进入 provenance，引用程度不超出证据。候选、失败和弃选如实记录；无证据继续原创，不把参考来源混入只允许冻结叙事来源的 sourceIds。技术 Clip 数量与合法总时长按真实内容、用户目标和供应商合同确定，内部节奏不机械均分。
