# 演员资产投入与群演视觉设计

## 来源与适用边界

吸收探路AI于 2026-09-29 发布的[《群众演员如何做到千人千面！使用Codex一边做剧情一边完成角色制作》](https://x.com/TanLuAI/status/2104809537685631014)，于 2026-09-30 通过浏览器读取全文，并查看群演全身群像与配角身份参考配图。下文是结合 TapCanvas 当前资产合同的设计方法，不是原文转录，也不证明某模型、图片数量或做法必然保证视频一致性。

可迁移的经验是按实际叙事用途分配身份细节：背景群体先让轮廓可区分；重要配角加强面部与身体身份；主角和有连续性要求的人物锁定身份与状态。原文的校园混混、年龄、性别、纹身、染发和金链属于该片案例，不作为其它故事的默认人群。原文的模型称呼不进入执行合同，仍读取本轮真实启用模型、规格与供应商上限。

本参考负责已给定人物或群体的视觉选角与资产表达，不增加演员、不改剧情、不替编剧决定谁出场。群像选角参考与关系图、站位图、镜头表演各有职责；不把多人群像伪装成单人身份锚。

## 从镜头用途决定投入

先读本轮完整故事范围、已规划的出镜用途与已有真实资产。判断观众需要记住的是某个人的脸、某个人的身体造型，还是一群人的组成和规模；再判断哪些信息会跨镜延续。主角、配角、群演称谓仅帮助讨论，不是固定等级、图片配额或生成闸门。用户指定精确复刻、逐人卡或群演参考时，尊重其明确范围。

| 当前需要观众辨认的信息 | 可选资产表达 | 继承边界 |
| --- | --- | --- |
| 只需背景人数和氛围，无个人或群体视觉连续性要求 | 在当前合同允许时直接由镜头表达 | 不为了“资产齐全”虚构个体身份；若冻结合同明确要求所有入镜主体有图，则仍以群体图满足 |
| 需保持群体构成、服装和轮廓，面部不承担剧情信息 | 全身群演选角参考，使用 `ensemble` | 保持群体视觉区别，不声称其中每人已有 canonical 身份 |
| 配角已可辨认，但当前只需要有限视角 | 复用真实证据帧或已有肖像；需要时补正面与近景群像 | 没有清晰身份依据就不宣称锁脸，未来新增近景用途时再补身份资产 |
| 人物承担持续近景、对白、与他人的具体互动或反复辨认 | 独立 `character-card/v3` 四宫格身份卡 | 可从一开始就建卡，不要求先生成群像；“配角”不降低身份精度 |
| 同一身份有背包、换装、伤势等需要稳定复用的可见差量 | 从精确基态或上一状态派生 `state_variant` | 只改变真实差量，不重建脸，不把场景背景变成人物状态 |

这些是作者的选择依据，不建立“出场次数达到 N 必须建卡”等规则。背景群演不需要逐人编造完整身世或做主要角色压力测试；有独立关系与决策责任的人物仍按主 Skill 建立人物因果核。

## 群体远景可读性

先固定来源规定的群体组成、时代、年龄范围、性别、职业和服装制度，再设计允许变化的部分。制服统一、剃发或固定配色也是事实，不能为了差异擅自打破。可从轮廓、肩胯比例、身高关系、体型、发型体积、衣服剪裁与穿戴方式、鞋履、物件和有依据的磨损寻找差异；染发或配饰只在来源或授权设计允许时使用。

把整组放在同一观看尺度比较：缩成目标远景大小后，是否仍能由身体和服装认出不同成员？如果只剩颜色区别，或多人像同一张脸换装，回到设计修订。不要机械给每个人分配独一颜色、纹身、疤痕或帽子，不按外貌推断道德、职业或犯罪身份。匿名成员可以有可见外观，却无需虚构 canonical 姓名、身体身份键或角色圣经。

群演全身参考应让身体、鞋履和服装轮廓完整可读，各人不互相遮挡成一团，尺度与光照便于比较。人数、排布和画幅按当前构图需求及模型能力选择；可以一张承载完整群体，也可为可读性或真实供应商边界拆图，不设固定人数上限或“一定一张”。多张延续同一成员设计，不重新随机造人。群像中的中性站姿只是选角展示，不冻结剧情站位或表演。

面部细节按需要分配。匿名远景群体不要求每张脸都有主角级精度，也不机械套四宫格或强制全脸模糊；已确认且持续可辨认的人物不得因置入群像而失去身份。后续单人近景若超出现有证据可辨范围，按真实需求补独立身份卡。

## 身份证据、状态与渐进补齐

真实已生成视频中的清楚人物帧可由 `tapcanvas-parse-video` 抽取、登记为 `identity_evidence` 并直接复用；不必为了“标准化”额外付费重画。多人帧不能靠顺序猜是哪一个人，需依据真实媒体理解确定当前对象与证据映射。只有需要 canonical 身份板时才交本 Skill 规范化；不可见的背面细节仍是保守推断，不能声称视频提供了证据。

编写剧情和视频提示词时，可以同步发现资产缺口、复用现有资产并编译必要的新图；沿现有 Workflow IR 或授权图片工具提交，不另建生产流程、不自动扩成全 cast 批量生图。上游身份尚未有真实图片结果时，不把计划 ID 当成可执行图像输入；无依赖设计可以并行，受理项沿原 taskId 对账。

主角和重要配角继续使用现有四宫格模板：唯一清晰正脸特写锁面部，侧脸与正面全身只局部模糊脸，背面不露脸；不得为套原文的三视图案例改变本项目已确认规范。人物处于同一身份但背包有无、服装或伤势变化时，按真实连续性需要派生精确状态版本；临时取放物件、情绪、动作和不同场景不自动产生新卡。纯换装保留已有脸锚，不把原文“再做近景”机械解释为重设计脸。

## 现有协议与下游交接

群体图片节点使用现有 `referenceType="ensemble"` 和精确 `ensembleTitle`。`characterRoleNames` 只列真正已有 canonical 名称、且画中实际出现的成员；匿名成员不编造名称。该字段不能证明群像中每个人都已拥有单人身份卡，也不能把群像直接绑定给所有单人身份。模型与图片规格来自真实动态合同，来源与引用使用真实 node/asset/version ID，不复制内部 URL。

群体参考不填写 `characterAssetRole="identity_anchor"`、`characterProfileVersion="character-card/v3"` 或 `identityBoardSpec`。需要人物精确脸锚时，另外引用该人的独立卡；群体图只贡献其已声明的群体外观或构成，禁止把其他成员脸、参考背景、排版、姿态和光照迁移给此人或剧情镜头。

当冻结的 Workflow artifact 使用 `kind="composition"`、`referenceRole="composition"`、`physicalIdentityKey=null` 时，保留这套用途合同；`ensemble` 是图片节点/素材分类，不替换 artifact 的机器枚举。不新增 `crowdTier` 等未经 schema 声明的字段。把设计判断落实到当前合同已有的 prompt、对象不变量、引用职责与计划字段中。

交付分别报告群体参考、单人身份卡、证据帧和状态版本的精确 ID、真实用途、受理或完成状态与尚未覆盖的视角。生成前在当前作者链内检查远景区别、身份映射、状态差量与用户范围；已有媒体保留，诊断不成为运行时评分、字数、证据或风格门禁。
