# 商用级导演母合同与收敛编译参考

## 商用级导演母合同（所有题材常驻）

商用品质不是追加“电影感、8K、大片感、院线级”等质量口号，而是把观众注意、摄影、光线、材质、声音和剪辑组织成同一个可执行决定。每个 clip 在内部先冻结一份**导演状态**，再写 `shots[]`；这份状态不新增根 schema，分别落入现有 `continuity/editRhythm` 和逐镜字段；父级 `exitState` 只作为最后一镜必须达到的冻结目标：

### 视频语言诊断回放（提交前的内部修订环）

> **边界说明**：这是 `tapcanvas-video-prompt-writer` 的单一内部复盘方法，不是新的 Skill、路由、模板或运行时质量门禁。它只把导演判断回写到现有 `continuity`、`shots`、`lighting`、`soundPerspective` 和 `editRhythm` 字段；不得创建第二条提示词链、复制一份平行 JSON、拦截已受理媒体或把审美判断升级为 `blocked/failed`。用户事实、父任务冻结合同和供应商硬约束优先；用户或父任务明确选择的反常风格可以覆盖下面的默认建议，但必须在具体镜头语言中落地。

把最终稿当成已经拍好的素材回放，而不是一张分镜表。默认按以下顺序回放，并在当前 writer 响应内直接修订；如果用户或父任务已经明确选择了不同的摄影、剪辑、声音或节奏策略，保留该选择并检查它是否被具体执行：

1. **戏剧动作线**：用一句可见动词链说清“谁在什么压力下，因什么触发，做了什么选择，改变了什么状态”。如果只剩“展示、氛围、震撼、电影感”，先重写动作线。
2. **注意力路径**：每个镜头只承担一个主信息变化；观众的视线要能从主体、动作焦点、反应结果移动到下一镜。没有新信息的换景别、推拉或特写要合并。
3. **空间与阻力**：回放主体的屏幕位置、朝向、距离、速度、支撑点和接触点。位移必须有起点、路径、受力、落点与环境反馈；不能用“冲过去、飞起、瞬间出现、激烈交锋”跳过物理里程碑。
4. **摄影机动机**：逐镜回答“摄影机为什么现在移动”。运镜只能由主体动作、视线、声音、遮挡、揭示或空间关系变化触发；删掉运镜后信息完全不变时，改成有明确空间读法的固定机位或删镜。
5. **剪辑接力**：每个切点都要消费上一镜留下的速度、受力、视线、遮挡、声音或未完成动作，并在下一镜继续它。禁止把一条动作链剪成互不相干的“起手—命中—摆姿势”三张卡片。
6. **光与材质反应**：相邻镜头沿用同一套可解释的主光方向、软硬、色温和反射关系；特效必须影响主体、接触面和环境，不能只给主体加发光、粒子或震屏。
7. **声音透视**：声音要交代距离、方向、材质和因果。近处接触声、远处环境声、遮挡后的闷响和反应后的余波要与画面同步；没有依据时不凭空加入人群、广播或音乐。
8. **退出状态**：最后一镜落到父级冻结的 `exitState`，同时保留下一段可消费的速度、压力、关系或声音残留。除非父合同明确收束，禁止统一英雄定格、站稳、收刀或声场归零。

默认诊断优先级为：**动作因果 → 空间连续 → 摄影动机 → 剪辑接力 → 声音透视 → 光材质 → 风格修饰**。它用于分配 writer 的注意力，不是通过条件，也不要求每个镜头都同时具备全部层次。技术参数只有在改变画面执行时才保留；机型、焦段、快门、分辨率和“8K/电影感”等词不能替代视频语言决定。

- **视觉主任务**：当前 clip 只有一个主要剧情变化；每个 shot 再用 `visualTask` 写一个唯一可读的信息变化。环境、动作、情绪、道具细节不能在同一 shot 平分最高权重。若换景别但信息没有推进，合并或改变调度，不用景别轮换冒充剪辑。
- **摄影动机**：`framing` 写观众需要看清的尺度，`lensIntent` 写透视/景深/空间压缩或亲密距离为何服务当前信息，`composition` 写焦点、前中后景、遮挡、负空间和权力关系，`cameraMove` 只写由人物动作、视线、声音或揭示触发的一条主轨迹。不要捏造与项目媒介无关的机型、镜头品牌或毫米数；只有父任务已冻结具体摄影规格时才逐字继承。
- **摄影决定不可留空**：每个保留 shot 都要在 `framing + composition + cameraMove` 中交付一套可执行决定；固定机位也是决定，必须写清固定的空间读法，不能用空列把景别、轴线和时间解释权交给视频模型。`lensIntent` 只在透视、景深或空间压缩确有叙事作用时填写。高动力 shot 的摄影必须让进入速度、接触点、双方反作用和下一窗口同时可读；用户禁止特写或时间强调时，不得用摄影字段把它们偷渡回来。
- **带动机的光**：先在 `continuity` 冻结当前场景可解释的主光源、方向、软硬、色温、明暗比例和允许变化，再在 `lighting` 写本镜如何消费它。默认均匀平光不作为商业叙事方案；换光型必须由换场、可见光源变化或情绪/信息段落变化触发，不能逐镜随机换色。
- 阴天、雾天和室内漫射光仍必须给出可重建的主方向、负补光侧、明暗层次与材质响应；“平光、较平、均匀照亮”不能作为默认描述。爆炸、屏幕、车灯等局部光只在真实作用距离和发生相位短暂改变附近表面，不能无因果接管整场基础光型。
- **材质与介质**：`materialResponse` 只写当前镜真正可见的表面、厚度、粗糙度、反射、透光、磨损、空气介质或接触后果。皮肤、织物、金属、石木、液体、烟尘与 VFX 必须有可区分响应，不能用全局辉光、统一高饱和和随机粒子覆盖材质。
- **声画透视**：`soundPerspective` 写观众此刻跟谁听、声源远近/遮挡/空间混响、何时收窄或恢复；`sound` 再写与可见事件同步的环境底声、动作前预示、接触瞬间和余响。全部人声只来自冻结的 `dialogueScript + narrativeAudioPlan.lines`，声音设计不得从动作说明或画面描述再造人声。
- **剪辑交棒**：`editRhythm` 说明每个切点由哪次动作、视线、声音、遮挡或信息变化触发。后一镜必须明确写出它消费了前一镜的哪一项位置、速度、受力、过冲、失衡、恢复空档、持物、光线或声场，并说明这一残余怎样触发截招、追击、换位或反制；“随后反击”“双方错身”“重新蓄力”不算过渡。非终镜 action-out 禁止重新站稳、重新起手或完整收势。

**商用节奏不等于碎切。** shot 边界与持续时间必须从当前信息变化、动作完成时间、对白可懂度、表演反应和剪辑触发点反推；没有新信息或状态变化的换景别必须合并。只有父任务 `pacingDecision` 或用户合同明确要求快切时，才进入下文“忠实快切覆盖”；普通文戏、关系戏与对白场应给动作、停顿和反应足够可读时间，不把一个供应商长 clip 机械填成连续 1–3 秒镜头，也不靠笔尖、眼神、呼吸、钟表等重复插镜虚增镜头数。高动力场景仍可高密度拆 shot，但每个切点都必须消费新的动作相位、受力结果或空间变化。

媒介自适应必须服从父任务真实画风，不得把“商用级”误解为一律真人写实：

- 真人/实拍向：只有项目事实确认写实媒介时，才写自然皮肤与材质微瑕、空气介质、受控高光、真实遮挡和极轻微摄影机呼吸；避免塑料皮、过度磨皮、CG 扫描式运镜。静帧参考若来自 gpt-image-2，不把胶片颗粒/高感光噪点反写进静帧资产合同；视频层是否采用颗粒仍服从已锁定风格。
- 动画/漫画/风格化：保持线条、笔触、赛璐璐/厚涂层次、受控形变、轮廓清晰度和材质区分；禁止强塞毛孔、真人肤质、胶片颗粒或实拍机型，把既有媒介污染成假真人。
- 产品/品牌主体：产品外形、比例、材质、功能与品牌事实优先；镜头运动和人物表演只能服务一次明确的卖点揭示，不能让装饰特效遮住产品真实性。

这是一份 writer 同链创作合同，不是 Hono/Web 的运行时质量闸门。提交前若某个适用字段没有实质信息，writer 在当前首稿内继续补足或删去无信息镜头；不能只在 `selfQaNote` 口头声称“商业级”，也不能因主观质量判断让已受理或已生成资产被拦截、回滚或丢弃。

缺少权限、真实资产 URL、供应商必需字段等硬输入时，在唯一 JSON 结果的 `selfQaNote` 中如实说明；不得猜默认值、伪造资产或扩展任务范围。创作质量、战斗密度和字符水位不是本地运行时闸门；writer 只在父任务给出的动态额度内完成可执行正文，额度不足以承载冻结合同与最小因果时在 selfQaNote 报告 input_contract_budget_conflict。

## Prompt Project Packet 的单 clip 编译合同

父任务可能提供由 `tapcanvas-video-workflow` 编译的临时 Prompt Project Packet。它不是新的 schema，也不是让 writer 重新规划全片；你只消费与当前 clip 有关的四层事实，并把创作决定落入现有 `continuity`、`shots` 和声音字段；`exitState`、`assetObjectContracts` 等冻结字段只作为输入，由服务端投影：

- **Project Lock**：只继承跨 clip 不应漂移的视觉、材质、身份、声音和信息揭示硬事实；本轮导演选择如果只影响当前 clip，不要把它写成全片永久规则。
- **Asset Registry**：逐项读取父任务给出的 canonical 资产名、nodeId/assetId 和 `referenceRole`。角色图只锁身份/外观，环境图只锁空间/材质，道具图只锁材质/功能，VFX 图只锁主形/运动，画风图只锁媒介/色彩。严格遵守 `forbiddenTransfer`；需要只取某一元素时，写明 isolate-and-extract，不继承其余背景、构图、人物或镜头。authoring JSON 内继续使用冻结的 canonical 名作为结构外键；不得预估或填写 `@图N`，最终供应商正文由 renderer 按真实 `content[]` 顺序投影为纯 `@图N` 参考令牌。
- **Scene Packet**：先写画面打开时的空间锚、人物/道具站位、朝向、距离、持有关系、物理状态和环境持久项，再写主体运动。`subject motion` 与 `camera motion` 必须分开，摄影机不能替代主体因果。
- **Clip Packet**：这一窗口只承担一个主要视觉变化。静止起步的首镜可按“起始状态 → 发力/路径 → 接触或选择 → 可见反馈”编译；连续高动力镜从上一拍未完成的速度、受力、姿态或恢复债务直接进入“截入/利用 → 路径改变 → 接触/落空 → 新窗口”，禁止每镜补齐独立起势和稳定端点。时间轴、hard cut、连续长调度由当前父任务和动态模型合同决定，不由本地关键词、固定 15 秒或引用数量决定。

父任务给出 `temporalContext/sceneState/characterStateVersions` 时，它们与 `characterStates` 一样属于 Beat-owned 冻结事实，writer 不得改写、删除或跨作用域继承。`temporalContext.stateScope` 不同意味着相邻 clip 也不是同一身体/服装/伤势/空间入口；进入回忆、预知、平行线或返回现实必须按 `relationToPrevious/transitionCue/returnAnchor` 建立画面，禁止把上一物理 clip 的姿态和光线硬接过去。`returnAnchor` 不是“回到原处”之类标签，而是一份可重建的现实状态元组：每名角色的站/坐/躺姿、场景锚点与相对位置、朝向、接触关系、持物、身体状态和仍在进行的动作必须逐项等于进入记忆前最后一个现实 shot；若原文没有在记忆中改变现实身体，返回镜不得擅自坐下、起身、移位、松手或重新接触。`sceneState` 的内外景、时段、光线、空间锚和 `stateIn/stateOut` 必须落进 continuity 与真实 shots；`characterStateVersions` 的孕态、伤势、年龄、妆造、污损、持有物等可见事实必须在每个相关 shot 保持，不能因为角色身份参考图没有表现该状态就回退。最终 renderer 会把这些冻结 JSON 置于逐镜表之前；writer 仍须把它们拍得可见，不能只依赖标题。

父任务给出 `visualStateRefs`、`continuityLedger` 与 `visualStateAnchorRequirements` 时，它们同样是 Beat-owned 事实。`visualStateRefs` 是当前 clip 唯一允许使用的持久状态版本集合；同一 clip 穿插回忆、预知与现实时，按各 stateVersion 的 stateScope 分段，不把某一版本覆盖整个 clip。writer 的第一 shot 必须从 `continuityLedger.entry` 的全部稳定 key/value 开始，最后一 shot 必须落到 `exit`；禁止把已完成动作退回起点、换手、换持物、改变接触目标或改换空间。`visualStateAnchorRequirements` 规定当前 clip 必须服从的持久状态版本：writer 只能使用其中的 canonical `stateVersionId/stateKey/visualFacts`，不能因为状态锚尚未生成就回退基准体态。`prompt_only` 的未绑定状态锚只进入自检与 Prompt Package 缺口记录，writer 不调用图片工具。

姿态、年龄、孕期、相对时间和数量词也使用事实原词账。父事实写“站立”时不得出现“坐立”“端坐”或其它可能触发坐姿的混合词；“孩子才三个月”“孕三月”表示当前孕期，不得改写成“三个月后”“三个月大的婴儿”或其它时间位移。原文用“如冰水”“心寒”“眼前一黑”等比喻表达心理感受时，除非父 Beat 明确冻结为 VFX/现实环境变化，否则只通过人物可见反应、构图与既有光线承载，禁止把比喻物理化为室温骤降、结霜、冷意颗粒、无来源变色或其它世界状态变化。

持续状态采用“角色入画即重复锁定”的正向合同。当前作用域中仍有效的孕态、伤势、年龄、妆造、污损和持有物，必须在每个该角色真实入画的 shot 中保持；景别没有拍到对应部位时也不能写出相反体态，景别重新露出时必须仍可见。婚前/婚后、现实/回忆属于不同 `stateScope` 时分别服从各自版本，禁止把婚前非孕态带回现实，也禁止把现实孕态污染更早回忆。父 beat 遗漏了原文明确且跨镜持续的身体状态时，writer 不能猜成默认体态；在 shots 中沿 `sourceSpanText` 的明确事实保持可见，并在 `selfQaNote` 标出父级应补齐的状态版本。

一个 clip 内存在多个回忆阶段、事件前后或蒙太奇子时段时，先在内部建立逐 shot 的 `timelineId/stateScope/subphase` 状态账，再写画面。每个 shot 只能读取自己子时段已经生效的身体状态；原文明示或因果上已经成立的持续事实不能被“未知”“不跨时段推断”“本镜不表现”抹掉。例如角色在该子时段已经怀孕、受伤或持有某物，即使没有近景展示，也不得写成平坦、完好或空手；只有原文明示更早时间或状态尚未发生，才允许采用对应的非孕、未伤或未持有版本。一个 beat 无法用单一 `characterStateVersions` 无歧义表达多个子时段时，在 `selfQaNote` 要求父级拆 beat 或补足分阶段状态，禁止自行选一个方便版本覆盖整段。

人物接触采用具名接触账：记录 `actor -> target -> bodyPart -> side -> contactMode/intensity`。跨 shot 或跨 clip 延续抓腕、扶臂、牵手、按肩、持物等关系时，参与者、目标部位、左右侧和力度必须逐项一致；“触碰、扶住、握住、扣住、抓紧、攥住”不是可互换近义词。父合同已给出 `抓住(grip)`、`轻触(touch)` 等 canonical 接触词时，`continuity/visualTask/action` 与最后一镜必须复用同一个中文动作词，不能只保留英文 mode 后改写中文近义词。任何变化都必须有真实可见的松开、换手、加力或转移过程。continuity、起幅和最后一镜禁止使用“另一只手腕”“对方的手”等会混淆施力者和目标的省略写法。

接触账还必须计算每个时刻的**肢体占用状态**。某只手、手腕、手臂正在被持续接触、持物、支撑或限制时，不能同时被写成“从身侧抬起”“伸向另一目标”或承担第二条互斥运动轨迹；若动作必须由该侧执行，先在唯一可见 shot 中完成松开、放下或解除限制，再执行新动作。父 Beat 同时冻结“该侧持续被接触”和“该侧开始独立动作”时属于父事实冲突：不得挑一条静默覆盖，也不得在最后一镜制造换手；首稿应保留双方最后共同合法状态，并在 `selfQaNote` 请求父级明确动作侧。相邻 clip 已明确未占用侧承担动作时，当前 clip 的准备动作与最后一镜必须使用同一侧，禁止在接缝处由右手无过程跳成左手或反向跳变。

接触账与持物账必须按肢体分别维护：`character -> side/bodyPart -> heldObject/empty`。一个人物右手持器械，不等于其被接触的左手也持器械；shot 的 framing、action、materialResponse 和 sound 均不得把另一侧肢体的持物复制到接触目标上。当前 clip 负责新建接触时，`continuity/startKeyframe/stateIn` 必须保持“尚未接触”，只在唯一发生 shot 后把接触元组写入后续 shot，并让最后一镜达到父级 `exitState/stateOut`；不得为了强调持续锁而把片尾接触状态前置到片头。

动作声必须由画内可见材质和真实运动直接产生。皮肤接触只能有极轻皮肤/衣料摩擦，不能产生机械咔嗒；静止或悬停的惰性金属不能无来源嗡鸣；画面亮度、人物淡出、抽象关系构图和“意识流动”本身不生成闪烁声、电流声或虚空脚步。无法指出可见声源、接触材质和发声相位时，使用中性 room tone 或保持静默，不为每个 shot 强行凑音效。

`visualTask` 记录内部信息任务，`action` 是供应商可见内容，两者必须使用同一进入姿态和同一动作主语；必要画面不能只存在于 visualTask：角色已经站立时不得在 visualTask 写“起身”，已经抬头时不得写“抬头”，已完成的动作只能作为既成状态。身体部位不能代替人物执行另一个部位的动作，例如不能写“指尖转动视线”；应拆成“指尖停在扶手上，人物视线转向对面”。生理动作同样遵守唯一所有权：原文只写瞳孔骤缩时不得先放大再收缩，未冻结吞咽时不得以深呼吸为由新增喉结滚动。

公开 Hell Grind 提示词中常见的 `WORLD POSITIONS`、`STATE AT FRAME OPEN`、`PHYSICAL STATE`、`CAMERA MOTION`、`AUDIO`、`CONTINUITY`、`FINAL FRAME`，在本 writer 中对应的是事实槽位，不是必须照抄的英文标题。优先写正向可执行事实，负向约束只保留父任务明确的 `forbiddenTransfer` 或确定性漂移风险；不要把长的全局项目历史、所有再生成版本或无职责的参考图重复塞进当前 prompt。

角色资产卡只由上游 `tapcanvas-character-card` 生成：`character-card/v3` identity anchor 建立可复用身份，状态版本从同名基态/上一状态做有来源的 image-edit 差量。你不在 clip prompt 内重新设计角色、不把状态卡里的情绪烤成永久事实，也不把参考图的偶然姿势当成当前动作起点。

再生成只沿父任务提供的当前 prompt revision、scene/clip 作用域和真实资产事实继续。self-QA 可以报告引用职责、空间、动作端点、声音、状态交接和时长合同是否覆盖；没有真实媒体/节点证据时，禁止宣称“最佳版本”“已解决”或“成片完成”。供应商已受理或已产出的资产不得因 prompt 主观检查而被拦截、回滚或丢弃。

## 原创化首稿编译

在唯一首稿进入结构提交前，writer 必须依据当前完整语义上下文区分三类事实：项目自有或已明确授权的身份与资产、来源文本必须忠实保留的剧情/对白事实、以及仅作为第三方作品联想或创作参考出现但没有授权事实的名称与视听表达。这个区分由当前模型完成，不建立标题、人物、演员、工作室、作者、歌曲或风格关键词表，不由 Hono/Web 用正则或命中规则复判。

- 没有明确授权事实时，来源中出现的外部作品、角色、演员、工作室、创作者、歌曲、精确经典场面或“照着某段拍”的描述，只能作为剧情语境或功能参考，不能直接进入供应商可见的身份、造型、世界、镜头、声音或风格控制字段。不得从“用户提到了它”“原文人物回忆它”推导复制许可。
- 忠实度守恒对象是当前章的剧情功能、人物因果、情绪拍点、关系、事件顺序、冻结状态和逐字人声，不是第三方视听实现。writer 保留“人物回忆、比较、预警、误认或受到某作品影响”这个源事实；若需要把被提及内容画面化，则改写为同功能但原创的角色原型、服装轮廓、世界细节、空间几何、走位、效果材质、镜头轴线与剪辑节奏。
- 对精确场面类比，首稿在当前推理中至少建立两项彼此独立的原创差异，可从空间几何、人物走位与路径、服装/轮廓、效果机理与材质、摄影轴线与剪辑节奏中选择。这里是模型创作责任，不输出计数，不建立运行时阈值，也不由宿主逐项验收。
- 冻结 `speechEvents` 若逐字包含第三方名称，仍按来源合同保留，不删、不改、不拆；但不得把该名称复制到视觉控制字段，或据此扩展成精确角色、场景、表演、配乐和镜头复刻。对白说到什么与画面需要复制什么是两条独立责任线。
- 已存在的 canonical 项目对象、用户明确提供且声明有权使用的资产，以及真实 `assetObjectContracts` 继续逐字保留。writer 不得为了“原创化”重命名项目自有角色、替换已授权资产或臆测用户没有权利；同样不得仅凭资产存在推导它授权了资产合同之外的第三方作品复刻。
- 风格写成可执行的摄影、色彩、材质、节奏和表演特征，不以在世创作者、工作室或品牌署名替代创作决策。音频只使用冻结人声和本场真实声源；没有明确授权时不指定现成歌曲、旋律或可识别配乐复刻。

该原创化投影必须在唯一模型响应内部与剧情、动作、声音和连续性一起完成。runtime 只做 schema、权限、真实资产、计费幂等和供应商硬边界校验；它不在提交后调用模型改稿，不因原创差异数量、名称命中或主观相似度退回首稿。供应商仍可能基于其不可见策略拒绝某个输出；发生时保留所有已受理任务与成功资产，按真实错误结束当前物理 run，再由下一阶段依据失败证据改进合同并启动新的 fresh run。

## 首稿与同链复盘

先完成可执行首稿，再在同一作者上下文按权威 `authoring-contract-v1.json.runtimePolicy.reviewBudget` 进行证据驱动修订。对最终供应商可见字段合读，具体执行方法复用已加载的视觉共同基线；修改后回读受影响镜头与相邻承接，不能因已修订一次而留下已知可修复冲突。没有新错误或只剩可选审美差异时结束，不发起外部评分循环或额外媒体生成。缺冻结事实与外部条件如实记录，不能编造修复。正文稳定后更新 `selfQaNote/creativeReview`，iterations 记录本次实际内嵌复核次数，不固定填1，也不限制内部改稿次数。派生数量仍由现有结构编译器重算；检查不取得用户级终态裁决权。


- 对最终每个 shot 单独做一次“入口动词 + 信息任务”复核：`action` 的第一个状态变化必须直接消费上一镜 exit 或父级既成 entry；父事实已经是移动中、接触中、持有中、打开、显露或完成时，禁止重新写成接起、抬起、走近、准备、启动或再次完成。`visualTask` 只允许一个需要观众独立辨认的信息变化；同镜若还要求辨认另一个主体的状态变化、表演起点或不可逆后果，且二者不是同一接触的同时反作用，就拆成相邻 shots，并以动作、视线或声音接力。不得因为它们属于同一个 `storyEvent` 就合并。

- 必须服从本 skill 已内含的 V3 画面/运动基线：旧式逐段配图、静态展示、每镜稳定落幅、无动机运镜包装主体不动的写法不得进入首稿；不通过另一个 Skill 重复加载同一套基础规则。
- 当前 clip 可能没有关键帧、使用普通单状态 image，或把 2～3 个决定性状态按时间顺序收束为一张故事板 image。只有存在多状态故事板时，首稿才需要把格间变化写成连续因果：上一状态的速度、受力、视线或环境变化触发下一状态；禁止逐格报幕、逐格停住或把故事板当互不相干的 PPT。核心人物卡、群像图与决定性武器/VFX 资产只锁身份和物件，不复制其原姿势与背景。

- 第一拍从 `startKeyframe` 的既成状态开始，不重演上一 clip 已完成动作。先列出本 clip 内每个不可逆动作（抬头、起身、抓住、放下、进入、离开、吞咽/喉结滚动、切入/切回时间层）的唯一发生 shot；同一动作不得在开头和结尾各执行一次，也不得以近义词重复。父任务若把同一动作同时写进上一 clip 的退出态和本 clip 的起幅，只能把它视为已经完成的状态，不能再次执行；若当前 clip 才拥有该动作，上一状态必须明确为“尚未发生”。若剧情需要先看对方再“猛地抬头”，前者必须改为不改变头部终态的眼神/听觉反应，不能让人物完成两次抬头。
- 父任务给出的 `startKeyframe/characterStateVersions.stateIn/sceneState.stateIn` 若与上一 clip 的冻结 `exitState/stateOut` 存在未被拍出的姿态、接触、道具或空间跳变，writer 不得用“按冻结起幅重建”“不硬桥接”等解释性文字把矛盾藏进 `continuity`。只能沿真实共同状态写首拍，并在 `selfQaNote` 明确要求父级修订相邻 beat；若父任务声明时间跳跃，则核对前拍是否已经完成返回，禁止重复执行同一次回忆→当前切换。
- 最后一拍明确落到父级 `endKeyframe` 与 `exitState`；它们是技术窗口的状态边界，不自动代表戏剧结尾。writer 不复制这两个宿主字段，只在 `continuity/shots` 中把终态演出来。
- 父级 `exitState` 已按当前 `arcContract` 冻结真实终态：`open_motion` 保留未完成动作矢量，`local_transition` 完成局部换势，`sequence_resolution` 可以稳定收束。最终 renderer 只会逐字投影宿主保存的 `【退出态 / EXIT_STATE】${exitState}`；writer 必须让最后一镜与其一致，不得另写第二份退出态，也不得统一追加“向下一镜交棒”“保留残势”“不提前稳定落幅”或相反的强制定格/稳定落幅。
- 逐字服从父任务冻结的 `continuityMode`：`editorial_cut` 在新镜头中重建构图但保留身份与物理进入态；`bridge_frames` 必须把真实起幅通过可执行的动作/受力/运镜/形变路径落到真实尾帧；`reference_video` 从上段真实视频已接受的终态继续，不复述、倒放或重演已完成动作。
- 一条 clip 只服务一个剧情变化，所有 shot 形成因果推进。这里锁的是剧情结果，不是动作数量：高烈度战斗可以用多次可逆拆招、追击、换区、局部破坏与攻守反转把同一个结果完整演出来，不能把“一个剧情变化”误写成“一次攻击”。
- 每条 clip 逐字服从父任务的 `arcContract`。起承转合只在用户要求的真实整体尺度成立，不按供应商单段时长重启：`open_motion` 从既成动作/压力中进入，以仍开放的速度、受力、追击或交互矢量退出，禁止补对峙开场、局部终局高潮、悬念、胜负收束、定格或声场终止；`local_transition` 允许完成一次换势与可见后果，但不得冒充整体结尾；只有 `sequence_resolution` 才形成完整余波与收束。所有 clip 仍须有真实主体变化，不能退化成素材轮播或摆拍。
- 大片感来自尺度、对比和后果的组织：先用建立镜交代空间和人物关系，再用中近景承载选择与表演，最后用反应/余波证明事件改变了什么。需要细腻时，写可见的停顿、视线回避或锁定、呼吸变化、手部犹豫、距离缩短/拉开和声音断裂，不堆“深情、震撼、压迫、电影感”等抽象词。
- 逐项落实父任务冻结的 `arcContract/dramaticChange/audienceExperience/payoff/emotionTurn/pacingDecision`。非终局窗口中的 payoff、观众注意与情绪字段必须解释为整体弧线的 carry/escalate 或局部推进，禁止据此发明当前 clip 的独立问题、终局兑现或开放式结尾。`dramaticChange.stateTransitions`、债务生命周期、最早兑现拍、因果来源与 `residueIn/residueOut` 都是不可改写的连续性事实；每条状态动作必须在画面、对白或声音后果中可辨认，但不要自行新增、重复应用、改写 before/after、提前兑现、关闭后复活、把推断升级成事实或让人物情绪重置。
- 逐镜演出必须保持冻结合同的语义强度。身份或归属误认只能演成对应对象、视线、示意和已发生的错误判断，禁止在 action、表演、声音、构图或 `selfQaNote` 中升级成偷窃、欺骗、背叛、罪责或恶意；口述、猜测和人物表态不得拍成客观鉴定或真相。父任务只确认动作重复、持续或次数增加时，只能表现同性质动作及其累积痕迹，禁止擅自增加力度、速度、愤怒、恐惧或敌意。需要更强推进时，从冻结的约束、次数、位置、资源、暴露痕迹和可见后果中组织，不得改写事实强度。
- `pacingDecision.essentialCausality` 只是原文承载下限，不是完整清单；canonical `sourceSpanText` 才是当前 clip 的逐句事实真源。用户明确要求忠实完整原文时，writer 在设计 shots 前必须把 `sourceSpanText` 逐句、逐分句反向拆成身份、背景、关系、位置、动作、神态、环境、动机、因果、选择、结果与时间转折义务，再逐项指定实际 `shotNo`。每项义务都必须进入 `shots[].visualTask/action` 的可见画面；只写在标题、logline、continuity、notes、`selfQaNote` 或 source marker 中一律视为未覆盖。父任务的 `essentialCausality`、logline 或关键帧若漏列了 span 内事实，writer 仍须在不改写剧情、时空和终态的前提下用真实 shots 补足；合法时长确实不足时报告 `input_source_obligation_budget_conflict` 让父级增拍/增时长，禁止静默删除。
- 原文跨度不是逐句照抄成画外音的清单。主 agent 已在 `narrativeAudioPlan` 中对当前 clip 作出语义裁决：`visual_only/source_speech_only` 时不新增人声，`source_grounded_voice/mixed` 时只使用其中已经冻结的 lines。writer 不重新编写、删除或改写这些正文，只判断它们与画面是否互补，并安排可懂的发声窗口。身份、背景、动机、因果或结果若能由动作与状态清楚表达，可保持纯视觉；若陌生观众仅凭蒙太奇无法理解且父计划已冻结叙事音频，则让 VO/OS 提供方向或因果，但仍必须有相应可见载体，禁止“坐着把剧情念完”。原文未给地点、交通、设备、服装或行为细节时，只作当前画面成立所需的最小中性选择；不得把“回国”擅自具体化为码头/机场/车站，不得把未具名房间在相邻 clip 间改叫书房、卧室或客厅，不得增加年代不确定的仪器、病号服、文字牌、人物动作或新的因果。后文已经描写同一事件时优先复用后文的一手细节。
- 抽象背景事实、关系变化、资产转移、某人离开或未来结果没有 canonical 地点和可见动作时，采用“事实物化预算”：只表现来源已经确认的人物、关系、物件与结果，不补房屋格局、窗户、门、街道、人群、柜架、交通方式或离场动作。画面需要承载抽象事实时，优先用非可识别环境、受控留白、既有资产局部、关系构图或已确认物件状态；不能为了让蒙太奇看起来丰富而建立新的生活空间和群众行动。
- 负向约束不得把一个抽象禁止项扩写成长串具体地点、交通工具、人物或物件名。若来源只要求地点未知，使用正向允许态“无可识别地点/交通信息”；不要在可执行提示词中反复写出码头、机场、车站等未发生名词，避免反向诱导生成。
- 环境声同样属于事实。脚步、人声、广播、门响、车声等会暗示新增人物、动作或空间；只有来源、Scene Packet 或可见动作已经建立时才能写入。没有依据时只保留当前可见人物/物件真实产生的声音与中性 room tone，禁止用画外人声或走廊动静补热闹。
- 必须提交 `dramaticCoverage`，把冻结的每条戏剧义务映射到真实存在的 `shots[].shotNo`。它是 writer 的可追溯承载声明：`stateActions` 使用当前 beat `stateTransitions[]` 的零基 `stateTransitionIndex` 逐项覆盖 `0..N-1`，禁止复制、改写或自造机器 `actionId`，服务端会从冻结 BeatSheet 确定性还原并持久化原 ID；`debt` 逐字沿用 `payoff.debtId/lifecycleAction`；`causality` 以零基索引逐条覆盖全部 `essentialCausality`；观众揭示、可见兑现、反应承载与情绪导致的行动变化分别填写非空镜号数组。不得用 logline、自检文字或笼统“全镜覆盖”代替逐镜映射，也不得引用不存在的镜号。
- 景别、机位、运镜、构图、光线、动作、表演和声音围绕当前变化组织，避免静态站桩与 PPT 式轮流展示。
- 不以“有运镜”作为动态充分条件。若去掉相机运动后主体、道具、环境和人物关系没有发生可见状态变化，该 shot 仍属于静态展示，必须重写主体因果链。
- 动作必须写可见的进入条件、过程、反馈和结果；进入条件可以是静止起步，也可以是上一动作尚未消失的速度、受力、偏转、失衡或恢复债务，连续链不得把“进入条件”误写成每次重新起势。人物情绪用呼吸、视线、姿态和小动作表达。
- 对任何位移动作，必须写出可复现的空间轨迹：起点相对场景锚点、移动方向、垂直/水平高度差、持续时间、受力来源、途中姿态、落点/接触点和环境反馈。禁止用一个动词概括完整位移（例如只写“跃上屋顶”）。如果跨 clip 省略了无法仅靠冻结文字和 canonical 资产推导的关键物理里程碑，例如前段尚未起跳而后段已经落上屋顶、物体尚未释放而后段已经被接住，必须使用冻结的 `bridge_frames` 起幅/尾幅或真实 `reference_video`，不能用 `editorial_cut` 隐藏因果缺口。由父任务成对冻结的低熵 cut-on-action 不属于状态跳变：人物、武器、方向和环境终态必须连续，剪口只省略同一简单遮挡/主形/运动矢量的微小中间相位，下一段仍从自己的真实资产独立重建。
- 对任何物体转移，严格保留源动作类型和权力关系：抛掷必须写释放点、抛物线方向、速度/距离、接收者的反作用与最终握持状态；递交/交接才允许写伸手靠近。不得把“直接抛出”改写成礼貌递交，也不得让接收者无受力地凭空拿到物体。
- 空间关系必须能被观众读出来：在同一镜出现两个以上主体时，分别写前/中/后景、屏幕位置、主体间距离或相对身高、视线方向、轴线和遮挡关系；出现屋顶/地面/高墙/塔等垂直结构时，写明确高差和同框尺度参照。只写“保持距离”“空间关系完整”不够。
- 信息型镜头不能只靠旁白完成。对世界史、任务面板、资源/风险权衡和主角内心总结，至少安排一个可见载体（时代变化画面、系统面板、主观空间、道具数值/反应或角色选择动作），并在 `dramaticCoverage` 的 `audienceReveal` 与 `visiblePayoff` 中逐镜映射；没有载体时必须在 `selfQaNote` 显式报告缺口。
- **真实感是物理可信，不等于真人写实。** 动画化比例、速度线、受控形变和用户允许的冲击标点可以夸张，但质量、重心、惯性、摩擦、碰撞、反作用与材料响应必须连续。禁止用粒子、闪光、残像、瞬移、震屏或旁白替代没有生成的人体运动与角色交互。
- **重击后的空中路径必须有重力和制动。** 除非冻结的角色/世界合同明确了飞行、悬浮、失重或持续外力托举，受击者不得在空中匀速、慢悠悠地漂浮。写清攻击方向与接触点 → 瞬间加速度/旋转 → 有限抛物线或被墙、地面、障碍物截住 → 撞击形变、碎屑/扬尘/水花等材料反馈 → 落地、翻滚、滑行或抓握制动后的终态。打斗强度优先由动作幅度、重心失衡、惯性残势和环境破坏表达，而不是把角色悬停并叠特效。
- 对 agent 明确判为高动力的 shot，附上 `motionDynamics`，采用**导演级相对档位**而不是捏造精确物理数据：`tempo: instant|fast|sustained`、`force: light|medium|heavy`、`direction: left|right|forward|backward|upward|downward|diagonal`、`airborne: none|brief|extended`、`rotation: none|partial|full`、`brakingMode: ground_friction|wall_impact|grip|counterforce`、可选 `impactSurface: ground|wall|water|object` 与 `environmentalResponse: none|dust|debris|splash|deformation`。例如重拳命中后可写 `{tempo:'instant',force:'heavy',direction:'diagonal',airborne:'brief',rotation:'partial',brakingMode:'wall_impact',impactSurface:'wall',environmentalResponse:'debris'}`。`direction` 没有 `none` 档：若当前 shot 没有可声明的方向或并非高动力镜头，语义上省略整个 `motionDynamics`；严格提交工具若要求属性存在，使用 JSON `null` 表示省略。不得给任一枚举写 `none`、空串或自造值。这份结构只表达快慢、冲击与制动；动作正文仍必须描述谁受力、在哪里接触、可见后果和最终姿态。
- 连续追击、抢攻、重击、冲刺、翻滚、击飞或高速换位一旦构成本镜主要变化，就属于高动力 shot，不能因动作正文已经写了“快速/猛然”而省略 `motionDynamics`。连续链中 `tempo` 描述当前动作实际速度，`brakingMode` 只描述真实受力或落点，不得反向扩写为额外停顿、站稳或完整恢复表演。
- 呼吸、视线、姿态和小动作只能让冻结情绪行动可见，不能自行诊断角色内心或提高指控等级。没有源事实或合同支持时，不添加“心虚”“凶狠”“仇恨”“被揭穿”“犯罪感”等结论性表演标签。
- 跨场景时第一拍建立新空间；`timeJumpNote` 存在时明确时间跳跃，不伪装连续动作。
- `characterRoleNames/sceneName/propNames/vfxNames/characterStates/temporalContext/sceneState/characterStateVersions` 只使用父任务给定值。时间作用域切换时禁止继承相邻 clip 的临时人物或场景状态；返回原时间线时按 `returnAnchor` 重建。
- 角色、场景、道具和 VFX 都是同级资产对象。逐项读取 `assetObjectContracts`，不得只把角色当主体、把道具或特效降成形容词。
- `assetObjectContracts` 是父任务冻结的结构化事实合同，只作为 writer 输入；writer 禁止在输出中复制、置空或改写，服务端会在返回后逐对象确定性投影。正式 renderer 只把对象职责、身份不变量与禁止迁移压成一次 `【参考资产锁定】`；`driver/stateChange/endState` 必须真正落实到 `continuity/shots` 的动作与状态变化中。
- `identityInvariant/startState/spatialRelation/scale` 是已由真实资产与 1～3 帧 clip 故事板建立的静态事实；renderer 会在参考锁定中保留 `identityInvariant`，writer 必须把当前动作真正依赖的 `startState/spatialRelation/scale` 在 `continuity` 或首次消费它的 shot 中正向写清，后续继承而不逐拍复读。shots 不重新设计站位、接触关系或尺度。
- shots 的主要职责是逐对象落实 `driver -> stateChange -> endState`，并写清动作引发的环境反馈。不得为增加“画面感”改写对象身份或起始空间。
- VFX 仍是 VFX。合同写“青萍剑光”时只能表现光迹的发源、路径、扫过反馈与消散终态，禁止擅自实体化为“剑锋”“一把剑”。
- 每个发生状态变化的 VFX 必须写成一条连续的“特效运动合同”，而不是形容词或否定词清单。至少明确：生成源、可追踪主轮廓、前缘/主体/尾迹层级、运动路径与速度曲线、密度/厚度/透明度变化、接触阻力下的压缩/分流/卷曲、对角色与环境的遮挡关系、核心/边缘亮度预算、二级材质反馈、失去驱动力后的消散过程，以及相邻拍继承的位置/方向/厚度/速度。禁止特效每拍凭空重生为另一种形态、一帧消失或全域同亮同透明；战斗分支只在用户合同允许时叠加时间强调或峰值视觉重音，这些重音必须锁在可读的真实接触点上，不能替代主体动作。
- 非战斗技能展示仍以一个清楚且可持续追踪的主形为视觉中心。战斗 clip 也必须保持连续的接触、位移、反作用和局部材质反馈；是否使用峰值、英雄时刻、近景插入或时间强调由 UserIntentContract 与冻结故事事实决定，不得因“唯一战斗标准”自动为每个 clip 生成一个高潮。
- 本镜被 writer 判定为 VFX 主导领域并选择加载 `references/vfx-visual-quality-contract.md` 时，按其“主形优先、材质分层、接触耦合、逐拍继承”方法写作并完成反廉价感自检。
- 道具必须保持 owner、支撑方式、接触间隙与尺度链。例如合同规定“混沌钟悬浮于掌心上方、法力托举、由小变大”时，禁止改成手掌贴钟、握钟或先以巨钟贴身起势。
- **距离与动作必须自洽。** 贴身距离不能无准备地演成需要完整飞行距离的大力投掷；投掷必须先由角色拉开距离、改变释放方向或利用高低差，并写清释放点、飞行路径、接触与接取反作用。若 BeatSheet 同时冻结了互相冲突的距离与动作类型，在 `selfQaNote` 如实报告输入矛盾，不用本地关键词规则偷偷改写语义。
- **尺度链必须挂在承载得起它的景别上（服务端确定性校验）。** `assetObjectContracts.scale` 声明“占画面高度五成”这类近半屏比例时，本 clip 必须有一个中近景以上的镜承载它；若全 clip 都是大全景/远景/航拍，该尺度链会被渲染静默作废——主角小到读不出来，观众收不到“主体是谁”的信号，段与段的衔接随之崩掉。真实事故：某版 clip 首镜写“大全景，建立四人空间关系”却要求主角占画面五成，成片里主角只占不到一成，紧接前一段的航拍全景，观众完全读不出已经切回现实。
- **切回主线的第一镜必须让主体可辨识。** 从历史闪回、蒙太奇或大景别环境段切回当前主线时，首镜不得再用大全景空镜起手；至少要有一个能读清主角面部或标志性识别特征（发色、服装、随身武器）的景别，否则连续两个远景相接会被观众读成“又换了一张风景图”而非“回到现实”。若 BeatSheet 的接点写了匹配剪（如“公共火炬暖光匹配到掌中火焰”），必须在首镜的 `lighting` 里把被匹配的那个光源实际写出来，不能只在 `continuity` 里声明。
- 参考资产按身份和场景事实使用，不发明 node id、URL 或新资产。
- 每份参考资产只按父任务的 `referenceRole` 承担一个主职责，并逐字遵守 `forbiddenTransfer`。不得把 identity 的背景/姿势、environment 中的人物、palette 的具体内容、composition 的身份特征或 vfx 的实体外形迁移到成片。
- writer 输出中的 `speakerBindings.name` 与 authoring JSON 视觉文字都逐字使用 canonical 资产名；每个承担动作、反应、受力、视线或空间关系的主体必须使用对应 `assetObjectContracts[].name` 的完整冻结名称，不得缩写为“少年/少女”“他/她”“双方”等别名；禁止填写画布 node id、URL、`@图N` 或自造图片编号。`characterRoleNames` 与 `assetObjectContracts` 只作为冻结输入，由服务端投影。writer 禁止提交 `dialogue` 正文，`speakerName` 继续填 canonical 外键。
- 最终 provider prompt 只保留视听语言。参考图由 renderer 依据真实 `content[]` 顺序绑定到 canonical 对象的独立参考表；视听正文保持完整 canonical 主体名称，同一对象的多张图只表达多个参考视角，不替换成并列主体。nodeId、assetId 与机器协议不进入模型正文。
- 参考资产只作为模型可见的身份、外观、空间、材质和职责基线；动作、位移、受力、摄影、声音和终态必须在视听语言正文中直接写出。视频不注入项目画风锚，也不把 canonical 名或图片编号写进对白正文。
- 叙事/对白 shot 只设一个有动机的主运镜轨迹。高烈度战斗 shot 服从战斗 reference：允许并鼓励 `①起始捕捉 → ②随位移/攻击线接力 → ③接触/结果释放` 的 2–3 段 ACT 复合机位，在同一动作轴上无缝衔接贴地跟拍、whip pan、兵刃/眼神微距、俯冲追尾、Dolly Zoom 或焦点转移；禁止的只是无时间顺序、无动作动机的运镜词堆叠。
- 多人物镜必须给出可区分的角色名、画左/画右或前后层级、朝向、相对位置与各自动作；不得用“众人”“双方”代替已有权威角色身份。
- 静态 look 只服从父任务提供的真实项目 style reference 与 `filmBible.visualBible`，不得另找参考作品或对标品牌。普通叙事与高烈度战斗都不得补写默认的 8K、3D CG 写实、PBR、帧率、院线调色或实拍机型；父任务已冻结的媒介与动态输出事实可在开头集中写一次，随后把正文预算用于动作、光线、材质和声音，而不是逐 shot 复读画风或质量口号。
- 父任务缺真实 style reference、`visualBible` 与参考图互相冲突，或把待生成效果图当成已存在资产时，在 `selfQaNote` 明确报告输入缺口，不自行补一套默认视觉描述。

### 收敛编译合同（唯一结构化路径）

本 skill 内置提示词构造、动作、摄影、声音、VFX、情绪与 IP-safe 判断，但不改变 TapCanvas 的生产协议。最终仍只输出本 skill 定义的 `clips[0].shots[]`；禁止另造 `shot_type/style_lock/keyframe_first_frame/performance_timeline/negative_prompt` 等平行根字段，也禁止返回一份自然语言 prompt 代替结构化 clip。任何通用 Seedance 示例或普通短镜建议与本合同冲突时，以本 skill 与本轮按领域选择加载的唯一 reference 为真源；未加载 reference 时以本 skill 的基础合同为真源。

首稿按下列顺序编译，每句话都必须减少模型自由度、保存冻结事实或提供下一拍可消费的状态；不为“格式完整”填无信息字段：

1. **继承静态事实**：身份、服装、材质、场景、比例、站位基态和整体 look 只从真实资产、`assetObjectContracts` 与 `filmBible` 继承；`shots` 不逐拍复述，也不自行补风格名、器材参数或质量口号。父任务已冻结的媒介与动态输出事实只在开头集中写一次，不受“逐拍不重复”规则影响。
2. **建立空间坐标**：逐字读取 `beat.storyEvents`、`assetObjectContracts[].spatialRelation/startState/endState`、`beat.characters` 与 `sequenceContext`，在当前 writer 的临时推理中建立互动轴、机位侧、屏幕方向与必要的轴线重建策略；这些是创作过程，不回写 BeatSheet，也不形成运行时硬闸。再用已冻结的场景锚点写世界空间，把逐人站位、朝向和移动方向落实到真实 shots，不得只在 `continuity` 复述后让镜头自由漂移。跨镜保持轴线、视线和运动方向；需要反转屏幕关系时，必须先拍出中性轴移动、可见越轴动作或新建立构图。
3. **拆可见相位**：每个主要动作按“执行者 → 继承的进入条件/触发 → 路径改变 → 接触或选择 → 可见反馈 → 可接力状态或冻结终态”组织。只有真实静止起步才补一次独立起势；下一 shot 必须从上一 shot 已改变的位置、速度、受力、视线、持物或声场继续，禁止跳过过程直接抵达结果，也禁止先复位再开始下一动作。
4. **裁决长镜或切镜**：父任务要求真正一镜到底时，`shots[]` 只保留一个 shot，在该 shot 的 `action/cameraMove` 内按时间顺序写相位；不得同时出现“切到、硬切、正反打、甩到新机位”等剪辑语言。允许内部切镜时，每个 `shots[]` 条目就是一个真实 edit shot，`editRhythm` 必须说明切点由哪次动作、视线、声音或信息变化触发。
5. **摄影机服从动作意图**：叙事/对白 shot 只保留一条主轨迹；高烈度战斗 shot 可在同一动作意图下写 2–3 个按时间接力的复合段，并明确起始捕捉、位移/攻击线跟随、接触/结果释放。英文术语只在能消除歧义时作为短括注使用；中文可执行描述是默认，不设“camera 必须纯英文”的形式配额。
6. **同步因果声音**：环境底声只需建立一次并在变化时更新；动作声按“接触前预示 → 接触瞬间 → 接触后余响”绑定真实可见事件。静默、声场抽空和无音乐都可以是有效设计；禁止为了填满每拍而捏造音效，也禁止把音效当成主体动作已经发生的替代证据。
7. **正向锁定优先**：先把必须出现的主体、空间、方向、动作路径、终态和资产不可变项写清。仅在父任务已有 `forbiddenTransfer` 或已知模型漂移风险时，用短而具体的约束补充；不得罗列剧情中不存在的对象或事件来“提醒模型不要生成”，不得用负向词清单代替正向构图与因果链。
8. **显式失败而非规避**：平台安全、版权或输入合同阻断时，遵循父任务与供应商的确定性约束，并在 `selfQaNote` 报告真实缺口；禁止用拆字、谐音、隐语或替换平台敏感词的方式绕过审查，也禁止暗中换模型、换故事或降级格式。

交付前再做一次收敛自检：去掉摄影机运动后主体是否仍发生可见变化；每次位移/交互能否画出起点、路径、接触和落点；屏幕方向是否能从场景锚点复原；长镜声明是否与剪辑词冲突；每个声音是否有可定位的声源或明确的叙事静默功能；删掉任一句后若不损失冻结事实、因果或执行精度，该句就应删除。
