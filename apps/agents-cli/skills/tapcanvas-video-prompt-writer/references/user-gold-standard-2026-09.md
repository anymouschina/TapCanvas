# 用户金标视频提示词：吸收规范

本参考由用户提供的六组成熟视频提示词样本提炼而来。它是 authoring contract 的领域表达参考，不改变结构化输出 schema，也不构成运行时质量闸门。

本方法随 writer 声明依赖加载，适用于工作流与纯对话提示词。它不是原文案例正文，也不是供应商参数来源；原文只能通过视频案例搜索回执选择性读取。已有例子的时长、帧率、分辨率、人物与能力都不能覆盖本轮事实。

本轮提供 BeatSheet 与 JSON 输出合同时，按其冻结事实和字段写稿；纯对话只要求提示词时，以本轮明确事实为准写时间线文本，不凭空创建 BeatSheet、资产身份或结构化字段，不因没有工作流输入而拒绝写稿。通用维度仍用于创作回放，输出形式由用户交付范围决定。

## 对话成稿的工作版本

对话文本创作先用 `artifact_write` 保留完整首稿，取得当前任务私有的不可变工作版本，再基于这份首稿完成有依据的局部修订，合并为最终正文。这个动作把“写完一稿”和“改稿”分开，使后一次推理有真实稿件可编辑；回执本身不代表完成，也不需要把草稿链接发给用户。首稿仍在当前上下文时直接使用；确实缺少正文时再按真实回执调用 `artifact_read`，不重复检索或重读已经具备的资料。

改稿前先做一次独立的事实回放，用 `artifact_write` 保留当前稿的修订依据：从用户本轮要求提取持续成立的约束；逐个对象引用它在各时间窗中的状态原句，记录来源、持物、位置、运动、附着关系与退出态；摄影另列机位、观察对象和前中后景关系。此步先抽取，不写评分或改稿结论，不补正文没有的动作，也不将所有未交代的信息都升级成缺陷。抽取完成后对照用户约束、同一对象的前后状态及实际摄影关系，只将有相互冲突原句或明确用户要求依据的项交给下一次作者推理修订。该私有记录是可回放的工作证据，不是交付、审查门禁或用户补充信息清单；无确定冲突时可以保留首稿。

事实回放优先核对持续约束的作用区间：将用户原句、正文总纲、各次出场和最后一个时间窗的退出态原句并列，不以自己的概括代替这些原句。最后一个画面仍属于成片，收尾、留白、冲击后的余效或剪辑转换本身都没有权力解除用户明确要求持续成立的状态。若正文另有结束条件，核对它是否来自用户事实；没有依据的结束条件由作者修订。环境余效、离体残留与主体自身状态分别记账，不能用前者的变化推断后者也变化。此项是作者的状态比较方法，不是运行时关键词检查或额外完成闸门。

改稿时承担作者职责，不回答“是否通过”。先在当前上下文找出确实需要修改的原句，说明它与哪条用户事实、同稿状态或摄影关系冲突；没有具体依据的改动不执行。以最小连带范围修改问题所在动作与相邻承接，其他成立的段落保留，不把完整重写当成必做程序，不为了更具体而新添数值、解剖细节、机位或动作。修订后对照原稿核对改动是否引入新的空间、时间或持物矛盾。保留用户事实和成立的创意，把同一对象在各次出场中的明确属性、持物、支撑和接触状态放在一起核对，直接解决正文中的欠定选择、相互冲突或无法执行的承接。让镜头服务于已经写清的动作；明确的场景剪辑可以建立新的开始状态，不必补拍用户没有要求的全部路程。把可迁移的方法落实为当前稿的动作和状态，不能把案例特有的人物、装备或结果当成当前事实。修订后只交付可执行全文，不附“已按金标通过”等自评和工作过程说明。

已有正确内容可以保留，不为显示改动而重写，不以改动数量、稿件数量或差异大小判定质量。私有草稿工具不可用时如实记录该诊断，仍在当前作者上下文完成修订；它不是知识、生成或交付门禁。正式 Workflow IR 的结构化 writer 继续遵循其冻结的单 Clip 提交合同，不将私有草稿误当已提交的工作流结果。

## 在当前稿上完成复盘与修订

结构化工作流的事实回放直接在同一作者上下文执行：对每条冻结事件，将其“施力者/行动者、路径、接触目标或选择、结果”与实际 shots 的原句并列，尤其核对造成落败、伤势、物体转移或控制权改变的原因。事件索引、覆盖表和宿主投影的退出态只能证明声明与传输，不能证明镜头拍出了原因；击中物体不能替代击中人物，再保留后者的倒地结果。发现目标被换、过程被删或因果跳跃时直接改 action 及相邻承接，不用自检结论掩盖，也不等待后端拦截。

接触反馈写在接触当拍：偏转、分离、身体重心/肢体反作用及下一攻击窗口，环境火花或震屏只辅助它。已确认疯切、极快节奏时，写出不等长功能短镜与由动作触发的华丽转场，连续实时运动跨镜消费；不以一个“快速交锋”摘要占满多秒，不以“读清冲击”重新加入锁剑保持、慢放或长尾声。遵守本轮明确数值要求，但不把审美措辞换算成固定镜长或帧率。

严格工具要求每个键存在时，适用的导演字段填写真实执行决定；不适用的 lensIntent、lighting、materialResponse、sound、soundPerspective 用 null。framing、composition、cameraMove 仍需明确决定，固定机位也写清观察关系。不使用句点、空泛质量词或复制 action 填格；协议允许 null 不等于省掉镜头所必需的声音、光线或反馈。只输出必要信息，避免凑列。

保留首稿作为当前上下文的工作稿，按下列顺序回放，发现问题后直接修改对应时间窗；不要只补一段自检结论。工作流使用已有 `creativeReview/selfQaNote` 记录具体问题与修订，纯对话遵循用户要求交付最终稿，不额外公开内部手册或工作稿。

起草时先在当前推理中分别建立**主体轨迹**和**摄影机轨迹**。主体轨迹只记录每个实体的起点、通过的路径、发力/支撑和终点；摄影机轨迹只记录观察位置、方向、构图和遮挡。先把主体轨迹写通，再装配摄影机，不能用摄影机的运动动词替人物完成位移。正文可以合并两条轨迹，但合并后仍要能分别还原。

复盘时做一次删除检验：暂时拿掉“自然衔接、动势转化、连续、不得瞬移”等结论句，逐个比较相邻时间窗中同一实体的末态和初态。若仍需要读者自行补出位移、取得物体、拔出武器或变换支撑面的过程，就把该过程写进具体动作，重新分配时长；若使用明确的时间或场景剪辑，交代编辑关系与切换后的新状态，无需补拍未要求的全部路程。不要再加一句“保持一致”代替修订，也不要以看起来流畅的匹配构图作为人物连续性的证明。

1. **先回放状态，再看摄影。** 暂时删去摄影、光效与形容词，检查每次地点、距离、朝向、持物、支撑点与速度变化是否有可见过程。镜头从一处移动到另一处不等于人物已经到达；声称连续运动时交代位移，明确的时间或场景剪辑则建立切换后的新状态。
2. **把时间给动作。** 将本轮总时长分配到可执行的正数时间窗，每窗写清起始动势、一次主要变化和退出状态，保证总时长闭合。拆分或合并的依据是动作与信息可读性，不是等长排版或固定镜头数量；镜头形容词不能替代缺失动作来占时间。
3. **统一同一对象的状态。** 对照时间线各处的角色、武器、道具、能量形态、颜色、附着位置和余效。区分光照导致的外观变化与对象本身变化；声明保持不变的状态不能又在后文改变。先修正冲突描写，再精简多余否定句。
4. **从案例提取方法并验证迁移。** 只使用已经读到的原文，指出它能解决当前稿的哪一处缺口，把可迁移的触发、路径、反馈或剪辑关系改写成当前人物和时空中的动作。没有适用案例时按本方法原创，不编造来源，也不机械添加参考案例的复杂动作。
5. **用修订后的正文复核。** 每个已发现问题都对应到修改后的动作或状态，确认修改没有破坏另一处事实。`creativeReview` 记录“原问题 → 具体改动 → 修改后仍需注意的限制”，不以次数、字数、时长求和或“全部通过”充当改稿证据。不为显得做过复盘而捏造问题或修订。

## 金标的核心判断

高质量提示词不是形容词密度高，而是供应商能够按时间执行、观众能够按画面复原因果。每一段都要回答：谁在什么空间、从什么状态开始；什么触发动作；动作经过哪些可见相位；接触/命中后发生什么物理反作用；镜头如何让信息读清；这一段以什么状态交给下一段。

## 内部核对与最终表达

规格、身份、因果、状态与执行约束先在内部核对，不要求在供应商正文各写一节。最终按参考绑定与镜头时间轴表达：首镜落实必要进入态，每镜写实际动作及服务它的摄影、声音和必要光线，末镜落实退出态。全片因果总纲、执行纪律和高概率失败分析只有转化为本镜确需的具体指令才进入正文，不重复输出报告或通用禁词清单。

## 主体生命周期与镜头执行标准

- 画面里每个可见主体——人物、武器、道具、载具、特效、光、粒子、碎屑、烟尘与环境要素——都按同一条“结构 → 轨迹 → 环境反应”展开，不因它是人物还是特效而换规则：
  - 结构：它是什么、从什么状态开始、边界在哪、从哪里来。人物写起点姿态与支撑，物件写归属与持握，特效与二级元素写生成源、粒径与密度。不在画面任意位置突然出现。
  - 轨迹：它怎么动、沿什么路径、速度怎么变。写清路径、驱动来源与速度曲线，以及与接触对象的相互作用；镜头移动不能代替主体位移。
  - 环境反应：它改变了什么、留下什么、以什么状态交给下一段。接触点、受力方向和当拍反馈必须有实体来源；残留与退出态为下一拍提供位置与方向事实。
- 相邻拍必须继承上一拍的四项状态：位置、方向、厚度、速度。若任一项改变，写出造成改变的外力或阻力。
- 动作是主体的一种，按“继承速度/压力 → 触发与选择 → 路径/方向/速度变化 → 接触或释放 → 受力反应/环境后果 → 下一窗口”展开。
- 每次挥击、投掷、落地、碰撞、闪避或位移都要有可见的接触点、受力方向和当拍反馈；反馈可以是碎石、尘浪、火星、流体、结构破坏或服装受风，但必须有实体来源。
- 连续高速动作从上一拍未结束的动势接起，不反复写“站稳—蓄力—起手—收势”。除非用户明确要求，否则不把每段都写成独立的起承转合。
- 镜头运动服务于信息：超广角负责空间尺度，贴地跟拍负责速度与接触，特写负责关键物理细节，拉升/俯拍负责结果规模；镜头切换要说明动量、视线或遮挡的接力。
- 角色主体和关键动作保持可辨认。速度由位移、景别、前景掠过、环境反馈和镜头惯性表达，不依赖整个人物拖影或轮廓糊化。
- 特效必须有锚点：来源于剑刃、枪尖、服饰纹理、身体发力点、命中点或环境裂缝；禁止无来源的漂浮光团和粒子。
- 声音只写与画面实体和动作相对应的声音，并说明声音视角的远近/遮挡；不要用音乐或音效替代未拍出的动作。

## 复用时的取舍

优先保留可执行事实、因果清晰度、状态连续和镜头可读性，再压缩修辞。可以借用“宏观尺度、流体、层级破坏、电影光影”等表达方向，但必须按当前角色、场景、时长和供应商事实重新编译，不能照抄样本中的人物、武器、特效或固定镜头。

## 对话输入的最小信息

用户只需说明：视频目标时长/比例、角色或主体及其可用参考资产、场景与风格、核心动作或剧情结果、是否需要对白/声音、希望的节奏（例如高速连续、自然文戏、广告展示）。缺失的信息由 writer 依据真实上下文补成中性可执行 staging；涉及剧情事实、角色关系或不可逆结果时应由用户提供或由上游 beat 冻结，不凭题材惯例猜测。
