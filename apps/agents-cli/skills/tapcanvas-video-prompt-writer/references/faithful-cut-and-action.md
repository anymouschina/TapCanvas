# 忠实快切与原创战斗运动参考

## 忠实快切覆盖（仅在父任务明确裁决快切时）

本节只在父任务 `pacingDecision`、已锁 shot 边界或用户明确指令中指定“不改剧情、丰富镜头、自然主义表演、3 秒内切镜、长台词换机位”等快切裁决时启用。没有这类事实时回到“商用级导演母合同”，由信息变化、动作、对白和表演决定镜长，不把 1–3 秒当默认配额。这里的“忠实”锁剧情事实，“丰富”只增加可见证据与剪辑覆盖；两者不能混为一谈。

### 冻结层与可创作层

- **冻结剧情，允许拆 shot**：绝不改变原文锚点、状态变化、因果顺序、对白原文与顺序、clip 数、clip 时长、进入态和退出态。可以在当前 clip 内拆分或重组 `shots[]`，用不同机位承载同一个既定剧情变化；新增 shot 不等于新增剧情。
- 若父任务还明确锁定当前 clip 的 **shot 数量或 shot 边界**，则逐字服从并保留既有顺序、逐镜时长、台词归属与镜头功能；原有特写、空镜、反应镜全部保留，只深化现有行的表演、构图、声音和动作层次。若“锁镜头数”与“新增镜头”同时出现，在 `selfQaNote` 报告冲突，禁止暗中选择一边。
- 每个 shot 的可见内容必须能追溯到冻结事实，或属于不改变事实的**中性覆盖**：眼神落点、呼吸、手部小动作、道具细节、在场者反应、承接空间的短空镜。中性覆盖不得制造新道具、新线索、新动机、新关系、新伤况、新结果或提前揭示。

### 节奏与覆盖

- 快切模式下，内部 edit shot 默认 `1–3s`，逐镜从对白容量、动作完成时间、反应可读时间与切点功能反推时长，可使用 `1 / 1.5 / 2 / 2.5 / 3s` 等不同拍长，禁止把整个 clip 机械等分成同一个秒数。**如果用户合同进一步明确“最多 2 秒一个镜头”，或把本段裁决为疯切/高频硬切，则覆盖上述默认范围，所有 shot 必须 ≤2s；超过 2 秒仍有动作、接触、反作用或空间结果的镜头必须沿真实动作节点拆开，不能以空停、重复摆架或无意义运镜填满。**交付前检查时长分布：若所有 shot 恰好等长，只有每镜信息密度与动作复杂度确实相当时才允许保留，并在 `editRhythm` 逐镜说明；不得为了制造差异随意抖动数字。超过 `3s` 只用于无法再切而不损害对白、动作因果或表演停顿的镜头，并在 `editRhythm` 说明该长保持的叙事理由。
- 不按配额塞特写。只有当镜头改变观众所读到的信息、情绪证据或关系压力时，才从建立镜、过肩正反打、近景、眼神/手部/关键物大特写、在场者反应、功能性空镜中选用。只换角度却重复同一信息的 shot 必须合并或改写。
- 连续快切仍要有动作接力：优先用视线落点、动作方向、手中道具、声音先入/延留、光线变化或上一镜未完成动作连接下一镜。内部 shot 不要求逐镜稳定摆拍；非终镜可以 action-out，但当前 clip 末拍必须准确达到父级冻结 `exitState`，writer 不复制该字段。

### 自然主义表演

- `beat.characters` 是本 Clip 的可见参与者事实；结合冻结 `storyEvents` 和对象状态，在 writer 临时推理中为真实在场人物建立 `stimulus → visibleResponse → stateConsequence`，并由至少一个真实 shot 承载。主角决定镜头重心，次要或环境人物可以低振幅、短时出现或落在同一群像镜头，但不能被冻结成毫无反应的背景板；上游未声明在场的人物不得被补入。
- 写 shots 前在内部按人物建立不进入输出 schema 的 `causalProvenanceLedger={characterName,characterStimulus,responseShot,visibleResponse,stateConsequence,editTrigger}`；其中 `characterStimulus` 必须来自冻结事件或对象状态，`editTrigger` 只说明摄影剪辑为什么在该处切换，两者不得混为同一个因果字段。切点可以消费另一角色的动作、声音、视线或信息显现，但不能因此改写故事事实。
- `continuity`、逐镜 `visualTask/action/notes`、`editRhythm` 与 `creativeReview` 必须保持同一个人物、同一个刺激、同一个反应及其先后关系；可以把执行动作拍得更具体，但不得把角色 A 的动作替换成角色 B 的刺激、把共享刺激改写成某个配角动作，或在剪辑说明中另造一条与逐镜内容冲突的触发链。`editRhythm` 在最终 shots 因果链成立后再由镜头切点投影，不独立重写角色因果。提交前按人物逐项横向回放全部字段。
- 配角灵动不等于随机眨眼、点头、摇晃或手部小动作。反应必须发生在刺激之后，并至少改变视线、呼吸、重心、姿态、距离、接触或选择中的一项；若动作不来自当前刺激、也不留下状态后果，就删除。多人同框时用反应的振幅、时序和景深保持主次，不让每个人同时抢戏。
- 情绪细节优先写可执行事实：视线停在哪里又如何移开、一次呼吸是否被截断、手指如何松紧、下颌或肩背如何变化、身体是否靠近/退开、说完后如何处理道具。细节必须推动理解，禁止为了显得细腻而给每个人堆同一套咬唇、握拳、泛泪模板。
- 禁止使用“瞳孔地震、眼神一凛、眼底结冰、杀意爆开/炸开/燥开、气场全开、嘴角勾起一抹冷笑、死亡凝视、极致××、绝美××”以及“像××一样”的比喻式 AI 腔；禁止用“战士、法师”等模板标签替代原角色身份。禁止把人物态度升级为源事实没有支持的恶意、罪责或结论。
- 不自行补写或强调具体肤色、年龄、性别特征等敏感身份描述；已有角色身份由父任务的 canonical 名称与真实资产锁定。缺必要资产时报告缺口，禁止用文本重新发明角色。
- 暴力剧情保持原事件、施受关系、结果和顺序，但不直接描写血液、开放性伤口或残害过程；用遮挡、画外动作、受力声、道具落地、在场者反应与非血腥后果表达。安全表达不能反过来改写剧情结果。

### 对白、OS 与声音

- `dialogueScript` 中每条台词逐字保留并保持原顺序，但 writer **不得复制或提交台词正文**。每条 line 建立且只建立一个 `speechEvents[]` 项：`startOffset=0`、`endOffset=codePointLength`，并给出独立于镜头的 `startSeconds/endSeconds`。一个 SpeechEvent 可以跨越任意多个 editorial cuts；writer 必须省略 `shots[].speechEventIds`，宿主会在模型首稿已经闭合的最终镜头时钟上按时间窗相交关系确定性编译，绝不能因为换机位把“尸骨未寒”一类完整话语切成多个发声片段。
- 中文逐事件服从 `字符数 <= (endSeconds-startSeconds) × dialoguePaceRate`；英文逐事件控制在 `<=3 words/s`。语速不够时延长完整事件的发声窗口、调整视觉切点或回报父级重切 beat，禁止吞字、改词或用无依据的快嘴解决。
- `dialoguePaceRate` 必须作为真实表演速度使用：普通中文剧情对白应给停连、重音、呼吸和对方反应留下时间，通常落在约 `3–4.5` 字/秒；父任务给到约 `6` 字/秒但原文并非明确急促抢白时，writer 不得照单全收并产出“结构上刚好装下”的超速对白，必须在 `selfQaNote` 报告父级增加合法时长或重新切 beat。该检查属于同链创作修订，不是 Hono/Web 运行时闸门。
- 本 writer 没有跨 clip 搬运对白的权限。若冻结的当前 clip 时长仍容纳不下原句，在 `selfQaNote` 明确报告“父级需把剩余原文按顺序重分配到下一 beat/clip”，不得擅自挪动、截断、复制上一 clip 的镜头结构或提交超速对白。
- OS / VO 可以跨多个反应、细节、主观观察或功能性空镜。每个承载 OS/VO 且该角色入画的 `shots[].action` 都必须逐镜明确写出“嘴唇闭合、不做对应口型”，不能只在 `continuity`、`sound` 或一次总说明里声明；主观画面必须保持“角色所想/所见”的身份，不能把猜测拍成客观事实。
- OS / VO 的发声窗口必须与冻结 line 的 `sourceEvidence`、`afterSourceLineId` 和当前有序事件阶段对齐。可以跨切镜，但不得无说明地跨过与该句因果无关或语义相反的阶段；若确需用同一句串联两个阶段，先确认这是父级 `narrativeAudioPlan` 的明确策略，并让事件窗口起止和画面载体共同证明该跨越。逐镜引用由宿主编译，不是 writer 的证明字段。
- 除父任务明确要求音乐或字幕外，不自行新增 BGM、歌词、字幕或花字；`sound` 只写环境声、动作声、衣料/呼吸、对白与有叙事作用的静默。确定性渲染器会把 canonical `speakerName` 显示为 `@角色名`，writer 不得把 `@` 塞进 `speakerName`。
- 每条 `sound` 必须能回指本 shot 画内可见且确实发生运动、碰撞、摩擦、燃烧或发声的实体；没有可见物理声源时就保持静默或只继承已经冻结的真实 room tone。气味、墨水洇开、意识变化、回忆切换、人物从关系构图中缺席、模糊/虚化、静止或悬停的金属、皮肤轻触和抓握本身都不是声源，禁止为它们编造“气味对应底噪、意识流动声、虚化嗡声、淡出电流声、接触闷响、悬停嗡鸣”等感官代理音效。

### 空间与光影连续性

- `continuity` 先写本 clip 起始时所有出镜人物相对场景锚点的位置、身体朝向、彼此距离、持物、视线落点，以及主光方向、光质、色温与明暗关系；不要只用“画左/画右”代替真实空间。
- 站位变化必须写移动路径与新落点。后续 shot 继承上一 shot 的人物、道具、衣物、伤况、呼吸、光线和声场状态；换机位只改变观看方式，不重置人物状态。

### 交付前快切自检

交付前先把最终 `shots[]` 逐镜回放给七账本：镜号顺序必须逐项等于 `orderedEventLedger`，不得把父事实后果提前、把原因后置，或把“已缺席/已完成”重新拍成过程；所有 canonical 词逐处等于 `canonicalLexemeLedger`，不得残留近义词；所有肢体、接触、持物逐处等于 `limbContactObjectLedger`；每条 sound 都能逐项指出 `physicalSoundLedger` 的可见声源、真实运动与发声相位，不能就删除；每个具体化画面都能回指 `factStagingLedger` 的父事实且未把中性演出升级为新剧情；每个剧情承载对象都逐字命中 `visibleObjectLedger` 的 canonical 合同或已冻结占位；每个 shot 的 entry 与上一 shot 的 exit 必须在 `shotStateChainLedger` 中可重建接力，显式时间/场景切换则必须消费父任务冻结的新状态作用域和可见转场提示。

再逐项核对：逐条 `sourceSpanText` 义务都有真实 shot 承载，且每个冻结 `stateTransition` 都在 `dramaticCoverage.stateActions` 映射到至少一个真实 shot；剧情事实与顺序零改写；所有新增 shot 都是中性覆盖；姓名、台词与题材惯例没有被用于猜测未冻结身份；每个 shot 的时间子阶段与身体状态一致；不可逆动作各只发生一次；时长总和精确；每条冻结 lineId 恰有一个完整 SpeechEvent，长台词跨机位时事件不中断、不重启、不重复，writer 输出不含任何发声正文；OS 闭唇；所有出镜人物有自然反应；相邻 shot 的动作、视线、道具、声音或光线至少有一项明确接力。任一项不满足，先改首稿再交付。

## 原创战斗运动系统

出现攻击、防御、追逐、闪避、擒抱、重物碰撞或其他高动力交互时，逐 shot 使用同一套原创机制，不在最终生成提示词中引用、模仿或复刻任何现成游戏、角色、招式、UI、镜头或品牌名：

出现攻击、防御、追逐、闪避、擒抱、重物碰撞或其他高动力交互时，writer 必须先用 `Skill({skill:"tapcanvas-video-prompt-writer",resource:"references/combat-action-expansion-standard.md"})` 加载通用战斗 reference；加载成功的 `<skill-loaded>` 事件才构成该领域证据。该 reference 是本 writer 的“小说战斗场景动作扩写标准”，也是所有战斗场景的唯一扩写真源，其战斗专用条款优先覆盖本 skill 中“一个主运镜”“一个 VFX 高潮”“不写全局质量总控”“最小后果插值”等普通叙事口径。它允许在冻结的最终胜负、伤势、能力、持有关系与不可逆后果内，主动补足高强度但可逆的中间编舞：连续拆招、追击、攻守互换、跨区/垂直位移、贴身 CQC、局部地形破坏、轻重碰撞与极近景插入。真实参考图只锁身份、服装、道具、空间与材质，绝不能压缩动作正文。

若父任务的结构化创作判断同时冻结了动漫/超自然高能表现，再用 `Skill({skill:"tapcanvas-high-energy-action",resource:"references/high-energy-action-provenance.md"})` 读取该扩展；它不是第二个战斗标准，也不改变任何事实、权重或时长合同。扩展只把已有动作事实翻译成高密度可执行的表现层：动作链过渡、能力生命周期、局部 VFX 绑定、造型—能力耦合、声画接触反馈和低熵 editorial handoff。用户未冻结这些表现时，不主动套用动漫特效、能力升级或潮流造型标签。

当用户/父任务进一步冻结为“瞬身攻击、一击爆发、击飞大片、受击者 POV 或受击姿态连续”时，writer 在上述战斗 reference 之外按信息增益选择性读取 `knowledge/视听语言演出/combat-camera-focuslock-grammar.md`；该卡只提供“瞬身重现即进入攻击/接触、峰值受力与纵深、姿态锁定、主体绑定 VFX、POV 环境前推”的领域语法，不是固定镜头数、固定时长或固定姿势模板。若当前任务没有这些冻结事实，不得主动套用该卡。

战斗首稿必须达到父任务当前节奏要求的**有效动作密度**：每个保留的位移、攻防、接触、读招插入和环境后果都推进同一受力链，不能站桩等待或用残影、VFX、震屏替代动作本体。连续交锋必须把招与招之间的过渡当作正文：上一击的偏转角、回收债务、脚步未落、身体过冲、视线遮挡或空间挤压，至少一项直接成为下一击的进入条件；删掉过渡后若只剩互不相干的招式列表，首稿必须重写。地形穿梭、属性残影、ACT 复合动态机位和高频碰撞只有在 UserIntentContract、冻结事件链与空间条件确实需要时采用，不是所有战斗的默认风格。碰撞强弱只描述真实受力差异；`0.05s / 0.1s / 0.15s` 抽帧、负片、微升格、定格不是固定碰撞语法，只有 UserIntentContract/父任务明确允许时才可写入。用户禁止慢镜或英雄时刻时，所有碰撞保持实时速度，用剪切、遮挡、攻击线、接触材质和反作用读清动作。禁止复制样本的专有角色与逐句镜头，也禁止把样本再次蒸馏成“刺击—格挡—斩击—余波”的低密度摘要。质量不足只在同一 writer 内继续重写，不新增 reviewer、completion gate 或用户可见创作阻塞。

上句“不新增 reviewer”同时表示不创建独立 reviewer agent、独立裁决链或额外 reviewer Skill 读取；`autoload-resources` 已把共享合同与 `embedded_authoring` 自检维度注入同一 writer 上下文，writer 直接复盘并修订首稿。

战斗首稿必须把同一个力学事件的身体/武器编舞、守方选择、双方反作用、摄影机轨迹、材料后果、VFX 和声音锁成一条同步合同。每个高动力 shot 仍只提交既有 `shots[]` 字段；不创建战斗专用 schema，不让 Hono 或前端通过关键词、正则、招式表或固定 route 代替 agent 的语义扩写。

跨 clip 战斗默认优先设计可独立重建的 `editorial_cut` 剪辑接口，不把上一段真实尾帧当成唯一连续性来源。父任务若已冻结“低熵转场接口”，本 clip 必须逐字落实：出接口镜只保留一个主体或一个局部细节、一个主运动方向、一个遮挡/亮度/形态锚和干净背景，并在动作仍向画外延伸时切出；入接口镜从自己的真实角色/场景/关键帧资产重新建立同一运动方向、形态或明暗关系，再迅速释放到下一轮空间。兵刃擦镜、衣摆/身体遮挡、水雾沙尘填屏、脚步落点、眼神反打、冲击闪白与环形波纹都可作为共享剪辑元素，但不得让人物在缝口停住、兵刃长时间相抵、完整收势或在下一 clip 重新对峙起手。只有冻结合同明确要求同一镜头、同一开放运动的像素级延续时，才使用 `reference_video`；已知首尾状态必须逐帧过渡时才使用 `bridge_frames`。

## 空间与关键帧

- `blockingFrameNodeId` 只提供俯视站位、轴线、相对距离和接触关系的结构事实，不是视频参考帧。
- `storyboardImageNodeId` 是父任务按需提供的可选图片引用：普通单状态 image 与一张 2～3 状态故事板 image 都合法；无关键帧时省略。在 `editorial_cut/reference_video` 中它是普通 reference image；在 `bridge_frames` 中它是字面起幅，且必须同时存在真实 `lastFrameImageNodeId` 作为字面落幅。
- 多宫格设计板、整章母板、俯视线稿不得进入视频参考数组。writer 不读取这些图，也不把它们写入参考数组。
- 当关键帧已经钉住“数百丈间距”“掌心与法宝有间隙”等关系时，运镜不得反向抹平该关系。镜头可以沿轴移动，但结束构图必须继续满足合同指定的空间终态。

## 时长

### 同一信息只写在承担它的层级

- `continuity` 只交代入镜状态、轴线、时空切换和必须保持的关系，不预先复述整段动作、对白和离场过程。`editRhythm` 只补充逐镜正文无法表达的跨镜剪辑关系，不再按镜号概述全部剧情。
- 动作因果、构图、运镜、声音及发声放在实际发生的 shot 内；不同字段应各自增加可执行信息，不以同义改写增加篇幅。保留动作的先后与反作用，不能为了去重把连续表演改成摘要或静态画面。
- 自检从最终渲染的整段正文阅读：边界状态应描述同一时刻的实际画面，不得把已结束的梦境状态带进现实镜头；时空切换前后状态只能按冻结时钟各出现于对应位置。`exitState` 只留在结构化交接证据中，实际终点写在末镜 action，供应商正文不另附结束状态。
- 用户要求的尾部容错留在自然运动、呼吸或环境延续中，关键对白和剧情动作须在容错开始前完成。发现上游把过多事件塞进单 clip 时，在同链说明需要重分段的具体事实，不用加速叙述或删除心声解决。

- 父级冻结的 `clip.durationSeconds` 必须已经命中 `generationContract.durationOptions` 并等于当前 beat 的 `durationBudget`；writer 只消费这个时钟事实，不在输出中复制根时长。
- 每集 `90–120s` 属于父任务的整集时长合同，不由单 clip writer 自行补齐或裁短。父任务提供该目标时，当前 clip 必须保持其绝对 `clipIndex` 与合法时长档位，让全体 clips 的确定性加总落在合同内；若父任务要求整集 90–120s 却没有提供足以验证的整集时长/clip 计划，在 `selfQaNote` 报告父级缺口，禁止凭本镜猜测或增删 clip。
- 所有 `shots[].durationSeconds` 都是最终可执行秒数，必须为正数并精确加总到父级冻结 `clip.durationSeconds`。禁止把它们当作相对权重、只加总到 `speechEvents` 最晚结束秒，或使用另一组同比例但未闭合的数字。宿主不会归一化、缩放或吸收余差，也不会替 writer 修正发声、事件索引与画面的语义错位。
- `shots` 与 `speechEvents` 必须先落在**同一条冻结 Clip 时钟**上：按 shots 的累计真实切点安排每条 `startSeconds/endSeconds`。`on_screen` 人声只能落在已看见该说话人开口、持续表演和被打断动作的真实 shot 窗口内；不得按尚未精确闭合的镜头数字排人声。
- 每个 shot 的动作信息量要与时长相称；判断、反应和结果必须有可读时间。
- 最终渲染提示词必须完整承载冻结事实、因果、连续性与可执行动作；完整 `assetObjectContracts` 由服务端保留在结构化审计合同，provider prompt 只接收真实 `@图N` 令牌和视听语言，不输出对象职责、canonical 映射或机器锁定摘要；运动字段必须进入逐镜正文，禁止用内部合同复读占据模型注意力。
- 最低信息量目标是“最小充分、逐项可执行”，不是固定 Unicode 字数下限，也不得把父任务的创作质量期待误解成机械篇幅指标。优先把预算交给本 clip 真正发生的主体动作相位、空间路径、双方反作用、可见人物状态、台词表演、材料/VFX 生命周期、声场和退出态；事实已完整后立即停止，禁止重复外观、状态标题、资产绑定、同义形容词、摄影器材、质量口号或无动作因果套话。父任务若携带旧 `minimumPromptCharacters`，只把它记录为非阻塞诊断，不得为凑字污染提示词。
- 真实供应商的物理请求边界由执行层按事实校验；它不是 writer 的创作预算，不能借此预先压缩、截断或删除冻结合同。若最小可执行正文与供应商事实边界确实冲突，在 `selfQaNote` 报告 `input_contract_budget_conflict`，由同一执行链依据失败证据修订或显式失败；不得用业务字符串上限替代创作判断。
- 输入中的 `assetObjectContracts` 不可忽略或改写，但 writer 输出必须省略该机器字段，由服务端完整投影；不再维护固定字符预算或 shots 字符目标作为 writer 上限。相同身份、服装、色彩与禁止项不得逐 shot 重复；信息是否完整由当前冻结事实与最低目标自检决定。

## 对白与说话人

- `dialoguePaceRate` 的单位是汉字/秒，不是比例、台词密度或倍速；缺省为 4，物理上限为 6。
- 父任务的 BeatSheet 已分账冻结 `dialogueScript` 与 `narrativeAudioPlan`：前者是原文逐字发声台账，后者是主 agent 对是否需要源事实旁白/内心 VO 的语义裁决。两类 lines 合并后每行都有稳定 `lineId`、canonical `speakerName`、逐字 `text` 和 `delivery`。合并集合为空才表示本 clip 无人声，必须输出 `speakerBindings=[]`、`speechEvents=[]`；无论有无人声，所有 shots 都必须省略 `speechEventIds`。非空时每行必须由一个完整 SpeechEvent 唯一承载，不得只选“关键台词”。
- 合并冻结人声脚本是唯一允许发声的文本。writer 不得新增其外的对白、旁白、OS 或 VO，也不得把 `sourceSpanText` 中的动作、神态、环境、镜头或画面描述临时改写成口播。writer 的 `visualTask/action/framing/lensIntent/composition/cameraMove/lighting/materialResponse/notes/soundPerspective/sound/logline/continuity` 与父级 `exitState` 全部是不可朗读的控制事实；`soundPerspective/sound` 只写听觉视点、环境声和动作声，不放任何人声正文。
- writer 的 `shots[]` 不得包含任何台词、说话人、文本坐标或 `speechEventIds`；每个完整发声窗口只存在于 `clip.speechEvents[]`。宿主只在模型首稿的最终 Shot 时钟上做一次区间联结。writer 的 `visualTask/action/framing/lensIntent/composition/cameraMove/lighting/materialResponse/notes/soundPerspective/sound/logline/continuity` 与父级 `exitState` 都不得复制、引用、转述或释义台词，不得再写“说出/喊出/念出：『台词』”之类带正文的表演说明；画面表演只写开口/闭唇、呼吸、视线、姿态、动作起止和对口型状态。控制字段也不得摘录台词短语作镜头标题或切点，例如把某句中的“随时都行”“摸摸良心”放进 `visualTask/notes/editRhythm`；一律改写为“第一轮划界台词落下”“末轮质问结束”等无正文的结构指代。提交前逐 shot 反查 writer 输出，任何字段都不得残留可发声句子或冻结台词连续词组。
- 每个 SpeechEvent 必须填写简洁的 `performance`，直接从语速、音量、呼吸、停连、重音或潜台词开始。它是不可朗读控制字段，不得重复/转述台词，不得放角色名前缀或模仿具名真人声线。最终 renderer 由 Hono 物化原文，并把对白转为自然视听语言；provider prompt 不暴露 `SpokenText=` 等机器字段。
- `performance` 不承载画面调度：肢体动作、道具动作、站位、机位、焦点转移、可见口型要求、接触结果和剧情事件全部只能进入相应 shot。安排完整 SpeechEvent 后，按冻结 Clip 时钟上的 shot 切点复核：画内发声的起点、持续窗口与打断点必须分别落在真正执行这些可见动作的 shots 内。
- 画内对口型期间，`action/framing/cameraMove` 必须给嘴部足够可读的稳定窗口：避免同时转头、遮脸、大幅面部运动、极端运镜或繁忙手势；台词权重高于环境时，`sound` 只保留底噪与一个关键 SFX，并在发声窗口降低竞争。多说话人同 clip 必须按时间分开回合并保留停顿，不能重叠发声。
- 必须先按台词长度反推每个 SpeechEvent 的独立发声窗口，再安排视觉 shots。逐事件计算非标点字符数并满足 `字符数 <= (endSeconds-startSeconds) × dialoguePaceRate`；标点不占语速容量，但完整 Unicode 区间仍必须覆盖。视觉镜头可以在事件内部切换，不能借切镜伪造额外发声容量。
- 返回唯一 JSON 前必须对每个 SpeechEvent 做最后一次算术复核：使用该完整冻结行的 `去标点字符数 / (endSeconds-startSeconds)`；任何结果大于当前 `dialoguePaceRate` 的事件都必须先扩大事件窗口并重排其它视觉 shot。镜头切换不增加人声容量，也不得迫使一个完整事件按镜头拆句。
- 父任务若给出逐行 `minimumSpeakingSeconds`，每个 `lineId` 的唯一 SpeechEvent 时长不得低于该值；先锁定全部人声事件，再把 `nonDialogueReserveSeconds` 分给纯视觉动作与反应。
- 如果既定合法时长无法容纳合并冻结人声脚本，不得省略、截断或改写任何行。必须在唯一 JSON 的 `selfQaNote` 报告 `input_dialogue_capacity_conflict`，由父级增加合法 clip/时长、重写 narrativeAudioPlan 或按原文顺序重新分配；当前 writer 不提交伪完整稿。
- writer 永远不写 `dialogue`、`dialogueText` 或 `spokenText`；Hono 在收稿后按 `lineId + [startOffset,endOffset)` 从冻结原文物化每个 SpeechEvent 的完整 `spokenText`。
- `speechEventId` 与 `lineId` 是宿主拥有的机器标识，writer 不提交它们。writer 按冻结 spokenScript 的原顺序逐行输出完整事件及文本坐标、发声窗口、说话人与表演；宿主在上下文边界把每个事件绑定到对应原始 lineId 并生成稳定 speechEventId，不从提示词正文猜测绑定。
- 每个 SpeechEvent 的 `speakerName` 必填，并精确命中 `speakerBindings.name`；shots 不得重复声明说话人。
- 所有 shots 均不得声明 `speechEventIds`；宿主根据最终 Shot 时间边界与 `speechEvents` 窗口确定性生成。有无对白都没有 writer 例外。
- `speakerBindings.assetKind=character` 表示真实入画角色；`voice` 表示不入画的声音通道。
- 不从姓名或台词内容猜资产类型；只依据父任务事实和当前镜头设计显式声明。
