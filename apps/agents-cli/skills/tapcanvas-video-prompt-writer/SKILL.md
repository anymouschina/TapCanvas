# Video Prompt Writer

## 完整剧情的声画表达

以本轮用户目标、已读取来源、冻结章节执行稿和真实项目资产为事实依据，把当前 Clip 的剧情写成观众能看懂的声画过程。完整剧情和高忠实度是目标：保留人物身份与关系、世界规则、事件因果、重要选择和结果，让背景与动机得到足够交代。章节作者可以删减不影响理解的细节；单段 writer 不擅自删改已冻结剧情与发声，也不把“简洁”变成压缩剧情的理由。

镜头、表演、剪辑、旁白、心声、闪回、配乐和画面文字都是可选择的表达手段，没有优先级模板。按本轮剧情和用户要求决定如何使用，不要求每镜动作、每句反应、固定快切、人物情绪弧或某种系统形象。

导演判断服务当前故事与用户观看目标。依据真实剧情选择看点、信息揭示、表演、取景与声音；反差、铺垫、反应、静默和持续观察各有适用情境，不要求每项独占一镜，不要求每段另造钩子、高潮或悬念，也不要求重复元素逐次升级。运镜、光与音效可以改变观众的注意和感受，不能新增人物动机、世界规则、能力、情绪拐点或剧情结果。

执行正文写观众看到与听到的过程，取景、动作、光线和声音彼此支持。可以多镜的片段里，一镜只写一个观众能看到的动作、反应或取景变化，用一两句平实的话写清；一个冻结事件通常展开成几个镜头（谁先察觉、谁做了什么、对方怎么反应），一句话可以跨镜接续，不在一镜里写“继而切至”“随后拉开”“紧接转场”这类多次切换。章节稿的事件描述是剧情事实，不是镜头文本，不照抄成一镜。镜头粒度与写法对齐预载范例（30 秒片段约十几个短镜头），镜数仍由内容决定；`single_shot` 时整段只有一镜，按逐 Clip 合同连续调度。三个字段各司其职：`action` 一句平实的可见动作，不写心理（“眸底闪过一丝冷冽”“透出威仪”）和比喻；`camera` 只写景别、机位或运动（如“林嫣儿近景”“门内过肩”），不写人物动作，已点名主体时 `action` 直接从动作写起；`sound` 只写这一镜新出现、听得见的现场声，没有就留空，不把同一环境声逐镜重写。有人开口的镜头，台词与语气由宿主接在后面，`action` 只写说话人此刻的一个动作。改前：camera“林嫣儿与沈清秋双人中景，林嫣儿抬手引向画右”，action“林嫣儿侧身，抬手引向沈清秋，神情有些心虚，说得又快又急，目光不敢多停在顾观棋脸上”；改后：camera“林嫣儿与沈清秋双人中景”，action“林嫣儿侧身，抬手引向沈清秋”。常驻的画风、材质、色调、外貌与陈设由画风行和参考图负责，不在每镜复述；光线或声音的变化本身是戏时，写进发生的那一镜。特效与光效不论这一拍标成什么演出类型，都写成看得见的样子：从哪个部位发出、什么形状和颜色、多大（拿身体或常见物件比）、多亮、怎么动、照亮了周围什么，不写“剑意”“威压”“若隐若现”这类名号、气质词与半开度词。改前：action“姜望周身剑意勃发，剑光若隐若现”；改后：action“姜望拇指推开剑格，一道一指宽的青白光从鞘口窜出半尺，照亮他的下颌”。`scene` 是这一场的短标题，照“第一场：地点，时间，色调”写，需要时接一个站位短分句，约三四十字；换场或回忆用场景字段另起同样的短标题。拍摄理由、判断过程和内部追溯留在实际声明的诊断字段或工作记忆。

表演从人物的态度出发：先读 `wholeFilmIntent` 里人物对这件事、对彼此的态度和章稿 `delivery`，再只在决定这一段意思的那一拍（被戳穿、听到价钱、看到结果）给一个具体反应，比如眉毛一挑、手停在半空、笑意收住；其余镜头让人自然地说和听，不给每句话配一个手势。克制也是态度：“她听着，没接话，只把杯子往自己这边挪了挪”比“她神情复杂”更能演。

必要提议、问题、让步或回应以实际声画交代，不能用“许诺”“解释”等概括或无声手势代替。直接文本交付写出完整发声；结构化产物的冻结引用见下节。上游内容缺失时记录精确来源差异，按已授权路径修订，不擅自改写冻结声音，也不伪称静默动作补回了意思。

保留来源的事实强度与观看视角：回忆、想象、内在体验、传闻、计划、附带条件和已发生的现实事件分别表达。主观可视化不会自动获得现实物理作用，角色判断不升级成客观真相，有限能力与可能结果不扩大成新的能力或确定结局。执行细节可以原创，但不能披着视觉设计的身份改变这些事实。反过来，已标明是想象、设想或幻象的段落，画面本身可以放开规模、力量感与奇观（门后涌出的力量、铺满天空的景象），这正是它被写进来的理由；只要切回现实时现实里的人和物没有因此改变，就不要把想象拍成几道细线、一片暗场的示意图。原文点名的其他作品形象、招式外观与符号不画进画面，用原创设计表达同样的意思，供应商按成片画面做版权审核。

本段承接真实进入态，沿有序事件推进同一人物、场景与道具的当前状态，达到退出态或继续未完过程。离画、换镜或跨 Clip 不重置状态；回场按该故事时点最近成立的状态接续，需要时查已提供的 stateChain，而非只看邻段。状态变化有事实依据，包括修复、清洁、治疗与时间转换；回忆不改写返回后的现在。身份参考图的初态不等于全片当前态。实际参考说明与 scene/shots 一致，不重演已完成内容或提前兑现后来结果；发现作者引入的矛盾直接修稿，上游事实冲突只按已授予权限调整。计划、引用表和自评不能代替实际剧情表达。

## 写给视频模型看的几件事

视频模型只看得懂画面和声音，按这些写：

- **画面里的字要少**：模型写不出成段小字，面板、菜单、信件、欠条一次只让观众看清一两处关键字或一个数字（"余额 -12.50""辞职信"），其余靠台词、心声或系统画外音交代。不要把整张面板的十几行数值写进一个镜头。
- **不写术语，写看到的变化**："Match Cut""判定帧""180 度轴线""黄金分割点"对模型没有意义。要转场，就写观众看到什么：纸角上的火苗变成灶膛里的柴火。
- **前一段做完的，这一段不再演**：上一段已经烧掉的信、已经站起来的人，这一段从结果开始。本段退出态写"准备起身"，就停在准备起身，站起来留给下一段。
- **心声和旁白不抢跑**：只说已经发生或正在画面里发生的事。人刚在水里睁眼，心声不能先说"我把孩子救上了岸"。
- **动作只往一个方向走**：前倾又后仰、抬手又放下、走近又退开这类来回动作，模型常拍成倒放或抽动。一镜里的动作朝一个方向做到结果；做完还有余量，就顺着同一方向延续（门推开，人顺势跨进去），不往回收。`single_shot` 整段只有一镜时更要注意：把本段事件写成首尾相接的几步动作，一步接一步铺满整段，最后一句写清镜头停在什么画面（即本段退出态）；只写一个两秒就做完的动作，剩下的时间模型会自己编动作或让画面僵住。
- **一主一从的接触写清谁在用力**：喂药、掐住、递信、拽人，模型默认画成两人对称地握手或互推。写明主动的一方用哪只手、从哪边握住什么，被动的一方怎么承受（偏头躲开、手被按在桌上动不了）；容易混时直接写"不是两人对握"。
- **三人以上同框时，台词放进单人镜头**：同一画面里有三个或更多人时，模型容易把脸混在一起，或者让说话的人对不上口型。这样的镜头只交代谁站在哪、彼此什么关系（全景或中景）；谁开口，就切到他的单人近景或过肩镜头，一镜只有一个人说话。两人戏不受此限。
- **一句台词只有一张嘴在动**：两人戏也一样。说话的人开口时，其他在画面里的人闭着嘴，或侧脸、背对、在虚焦里听；接话的人等前一句说完、下一镜再开口。说完一句不站桩：给一个说完以后的动作或停住的样子（把茶杯放回桌上、转身看向门口），或者切到听的人。
- **写成画面里已经是这样，不写成修改指令**：写“她穿着红外套”，不写“把外套改成红色”；不用“修改”“替换”“延长”“续写”“去掉”这类词。视频模型会把它们当成编辑或续写任务，去改参考图，而不是拍这场戏。
- **一段的第一镜停在动作刚开始**：第一镜写动作被触发、还没做完的那一刻（手刚碰到门把、人刚要起身），不写已经做完的结果；否则模型会直接从结果开拍，前面的过程就没了。
- **反应排在触发之后**：先有那句话、那一下碰触，下一镜才有反应；反应写在触发前，模型会让人提前变脸。一段话里最要紧的常是听的人：把听者的反应单独给一镜（他把烟按灭了），比让说话的人一直占着画面更有戏。
- **情绪写人做了什么，不写脸上的颜色**：“脸红”“眼眶泛红”“脸色苍白”常被拍成整张脸均匀变色，像加了滤镜。写成动作：她低头把茶杯转了半圈；他喉结动了一下，没接话。
- **人看的东西要拍得到**：写了“他盯着门口”，门口就要在画面里，或者让他侧对镜头看向画外一侧；他看的东西不在画面里，模型常让他直接看镜头。
- **道具由人来动**：写“他的手把信推过桌面”，不写“信滑过桌面”；拿东西的镜头，手在这一镜开头就已经握着它。道具当主语，模型会让它自己动。
- **运镜要有理由**：只在意思变了的那一拍推、拉、跟，并写清从哪一下开始、停在哪里。例：“他说出‘我不知道’时镜头开始推近，停在她咬紧的下颌上。”其余镜头固定机位就好。
- **光写方向，不点灯具**：写“暖光从左边照过来”，不写“落地灯的光”。提到灯具，模型会在画面里画一盏出来，下一段又变了样。
- **结尾停在具体画面**：最后一镜写清停在什么画面上（他的手还按在门把上），不写“淡出”“渐黑”“画面慢慢暗下去”，这会白白耗掉最后一两秒。
- **调性和强度跟本轮事实**：日常戏不加来源没有的法术光效、能量灌体和符文，不把"笑了笑"写成"傲岸霸气"。保留用户明确画风与媒介；只有本轮确认宿主已提供画风时才省略重复表达。

## 唯一结构与真实输入

直接文本交付的声画须完整自含：实际台词、旁白或心声写全文，音色、音乐和画风按用户目标与真实输入表达。未确认存在的 renderer、角色卡或参考图不能代替这些内容；不虚构绑定、图号或资产 URL。

结构化 Workflow 交付由本轮动态 artifact schema 与共享 `tapcanvas-video-authoring-stages` 规定字段、引用和编译职责。本 Skill 的领域参考不定义另一套协议。

`tapcanvas.clip-production-packet/v2` 的 `videoPrompt` 是 `scene` 与有序 `shots`。使用 `storyEventIds` 和 `speechEventIds` 引用本段实际事件；完整冻结发声由 renderer 按引用放到开口处一次，writer 不复制或改写正文进 `action/sound`。供应商合同规定整段执行时长，视频模型适配片内镜头和发声节奏；不从整段秒数推导镜头数或另建每镜、每句时钟。其它产物的字段以其本轮 schema 为准。

该 packet 的 `action` 写可见动作与表演，`camera` 写取景和运动，`sound` 只写现场动作音效与环境声；全章配乐由剪辑统一铺，不在各 Clip 增加背景音乐。真实角色资产的音色由 renderer 放入参考说明，`sound` 不重复嗓音。参考图按人物、场景、色卡排序，色卡仅定色调与光影，不作为画面内容。仅在本轮确认画风由宿主或真实参考承载时省略重复画风；这些分工不适用于缺少相应合同的直接文本。

发声主体由冻结 `speaker/voice` 确定，不由镜头拍到的人决定。`inner` 沿用该角色的声音；独立 `narration` 保持叙述者身份，其稳定音色与本句语气来自章稿 `delivery`，renderer 随完整声音事件物化。纯旁白不需要人物参考图，不让画中角色对口型，也不被主角参考说明里的音色覆盖。跨 Clip 保持同一声源，用户或来源明确指定角色自述时才沿用该角色音色。发现第三人称叙述被错归角色心声等上游矛盾，向已授权的章级修订路径交回具体事件及来源差异，不在 sound 偷换 speaker、复制台词或追加相冲突的声音要求。文字音色指令不等于已绑定真实音频，不能据配音卡占位或名称声称已锁声纹。

一键成片的图片输入合同使用真实首帧/首尾帧或多图参考，不引用上一 Clip 视频。按冻结边界与图片资产承接；有图片引用的 `reference_to_video` 不代表视频参考。其它任务的输入能力服从本轮真实生成合同。

真实参考绑定承载身份与外观，剧情需要的位置、持物、进出和变化仍由作者写清。画外发声不自动变成可见人物，未入镜不等于离场；不要从机器 ID、节点标题或样例猜人物、剧情或资产 URL。

仅使用本轮实际授予的读取工具与精确回执，不越权读写画布、创建资产、提交媒体或重跑作品。保留原文引用、来源身份、权限、真实资产和供应商确定性边界；已有受理任务与成功资产不得因后续创作判断被覆盖或丢弃。
