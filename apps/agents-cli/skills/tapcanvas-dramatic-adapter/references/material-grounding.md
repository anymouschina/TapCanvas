# 创作素材的观察、选择与引用

本协议用于所有依据用户素材创作的 BeatSheet，不依赖题材、模型、图片数量或文件名。

## 先确定事实来源

`selectedAssetIds` 只记录显式勾选或提交的素材 ID。空数组不表示用户没有素材，也不撤销 UserIntentContract 中“使用当前画布素材”的要求。`projectAssetCandidates` 是冻结作用域内真实可用的图片；`mediaKind` 表示媒体类型，`kind` 表示素材库分类。普通上传图片可以同时是 `kind=text`、`mediaKind=image`，不能因此当作纯文本跳过。

由当前 Agent 把用户的素材范围要求与候选的 `flowId/nodeId/assetId` 对齐。用户指定当前画布时，从当前 canvasId 的候选确定任务对象；用户指定部分对象时依据真实观察选择对应项。项目中无关素材不自动变成必用输入。禁止把空勾选当作自由替换授权，禁止要求用户重复勾选本已明确要求使用的素材。

## 观察先于素材内容判断

候选的 `analysisEvidence` 是带 provenance 的既有观察；`analysisDiagnostics` 是读取状态，不是图片内容。先复用与当前问题相关的成功观察，保留图片身份与问题来源。只有文件名、ID、类型或就绪状态时，尚不知道图片内容。此时由 Agent 按所需信息调用已授权的 `tapcanvas_analyze_image({assetId})` 或当前画布的 `{nodeId}`，同一问题成功结果复用，不重复付费分析。缺少工具或分析失败时记录具体证据缺口，在同一链内处理仍可完成的部分，不以知识案例、文件名或模板商品替代真实观察。

观察必须区分可见事实、模型推断与未知事实。外观、结构、可读标签可以支持对应描述；材质成分、性能、认证或耐用性不能从外观擅自确定。创作话术可以原创，事实性卖点必须有用户事实或真实观察依据。无法确认的材质与性能保持未知，改用可证实的视觉特点组织表达，不补“抗摔”等任意演示。

知识与案例只提供表达方法。案例中的人物、商品、台词、场景与效果不是用户的对象，不能因为案例完整就取代用户素材。必须先确定真实对象，再选择有帮助的方法。

## 将选择写成可执行引用

按观察归并对象，在根级 objectRegistry 中用精确 `referenceAssetIds` 绑定原素材，保持多视角引用的顺序；同一对象多张图不等于多个对象，多种对象也不能合并成“产品”。已选用的素材不只写在说明里，必须进入实际参与它的 beat.objectStates 所引用的对象。只为原素材缺少且本轮确实需要的视觉对象新增资产计划；新增主持人或场景不能挤掉原商品引用。

提交前在当前 Agent 内核对完整用户目标：实际选用了哪些原素材、每个对象依据什么观察、在哪些 beat 出现、绑定是否仍是原 ID，未使用的候选为什么与任务无关。发现用了案例对象、泛称占位对象或遗漏用户范围时，修订当前 BeatSheet。该自检属于创作责任，不新增宿主语义评分、必读数量或阻塞闸门，也不允许本地代码替 Agent 决定素材意义。

## 跨段保持同一对象与演示过程

需要保持可辨认外观的对象在整片共用同一个 objectId、精确原图引用与 identityInvariant；商品的轮廓、结构、颜色、标签及可证实细节与人物身份同样需要连续。每段 objectStates 引用该对象并承接上一段 endState；改变的是展示角度、操作步骤或已发生的结果，不能在下一段换成另一种商品或重置演示。用章级事件与逐字口播共同推进同一展示过程，不让单 clip writer 各自定义商品、材质或卖点。

referenceRole 是明确的视觉依赖声明，任何非 none 职责在引用尚未物化时仍会进入资产编排。只做文字描述而无需视觉参考时明确选 none。商品原图已经可用时绑定原始 ID，由执行器复用；不能另造相似商品图替代。assetPlans 的对象职责必须与 registry 中的对象身份精确一致，不能一处叫“产品”、另一处叫“带货产品”。这一协议也适用于其它需要连续性的物件，不由宿主关键词推断身份。


## 同一项目的跨章节资产复用

章节切换不重置人物、道具与场景身份。规划新章节时先盘点 projectAssetCandidates 中其它章节已就绪资产，依据对象事实、既有分析与当前故事状态决定复用；selectedAssetIds 为空不能跳过这一步。跨章身份不能因为本章改用另一个显示名或新建 physicalIdentityKey 而重新生图。确认是同一对象且状态适用后，在 objectRegistry.referenceAssetIds 写入已存在的精确 ID；不要只把旧图当作新生图的文字灵感。候选存在多版本时依据真实观察、来源和本次要求选择，不能按名字相同、列表位置或日期单独猜选。确有状态变化或新对象时才规划新增资产，并保留旧资产。

先完成上述复用选择，再填写 assetPlans。逐项核对所有被 beats 消费且 referenceRole 非 none 的对象：已有精确引用的直接复用；缺真实引用的必须有对应生成计划。一次列齐缺口并在当前作者轮修订，不能每次只补一个角色后反复重写整章。角色、场景、道具、特效遵守同一规则；不要遗漏新出现的场景或特效。


## 全局身份与逐段素材分配

先从真实观察区分“同一对象的不同视角”“同一人物的不同服装或状态”“不同人物或商品”。不能把一批素材按上传顺序机械平均分组，也不能因为一起上传就合并为同一泛称主体。人物身份不变不代表服装状态相同：按本段需要锁定的身份、服装与姿态选择适用图，在 objectStates 的状态正文说明变化；不把多套互斥服装当作同一时刻的身份不变量。

根级 objectRegistry 保存对象可用的全部引用；每个 beat.objectStates 必须显式填写 referenceAssetIds/referenceImageNodeIds，选择该对象当前段真正需要的有序子集。整片覆盖用户指定素材，通过分段表达完成，不通过把全集复制到每段完成。选择考虑本段实际可见内容、要展示的细节、信息增量和跨段接力；同一参考可在多个相关片段复用，但每次都应服务该片段的画面。已有来源图的对象不能以空选择要求重新生成替身。新增对象没有已有引用时两个数组均为空，仍沿原资产计划准备。

在父作者内把逐段故事、引用和物理容量一起检查：总引用包含当前段的输入图、人物、场景、道具和其他实际依赖，不能只数用户上传图；使用宿主提供的真实模型上限，不把供应商最大值当作创作目标。多张图各自应提供什么本段必要信息？是否存在服装或对象互斥？有没有把另一个段落的图附进来？若超过容量，在原用户总时长与合法片段时长内重规划信息分配、删去自行增加而不必要的参考依赖或调整本段选图，不截断 ID 数组，不让 writer 在冻结后临时挑图，不要求用户重试。方法属于作者同链责任，不增加语义评分或强制图片数量。
