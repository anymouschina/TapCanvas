# 章级戏剧弧审查协议

## 为什么逐拍合格仍会平

逐拍都有目标、阻碍和变化，只能证明每个零件存在。整章是否有效，取决于相邻 beat 是否形成符合用户意图的比较关系：压力有没有改变约束，信息有没有推翻判断，兑现有没有被前拍偷走，以及动作或情绪结果是否被看见。余波、悬念和未解问题只有在用户或权威来源明确需要时才检查；它们不是每个视频的默认交付物。

审查时不要给整章打一个张力分，也不要逐项回答“是/否”。先把全部 beat 放在同一张比较表里，再按以下顺序修订。内部审查表只服务本轮推理，不进入 BeatSheet 协议，也不写入 Hono。

## 第一步：锁定观看承诺

用以下事实重述章级 `dramaticThesis`；最后两项仅在用户或权威来源明确要求连续叙事牵引时加入：

```text
焦点人物现在想要什么
哪股压力持续阻止他
本章哪次选择不可撤回
主要兑现改写了什么权力/认知/关系
兑现后留下什么可见结果、情绪或行动后果
（可选）兑现后留下什么明确的后续牵引或未解问题
```

这六句必须能回到原文事实或必要物理结果。若主要兑现只能靠新增前史、关系含义或未来计划成立，先降级为不确定压力，再重构，不得把推断升级为事实。

## 第二步：建立 Beat 功能带

逐 beat 写一行内部审查记录：

```text
clipIndex
dominantFunction: pressure | evidence | choice | payoff | aftermath | hook
newConstraint: 本拍新增或改变的限制
valueTurn: 开拍到结束，控制权/知识/关系/风险如何改变
debtMovement: 哪个 debtId 被 plant/carry/escalate/resolve/abandon
emotionAction: 情绪怎样改变行动
handoff: 下一拍必须接住什么
```

`dominantFunction` 在当前 BeatSheet v12 中会以非空短事实写入每个 beat，供相邻 Clip 共享同一章级方向；这里的 `pressure | evidence | choice | payoff | aftermath | hook` 仅是 Agent 内部比较视角，不是运行时枚举、关键词分类或固定题材模板。一拍可以包含多个成分，但必须有一个主功能；服务端只验证字段存在，不解释其语义。

同时把每拍时长放在同一条注意力带上比较：时长必须服务 `chapterArc.protagonistThroughline` 与 `chapterArc.primaryPayoff`，不能按原文段落长度平均分配。焦点人物暂不在场的连续铺垫若没有改变其后续处境、观众解释或兑现条件，应压缩为同一功能带；被压缩的来源事实仍由 `storyEvents` 与来源账本完整守恒。主角选择、主要兑现与最小余波若因铺垫过长而被挤到尾端，则即使每拍单独可看，也必须重做整章时长分配。

相邻两拍若主功能相同，且后一拍没有新增约束、推翻判断、不可撤回选择、债务推进或余波，就属于重复功能。优先合并或删除；不要通过增加运镜、台词、特效或表情把重复内容伪装成新 beat。

## 第三步：验证递增不是重复加码

逐相邻拍比较：

- 压力拍必须改变约束的种类或人物可用策略；只把同一种威胁写得更大更响，不算递增。
- 证据拍必须改变角色或观众的解释；只补充同方向说明，不算新信息。
- 选择拍必须关闭一条退路、消耗资源、暴露立场或承担风险；可随时撤回的动作不算选择。
- `carry/escalate` 必须让债务的到期条件、代价或观众预期发生变化；只换措辞复述 setupDebt 是空转。
- 情绪变化必须改变下一拍的时机、路线、力度、关系或愿付代价；只改变表情强度是轮播。

另用六条可查差异项交叉核对：谁掌握的**筹码**变了、谁知道的事实变了、哪条**关系边界**变了、哪条**退路**消失了、谁作出了**不可撤回的决定**、哪个后果**从威胁变成现实**。两拍主功能相同又指不出这六条中的任何一项时，后一拍只是复述，修法是删并或换向量抬阈值——不是换一件与核心矛盾弱相关的新靶心（那会切断观众追的线），也不是把同一威胁写得更响。

递增不能靠改写事实的语义强度制造。身份或归属误认不能自动升级成偷窃、欺骗、背叛或罪责；“不断示意”“持续沉默”“多次尝试”也不能自动升级成更用力、更愤怒或更敌对。只比较源事实支持的次数、位置、可见痕迹、可用策略和后果。

若相邻拍没有形成上述任一差异，先做删并。平庸小说的紧凑感主要来自取消无变化时间，而不是缩短所有镜头。

## 第四步：保护主要兑现的峰值占位

全章只选择一个 `principalPayoff` 作为主要兑现；其他兑现可以存在，但必须服务它、改变它的条件，或成为其余波。

检查：

1. 主要兑现之前是否已把结果完整说出、演出或用旁白解释？有则前拍只保留可回看证据和压力，不提前关闭债务。
2. `eligibleFromClipIndex` 是否真的保护了最早兑现位置，而不只是字段正确？
   - 该索引必须指向本章真实存在的 beat。跨章未决债务在末拍保持未关闭，并用当前末拍作为最早允许位置；不得用本章不存在的下一索引冒充下一章坐标。
3. 兑现是否同时具备 anticipation、impact、reaction 三个可感知阶段？可分布在相邻 beat，但不能只有结果公告。
4. `visibleConsequence` 是否改变控制权、知识、关系、目标或风险？若局面不变，只是展示。
5. `reactionCarrier` 是否承担了认知或行动改变？固定“震惊脸”而后继续原计划，不构成反应。

峰值不是音量最大的一拍，而是既有期待发生最不可逆改写的一拍。克制情绪、悬疑物证、喜剧误会和反高潮同样适用。

## 第五步：保留兑现后的后果（按意图选择是否延展）

主要兑现后至少要有一个与用户目标相符的可感知后果通道：人物改变下一步动作、关系重新定位、资源被永久消耗、空间/权力状态改变，或动作本身继续产生可见物理反馈。只有在用户或权威来源要求余波、悬念或后续牵引时，才延展成新的压力；用户要求持续动作或明确收束时，当前结果可以直接成为出口，不得为了“余波”额外添加静止、解释或问题。

余波不等于拖长收尾。需要余波时，它只需让 impact 产生意义；不需要余波时，直接结束在已发生的结果或持续动作上。以下情况仅在本轮明确要求余波时算余波丢失：

- 爆发后直接跳到无关信息。
- 反应者出现但没有改变判断或行动。
- 人物下一拍恢复原策略、原情绪、原资源状态。
- 兑现后继续重复同一胜利或解释，稀释峰值。

## 第六步：检验结尾形态（仅按用户意图）

只有当用户或权威来源要求悬念/后续牵引时，最后一拍才需要让开场问题发生升级、转向或代价化：

```text
开场问题 -> 本章得到的部分答案 -> 答案制造的更具体问题
```

合格钩子是观众已经理解、但尚未看到结果的具体风险、选择、关系或证据。以下不是钩子：

- “新的冒险即将开始”。
- 突然出现与本章无因果关系的新敌人或异象。
- 主要兑现之后的日常收拾、重复庆祝或总结旁白。
- 只藏信息却不改变任何人的下一步行动。

需要钩子时，钩子落下后立即结束；若用户要求持续高能或明确闭合，则以正在发生的动作或已兑现的可见结果结束，不制造未解问题。

## 第七步：沉浸式电影验收

在通过前六步后，做一次不看 prompt 文案的“观众体验复述”：

1. 只看每拍的画面任务、人物动作、对白、声音和状态变化，能否说出本拍发生了什么以及为什么发生？
2. 重要世界背景、任务规则和内心判断是否有可见载体，而不是被一段旁白快速念过？
3. 大场面是否先给出地理关系、尺度和人物站位，再进入近景情绪与动作细节？
4. 每个重要情绪是否经过“触发 → 克制/泄漏 → 选择 → 关系或行动后果”，而不是从平静直接跳到激动或从危险直接恢复平静？
5. 运镜是否改变观众的知识、距离或情绪位置？如果把相机运动删掉，主体仍完全静止，则运镜没有叙事职责。
6. 动作是否能在脑中画出起点、路径、接触和终点？如果只能复述“他跃起”“他递出”“他看向远方”，动作合同仍不合格。

任一问题答案是否定时，问题属于章级改编或镜头合同，不得交给模型生成阶段自行猜测。

## 修订优先级

发现问题时按成本和事实风险从低到高修：

1. 删除或合并没有新增局面的重复 beat。
2. 在不改变事实顺序约束的前提下，重排观众看见原因、反应和结果的顺序。
3. 把原文已有的犹豫、资源使用或关系表态落实为不可撤回选择。
4. 收回提前解释，保护主要兑现的占位。
5. 用原文已有反应、必要物理结果或下一步行动补足 impact 后的余波。
6. 只有因果无法读懂时才补最小连接动作；不得新增剧情线、前史、关系事实或未来计划。

每次修订后重新生成完整 BeatSheet 草案并从第一步复核。不要把章级问题留给单 clip writer，也不要为了通过审查而增加固定镜数、固定反转或统一爽文波形。

## 通过条件

只有以下与本轮意图相关的事实同时成立才进入资产规划：

- 六句观看承诺能由源事实支持。
- 每个 beat 都有唯一主功能，重复功能已经删并或产生了新的真实局面。
- 压力、证据、选择、债务与情绪至少沿一条因果链递增，而非同强度轮播。
- 主要兑现没有被提前偷走，并留下与用户目标相符的可见后果；若用户要求余波，再保留行动余波。
- 若用户要求悬念，最后一拍把本章答案转化为更具体的未解问题；若用户未要求悬念，不得凭空添加问题。

这只是生产前的语义自审，不是作品质量证明。真实效果仍由 frozen writer artifacts、最终视频 AI 诊断、用户反馈和跨 run 结果验证。
