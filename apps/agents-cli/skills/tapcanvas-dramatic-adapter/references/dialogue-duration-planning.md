# 对白与反应时间预算

## 适用位置

本协议只用于章级 BeatSheet 切分前的时长规划。它把“这段话能否真实说完”变成可追溯的生产事实，不替代戏剧判断，不是用户级质量闸门，也不规定整章总时长、固定 Clip 数或固定 15 秒模板。

## 预算步骤

1. 从已完成的章级发声台账逐行读取逐字 `text`。只统计真实会发声的中文、英文单词和数字；动作、镜头说明、环境描述、标点与空白不计入发声字符。
2. Agent 根据说话情境为每个 beat 提交正数 `dialoguePaceRate`。常态中文对白通常落在 3.5–5 字/秒；超过 5 只适用于来源或改编合同明确支持的短促快语、急喊或爆发，不得用虚报高速来塞入更多正文。服务端只验证数值和物理上限，不根据形容词猜语速。
3. 每行最低发声时间按 `可发声字符 ÷ dialoguePaceRate` 计算，并向上取到 0.5 秒。多行必须逐行取整后相加，不能先合并总字数抹掉换气和换人边界。
4. 在发声时间之外，按真实表演需要保留标点停顿、换人间隔和关键反应：逗号约 0.1–0.2 秒，句号约 0.3–0.4 秒，省略或未尽语气约 0.4–0.6 秒；金句或关系变化后的反应通常需要 0.3–0.8 秒。这些是 Agent 的创作预算，不新增 Hono 关键词规则。
5. 若台词、动作、反应和环境反馈不能同时落入当前供应商时长档位，`full_chapter` 必须保持原文发声台账不变，通过增加合法 beat、移动完整语句、按下述连续发声协议跨 Clip 分配或选择更长档位解决；`bounded_duration` 只有在用户明确授权的来源裁决下才能删并。
6. 一条 SpeechEvent 可以跨多个镜头。超过约 24 个可发声字符时，优先让摄影在同一句内部切换动作、反应或尺度，不得据此切断、重复或改写发声正文。

## 与现有权威合同的映射

- `delivery_scope_and_duration`：完整章节总时长由真实 beats 相加产生，不由供应商单段上限反推。
- `dialogue_and_voice_performance`：语速、停顿、换气和反应来自角色表演判断，正文守恒。
- `shot_information_task`：摄影可以在同一 SpeechEvent 内切换，但每镜只承担一个可读信息变化。

## 边界与反模式

- 不把 15 秒、固定镜数、R2 高燃或任何题材模板当成默认值。
- 不把评分、最低信息密度或“过关/不过关”投影为用户级终态。
- 不读取静态供应商表，不自动换模型、降低规格或静默删句。
- 不把“快嘴、低语、愤怒”等文本交给本地关键词表推导数值；表演语义由 Agent 决定，运行时只验证其结构事实。

## 长话轮跨物理片段，来源正文守恒

一条原文话轮可能长于供应商单次上限。不能要求整条话轮必须塞入一个 Clip，也不能把不同人之间的问答拼成一条独白。先按原文顺序保留话轮，再由章级 Agent 在自然呼吸、分句或反应处将长话轮分成连续的逐字片段。各片段使用可追溯的稳定 lineId（如同一源行的不同 part），保留说话人、标点和顺序，逐段拼接必须还原原始话轮；不添加省略号，不删中间句，不把别人插话前后的文字跨越拼合。该拆分是发声执行窗口拆分，不是剧情删并。

每个片段进入其所属 clipIndex 的 speechLedger，writer 原样消费该片段并在本 Clip 中安排 SpeechEvent。相邻 Clip 的声音、表演与状态交接由父计划安排，不让下一段重复上一段开场或再次念完整话轮。没有新信息的真实通勤时间可以省略，但人物判断、因果解释、喜剧铺垫和关系转折必须有对应的视听过程。

先估整条发声所需时间，再分配合法窗口；不要先定片段数量后抬高 dialoguePaceRate。语速是表演判断，不能为消除算术诊断而修改。若用户的明确整体上限与完整内容冲突，在同链中如实保留冲突与合法方案，不能把预算估计误写成删减授权。
