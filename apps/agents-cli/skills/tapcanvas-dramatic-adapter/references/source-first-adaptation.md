# 从来源盘点到可演出的章节

本方法属于父级改编 Agent，补充 `delivery_scope_and_duration`、`dialogue_and_voice_performance` 与 `audience_narrative_legibility`。不改变输出 schema，不给 Hono/Web 增加语义闸门。原始用户范围与本轮冻结来源是依据；已生成草稿和草稿自己的账本都不是独立来源。

## 先盘点，后决定片段数

改编已有叙事时，先暂不分配 clipIndex 和供应商时间窗，按来源顺序完整读到末尾。在当前创作上下文中形成两份事实清单：逐字发声，以及事件、思考、规则揭示与关系变化。每项保留能回到原文的短定位片段。先区分人物实际说出、明确心声、消息与非发声叙述，再决定其视听表达；不得通过引号计数、段落数或关键词替代语义判断。

来源发声清单是摘录，不是台词润色。原文的两次发声分别保留，不把它们合成一句概述；不把原文长句改成短句后仍称为 verbatim。对白账本可以完整而字段紧凑：省去重复解释与派生字段，不能省去实际台词。当前运行时将它序列化为唯一 `sourceCoveragePlan.speechLedger`，随后才为每行分配 clipIndex。

来源清单也包含原文已经写明的自言自语、内心独白和消息文本，不能只摘两个人面对面说的话。是否动嘴与是否保留原文是两个问题：保留原句并按情境选择 `on_screen/off_screen/voice_over`，不要因为人物独处就宣称“本段原文无台词”。完整改编中的有词心声与实际对白具有相同的来源身份；只有本轮明确允许删并或要求无声时，才另作表达裁决。

创意改编允许在授权范围内增强表达，但新增表达写入 `narrativeAudioPlan`，不能反向污染来源账本。完整章节与限时改编分开处理：只有用户明确授权删并的范围可以做删并裁决。原创简报没有原文对白时保留空来源台账，直接创作真实需要的人声，不制造来源。

## 用实际表演推导时间

依据完整清单，先安排人物如何获得信息、作出判断、回应对方、改变行动，再计算这些话轮和动作所需的时间。来源中不同的质问、回避、追问、解释和让步各有作用，不因为都发生在同一场景便合成一句总结。世界规则需要让观众看懂其如何改变人物处境，不能只保留规则名称。

按对白与反应预算方法分配时间，再切成动态模型支持的窗口。同一场连续对话可以占多个 clip；一个叙事功能可以跨多个技术窗口，不要求每个窗口重新建立、冲突、兑现和收尾。完整章节容量不足时保留清单，增加窗口或选用已经授权的较长档位；不从旧 run、示例长度、最大片段数或输出 token 成本反推删减。用户要求的容错时间属于可用表演时间的扣除项，先留出再排对白与关键动作，不借容错压缩来源。

## 从原文反查草稿，而不是草稿自证

首稿后再沿原文从头到尾检查每项来源事实实际落在何处。先看来源，后找草稿中的承载；不要只顺着已有 beats 阅读，否则未写出的内容永远不会出现为问题。

逐项问：观众实际看见或听见了什么？人物为什么作出下一步选择？原文中的问题和回答、发现和反应、规则和后果是否仍然成对存在？片段标题、sourceSpan 或一条概括性 storyEvent 不等于已经演出了这些内容。发现遗漏，回到父级完整草稿修订相应事件、对白分配和窗口边界，再按序重算关联状态；不能要求单 clip writer 自己补救冻结计划。

尤其区分可观察动作与人物心里的命题。揉额头能表现不适，不能独自说明记忆归属；看余额能表现拮据，不能独自说明某项开支为何无法负担；看排名能表现关注成绩，不能独自说明排名如何决定待遇。若这些事实改变后续选择，需要用来源心声、人物交流或实际发生的视听事件让观众获得信息。写在 `irreversibleResult` 或创作意图里的解释不是成片内容，不应据此把该段判为 `visual_only`。

最后做两个方向的核对：从来源找承载，确认没有用摘要替代必要表达；从草稿找来源，确认创意新增与原文发声没有混淆。检查中找到的具体遗漏与修订依据保留在本轮可用的创作诊断或工作记录中；最终 JSON 仍只输出当前协议字段，不追加自评通过声明、评分或另一套审查表。该检查用于 Agent 当前链内修订，不把语义判断变成用户级 blocked/failed，也不影响已生成资产。
