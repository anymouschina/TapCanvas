# 资产计划的可执行提示词：过审边界与写法

本文件只回答一件事：**`assetPlans[].prompt` 写成什么样，才能既表达设计意图、又不会被图片供应商的内容安全系统拒绝。**

## 供应商拒绝是硬边界，不是可以绕过的障碍

图片供应商会对提示词做内容安全审核。被拒时返回的是明确的供应商错误（例如 `Your prompt or input was rejected by the content safety system.`），
这一条属于供应商硬上限：**如实记录该子任务的错误，不换模型、不改写后原样重试、不把拒绝说成成功**。
被拒的资产不会产出，依赖它的下游节点会在自己的边界上显式失败——所以**首稿就要写成能过审的写法**，不要指望事后补救。

## 身份板提示词描述的是设计，不是主体的年龄或身体

角色身份板（四视图）要固定的是**可复现的视觉设计**：脸型与五官特征、发型与发色、服装形制与材质、配色与配饰、气质。
年龄、身材、身体状况属于**故事事实**，用来推导设计（例如"少年感"→ 清瘦脸型与校服形制），但**不写进可执行图片提示词**。

**未成年人角色尤其如此**：不得在图片提示词里写明确年龄数字，不得写身材、贴身衣物、腿部或袜装细节，不得强调身体曲线。
这些措辞与"未成年人 + 全身多视图"叠加时会直接触发内容安全拒绝；而它们对设计本身没有信息增益——
写清脸、发、制服形制与材质已经足够锁住身份。

写"少年感 / 学生制服形制 / 中性背景四视图"是安全的；写"16 岁 + 及膝袜 + 全身背面视图"是会被拒的。

## 可执行的写法

- 主体用**设计与身份**描述：`<性别气质>少年/少女 + 脸型五官特征 + 发型发色 + 服装形制与材质 + 配色`
- 视图要求保持中性：`标准正面脸部特写、侧面脸部、正面全身、背面全身四视图`（全身视图本身没问题，问题在叠加了身体/年龄指向的措辞）
- 背景固定为中性纯净背景，`漫射柔光`、`真实织物与发丝细节`
- 排除项写**设计漂移**：换发色、换服装形制、夸张表情、畸形肢体、多余人物、模糊变形
- 不要把剧情中的表演、情绪、姿势、动作写进身份板——那些属于 BeatSheet 的镜头，不属于身份卡

## 与其它合同的关系

本文件只约束**可执行图片提示词的措辞边界**。身份锚点、状态版本、四视图结构、模型与规格选择仍按 `tapcanvas-character-card` 与运行时合同执行；
本文件不新增校验、不改变任何结构字段，也不判断创作质量。
