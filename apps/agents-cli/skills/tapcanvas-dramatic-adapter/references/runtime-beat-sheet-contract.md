# 运行时紧凑 BeatSheet 合同

本资源随 `tapcanvas-dramatic-adapter` 的渐进骨架自动注入，供一键成片的章级 BeatSheet 原子节点直接执行。上下文已经包含完整权威来源、动态生成合同和版本化 JSON 合同；信息充分时直接完成创作、自检并提交，不再调用 Skill 重读本资源或主文档。只有当前来源出现本资源没有覆盖的专业方法缺口时，才精确补读一个必要 section。

## 权威输入与范围

- `delivery-contract.canvasFacts.authoritativeSources` 保留正文或创作简报的来源身份；逐项服从 `sourceId/content/sourceFingerprint`。用户基于真实素材要求原创时，结合同次冻结的用户目标、projectAssetCandidates 和带 provenance 的媒体观察确定对象与可证实的事实；没有现成剧情不代表可以忽略图片。素材使用遵循已自动加载的 material-grounding.md；不从 Skill 示例、历史会话、资产名或机器 ID 补事实。
- `delivery-contract.sourceProfile` 是宿主从 canonical 原文确定性推导的人声容量事实：`sourceSpeechUnits[]`（逐字原文人声段落）、`sourceSpeechChars`、`minimumPlannedSeconds`、`minimumClipCount`、`speechMaxCharsPerSecond`。直接按它规划整章 Clip 数；不要自行把估算上界、旧 run 结果或单 Clip 上限当成压缩目标。宿主会在提交时按同一份事实校验，`sourceProfile` 缺失时才由本 Agent 自行盘点。
- `scope=full_chapter` 且用户没有指定总时长时，完整保留人物、事件因果、明确人声、关键物件和不可逆结果；章节钩子只有用户或权威来源明确要求时才保留。供应商单 Clip 上限不是整章总时长，不得据此把整章压成一段摘要。宿主按提交 schema、原文逐字人声、原文人声覆盖与物理时长容量四项确定性校验本产物；任一项不满足会把可执行原因回灌到本节点继续修订，而不是交给用户重试。
- `generationContract.durationOptions` 是每个物理 Clip 的合法时长集合，`maxDurationSeconds` 是硬上限。没有冻结 `providerSubmissionTopology` 时，由 Agent 根据完整来源的因果、动作相位、对白容量和转场边界决定 Clip 数量；每段时长必须属于合法集合且不超过硬上限。
- 若存在冻结 `providerSubmissionTopology`，严格采用其数量、顺序和逐段时长，不再做第二套语义拓扑。

## 同链创作

`expandedSourceDraft` 是可修订的上游创作稿，不是用户已经确认的事件来源。先将它与父用户目标、权威来源和观看用途对照；草稿自行加入的收势、变身、片名或悬念不能因为写进草稿就变成必须保留的来源义务。发现冲突时，在本父作者权限内修改实际事件，再冻结 BeatSheet，不只在 rationale 中声称遵守偏好。真正的用户事实、明确对白与已确认结果仍须保留。

可修订不等于可无声摘要化。先独立通读完整草稿，找到实现用户目标的具体互动、反应、信息变化与段落亮点，再与最终全部 storyEvents 对照。删去或合并互动时，检查它承担的因果与观看作用由什么实际事件接替；不能把对方应对、迫使变招、借势位移和再次交互缩成“一击结束”，却把省出的时间分给没有新增作用的展示。没有承载的内容由本作者重编正文；草稿与用户目标冲突的内容可以舍弃，不把草稿自动升级为权威。sourceBeatLedger 继续只记录对应来源义务，不能从最终短版反向生成账本掩盖遗漏，也不新造必填质量字段。

命中造成的持续后果属于剧情状态，不能压缩成“火花四溅”或“受击后退”。将已创作的伤况、衣甲破损、武器损伤及行动限制保留在对应事件的实际动作和退出态中，后续事件继承并使用它们形成变招或弱点。参考资产锁定角色与装备身份，不把参考图的完好外观当作切镜后自动修复依据；没有恢复事件便继续保留损伤。血迹、破损或疼痛表情本身不证明伤害成立，还要有命中位置、受力响应与后续行动的因果联系。这些内容由本作者在既有用户/来源边界内修订，不新增宿主质量校验或伤害配额。

位移事件先保留来源明确的运动机制、身体相位与路径变化，再补足必要支撑。翻滚、跨步、攀爬、腾跃、上升后俯冲、受击制动和主动滑行不是可互换的速度修饰；相同起终点不代表同一动作。以来源的短原句为依据，核对谁主动或被动移动、哪一段姿态改变、经过哪些方向变化、如何接触或离开承托面。没有明确左右脚时不为填账编造，但正文必须让实际支撑转换可见。原文的滚转恢复不能为了火星换成长距离拖脚，空间折返不能为了跟拍改成横向平移；这些替换会改变表演本身。

先解释推进，再写效果。材料摩擦通常消耗既有速度，不自动提供加速；火花、衣摆、烟尘、镜头平移不证明身体做了动作。新创动作由主体目标、空间材质与已建立能力决定，不把“持续运动”“有重量”固定实现为低姿滑移、每击刹车或反复借力。合法滑行、滑冰、御空和悬浮按来源或本轮授权保持其机制，不以反滑步为由强制改成跑步或补地面支撑。动作质感来自可辨认的身体相位及因果，不能只加速度词。

冻结前分别核对来源与草稿，不能把草稿用作来源账本的证据。`sourceBeatLedger.summary` 只概括原文明确事实，保留动作机制和顺序；作者新增的距离、姿态、破坏或走位留在可修订的 `storyEvents`，不回填摘要冒充原文。按“原文短句 → 当前事件 → 新增细节及理由”在当前上下文比较；最终仍只提交现有 schema。发现表演被替换，先恢复来源机制并重写实际事件，再同步关键帧、对象状态和序列转场，不能只修一项摘要或附一句遵守原文。

来源内的正向动作与禁止项矛盾时，先区分用户本轮修正、授权范围、既定剧情结果和可调整的表现方式。较新的明确指令优先；在已授权创作范围内，保留剧情作用与结果，改掉冲突的表现方式，并使事件、终态和转场采用同一决定。确实无法推导的取舍记录为未决事实，不把互斥命令同时冻结，也不把不确定的原句默认解释成对全片的许可。该语义工作属于本作者同链修订，不新增宿主禁词检测、质量闸门或媒体重生成。

冻结每个事件的时窗时，按完整主体表演与用户节奏分配，而不是把物理 Clip 的剩余时长填给转换特效或收式。拟物能量在发生的事件里必须有对象、路径和作用，摄影与特效让该变化可辨认；不把“形态逐渐出现”默认等同于冲突升级。需要音乐或声音节奏时，在现有事件文本写出声音与行动的先后、重音、抽空和跨段延续，不能只放在 narrativeAudioPlan.rationale 中宣称配乐存在。Writer 应能据事件把这些事实编入 shots.sound，不能靠模型自行猜整段配乐。

在分配物理片段之前回放整段表演：逐次交互包含行动者、肢体/持物、路径、接触或避让、对方选择和受力后的新位置。空中双方仍要保持可重建的相对距离、支撑/外力与接触关系；环境破坏、飞行和特效不能代替双方动作。概括的“缠斗、连招、对冲”尚不足以冻结为多秒事件，应在本节点补成有序可演过程，再决定时间。先按实际动作和用户密度安排时长，不能从固定等长格子倒推内容。

相邻 Clip 的边界由同一父作者成对设计，具体落在现有 `storyEvents/exitState/startKeyframe/endKeyframe/objectStates` 和 `sequenceControlPlan` 中：切前可见主体在何处、持什么、向哪边移动或仍接触什么；切后首先可见的主体怎样继续这一次动作；共同场景锚、光向与跨切点声音怎样保留或有意变化。`transitionToNext/transitionFromPrevious` 描述同一切点的两侧，不各自发明一段过渡。白光或烟雾不是主体状态，不能作为唯一交接信息；重放同一爆炸也不能证明连续。不要为交接另造字段或复制整部剧本。

冻结前单独连读每个边界的末事件和后续首事件，暂时不看“无缝”等解释字段。连续时空要直接看得出谁在延续哪次运动，后一段不重新登场、变身或重演已完成动作；显式时空蒙太奇则能看出连接机制与新的状态范围。接不上时改真实事件与切点，再同步对象和关键帧，不能只改摘要。共同角色图只证明身份参考；空间身份与动作交接仍由实际场景/对象计划及正文承担。

先确定本轮的创作授权，再盘点来源发声。用户委托设计完整作品时，可在该目标与真实事实范围内创作所需的事件、讲解、对白或旁白；不要求用户先提供逐字稿或另外说出“允许原创”。授权范围由 Agent 结合完整请求判断，不由题材标签自动决定有声或无声。原文没有发声、没有录音、没有现成台词，只是来源事实，均不等于用户要求静音。用户明确要求无声、不新增台词或逐字忠实改编时，保留该限制。

把来源守恒与原创表达分开：`sourceCoveragePlan.speechLedger` 只收录已有的来源发声；用户委托范围内新写的人声进入 `narrativeAudioPlan.lines`，台账为空时仍可采用 `source_grounded_voice`。`visual_only` 表达的是本段确实由画面承担表达的创作决定，其理由应说明画面如何完成用户目标，不能以“未提供台词所以未经授权”代替判断。旧 Agent 的静音计划、默认 adaptationMode 或既有空台账都不能冒充用户禁止创作的事实；与本轮请求冲突时，在父级冻结前修订计划，保持来源与新增内容可追溯。

一键成片只创作一条覆盖完整交付范围的剧情线，物理 Clip 是这条线的执行窗口。先把全片的具体起因、主体行动、可见证据或后果、最终落点连起来，再分配时间；“介绍、展示、强调、收尾”只是功能名称，不能代替事件。叙事可以是人物冲突、操作过程、观察与发现或产品演示，不强制任何题材模板、冲突数量和结尾钩子。分段之后仍能按顺序复述同一件事，后一段使用前一段已经造成的状态或信息，不能每段重开场、重复卖点或单独促成一次结局。

来源是创作要求加真实素材时，先区分用户授权创作的剧情/口播与必须有依据的对象事实。图片只有 ID、文件名或旧 prompt 时尚未得到视觉观察；按当前问题使用已授权媒体理解并复用成功回执，再归并同一对象多视角、不同对象或使用情境。把有依据的身份、材质、结构、场景布局与不确定性放进共享对象不变量；全部片段沿用。外观不能证明成分、性能、价格或优惠，知识案例也不能补这些事实。需要更细方法时读取 `references/media-grounded-creation.md`。未知事实先保留未知并推进已支持部分，不能为了填满口播而编造。

在当前作者上下文把全片口播和动作放在同一时间线上比较：每条主张由哪一可见动作、细节或来源支撑，后一段新增了什么信息，最终结果回答了开场的什么问题。知识候选按这个具体缺口选择，正文只贡献可迁移方法；无关领域参考可以不读，无可用证据继续原创并如实记录。加载 Skill、读过案例或字段齐全都不能代替这个创作过程。

先在当前上下文内完成来源盘点，不把盘点报告写入最终 JSON：确认全部 canonical 人物、身份、场景、持物、动作顺序、站位、伤势、道具状态与明确人声；结尾钩子只有用户或权威来源明确要求时才记录。按“局面发生可见变化”的边界组织 beats；每段建立进入态、触发、选择或起势、过程或路径、接触或揭示、反应、不可逆结果和退出态。完整章节容量不足时增加合法 Clip，不删事实、台词或动作过程。

根级 `sourceCoveragePlan.speechLedger` 保存全部来源人声，按原文顺序为每行给出稳定 `lineId/speakerName/text`。原文无人声时使用空数组，这不决定作品是否有人声。`adaptationMode=faithful` 时各 `beats[].dialogueScript` 只能按顺序连续分配这些行，不得改词、漏句、重复、换人或倒序；原创或扩写授权内新增的表达仅进入 `narrativeAudioPlan`，不得伪装成原文对白，也不能编造来源对象的事实。`speakers` 可省略并由主机根据实际发声行投影。

根级 `sourceFidelityAudit.sourceBeatLedger` 只保存紧凑来源节拍：`sourceBeatId/sourceOrder/summary/durationSeconds`。`summary` 是一句原子事实，不复制原文长段，不写分析报告。每个来源节拍必须被有序 `storyEvents` 覆盖；`storyEvents` 从 0 秒起连续填满当前 Clip，逐项包含 `sourceBeatId/event/exitState/startSeconds/endSeconds`。首个入口由 beat 的 `startKeyframe` 表达，后续事件入口与 beat `exitState` 由宿主按事件顺序确定性投影；相邻事件和相邻 Clip 的状态因此只有一份可重建接力事实。

在切分任何一个物理 Clip 之前先完成根级 `chapterArc`，用 `storyPromise/protagonistThroughline/primaryPayoff/endingHook` 冻结整章共同方向；`endingHook` 只有用户明确要求或权威来源已有未闭合事件时填写非空字符串，否则必须为 `null`。每个 beat 再用 `dominantFunction/causalEntry/irreversibleResult/handoffToNext` 声明本段唯一主功能、进入因果、不可逆变化和下一段义务。首段只能从完整 BeatSheet 投影，不能先单独创作再要求其余章节倒推适配。

若用户明确要求全程高燃、持续动作或不收势，先冻结连续动作合同：每个时间窗都必须有可见运动、攻击路径、攻防选择、接触、位移、反作用、能力状态或环境反馈中的真实变化；禁止用建立镜、重新蓄力、观察停顿、完整收势、英雄定格、冷却余波、悬念钩子或未决结果填充时长。`open_motion` 只表示动作矢量仍在继续，不表示胜负或生死悬而未决。最后一窗验证明确发生的可见后果或仍在进行的动作，不提出新的未授权问题。

根级 `objectRegistry` 把全章真实参与因果的 character、scene、prop、vfx、palette 或 composition 各注册一次。每项使用稳定 `objectId` 与 canonical `kind/name/physicalIdentityKey/referenceRole/referenceImageNodeIds/referenceAssetIds/identityInvariant`；`forbiddenTransfer/scale` 为可省略的非空字符串字段，未知或不适用时省略，禁止用空串、null 或数字填位；character 的 `physicalIdentityKey` 非空，非 character 为 `null`。每个 Beat 的 `objectStates` 只通过 `objectId` 引用本段真实参与对象，并提交 `referenceAssetIds/referenceImageNodeIds/startState/spatialRelation/driver/stateChange/endState`。连续时空内，同一对象再次出现时 `startState` 继承它上一次声明的 `endState`；明确跨时间或换场时，在父序列的转场指令与事件中交代状态变化和新入口，保留同一身份，不把旧姿态强行复制到新时空。宿主会确定性展开下游 `assetObjectContracts`，Agent 不重复对象不变量。

`objectStates` 是本段完整的视觉出场清单，不是“状态发生改变的对象”或“主要说话人”的清单。逐段从完整动作、起止画面与人物互动理解实际入画主体：动作发起者、承受者、被触碰/扶起/观察者、共同持物者、可辨认的旁听与反应人物，以及实际出现的道具、所在场景和必要特效。状态不变的对象仍声明其保持状态；内心独白、画外音不等于人物不入画，发声名单不能代替出场名单。匿名人群由 Agent 根据连续性需要决定是否建立群体对象，不逐个虚构身份卡。

技能产生的外部造物也遵循对象与资产职责。造物持续参与束缚、支撑、持握、攻击或防御，且后续镜头需要认出同一形态时，父作者将其登记为独立 `kind=vfx/referenceRole=vfx` 对象，非角色的 `physicalIdentityKey=null`，并为全部出场 Clip 复用同一参考资产计划；不能只写在施术者的技能介绍或角色图里。成组造物可作为一个有明确成员与整体结构的对象，不逐个粒子建卡。已有真实资产就绑定精确 ID；没有资产就提交既有素材链能执行的完整计划，不能虚构已生成的 URL。瞬时闪光、碎屑等是否需要参考，由 Agent 根据实际身份连续性判断，不把所有特效一律资产化。

造物的 `identityInvariant/scale` 与资产提示词共同确定可辨认轮廓、结构、材质、颜色和尺度关系；参考画面清楚展示造物本体，不把施术者或承受者的脸、服装混入造物身份。逐段 `objectStates` 则记录它从哪里生成、连接谁的什么部位、锚定哪里、受力方向及仍完整/已断裂的部分。参考图不代替这些动作状态，也不要求受损造物恢复成参考图的完整姿态。断开、转移、消散或变形由实际事件表现，再同步下一入口；部分解除不能把其余连接一并抹掉。造物变形不等于施术角色变成另一个角色。冻结前沿所有出场片段检查同一对象、同一资产职责与连续状态，缺项就在父作者本轮补齐。

在同一次章级创作链内，逐 Beat 对照 `storyEvents`、`startKeyframe/endKeyframe` 和完整画面意图，双向复核 objectStates：画面中需要保持身份的每个对象都引用正确 objectId；每个被列对象都确实需要在本段呈现。发现动作写到双方而只列一人、人物特写漏所在场景、手持物体漏道具等不一致时，先修订实际 objectStates，再提交冻结 BeatSheet。角色图、场景图与群像构图图职责不同，不能相互替代；群像依赖由 Agent 按实际多人空间关系声明。引用只用 registry 的精确 ID，不以别名、类型前缀或列表位置猜对象。此检查属于 Agent 的语义自检，不交给宿主通过正文关键词判定，不新增用户级质量终态。

一键成片的每个视频 Beat 必须在 `objectStates` 引用至少一个 `kind=scene` 的已注册对象，场景参考属于必需输入。即使是人物特写或道具特写，也保持所在环境的同一场景身份；同一地点跨片段复用同一 objectId 和场景资产，换场才切换到对应场景。已有真实场景图时使用精确 referenceAssetIds/referenceImageNodeIds；缺图时保留明确场景对象交给既有素材生产链补齐，不能省略场景对象、虚构资产 ID，或用风格图、角色图、群像图代替。场景描述保持空间结构、出入口、固定陈设和光向，空场景卡不要出现人物；多人站位需要群像/构图参考时另设 composition 对象，并继续保留场景对象。提交前逐 Beat 核对场景引用是否存在且地点正确，发现遗漏在本轮修订后再提交。


只为成片中确实需要跨 Clip 保持可辨认身份、物件或空间连续性的对象建立参考资产职责。一次性路人、匿名围观者、背景人群或只承担群体反应的非核心群体，如果其个体身份无需跨 Clip 连续，必须在唯一首稿中设为 `referenceRole="none"` 且 `referenceImageNodeIds/referenceAssetIds=[]`，不要为其创建角色卡；若身份连续确实参与因果，再由 Agent 明确选择相应 referenceRole。runtime 不会通过关键词替模型决定，也不会在提交后纠偏。

若运行时提供非空 `selectedAssetIds + selectedAssetSnapshot`，每个 selected ID 都是必须消费的一等执行事实。依据快照与实际媒体观察完成对象归并，把每个 ID 原样写入恰好一个根级 `objectRegistry[].referenceAssetIds`；同一对象可保留多个有序视角，不同对象分别注册。共享场景、人物与物件的身份不变量只声明一次，各 beat 的 `objectStates` 消费同一身份并推进状态。禁止从文件名或选中数量猜材质、将全部图绑成泛称商品、漏图或另生成相似对象。宿主只派生逐 beat 对象合同并做结构校验，具体拒因沿同一逻辑任务回灌修复，不补绑、不替 Agent 解释对象语义。

## 唯一输出

最终根对象服从本轮动态 JSON 合同，使用 `sourceId/sourceFingerprint/protocolVersion/sourceCoveragePlan/sourceFidelityAudit/chapterArc/sequenceControlPlan/objectRegistry/beats`，仅在调用方要求时增加 `assetPlans`。其中 `sourceId/sourceFingerprint` 逐字等于冻结来源，`protocolVersion` 使用运行时精确值。

每个 beat 只允许：`clipId/clipIndex/durationSeconds/sourceSpan/narrativeIntent/visualIntent/dominantFunction/causalEntry/irreversibleResult/handoffToNext/startKeyframe/endKeyframe/exitState/characters/speakers/narrativeAudioPlan/dialoguePaceRate/storyEvents/objectStates`。`clipIndex` 从 0 连续递增；`exitState` 逐字等于末事件退出态；`characters` 只列真实出场角色，纯场景段允许空数组。原文人声只写根级 `sourceCoveragePlan.speechLedger`，新增且可追踪的叙事人声只写 `narrativeAudioPlan`；`dialogueScript` 由宿主从唯一人声台账投影，Agent 不重复输出。当前 beat 只要实际承载任一原文或新增人声，就必须提交由当前表演情境决定的正数 `dialoguePaceRate`；无发声时省略。宿主不提供默认语速，只执行数值、物理上限和可发声容量校验。

禁止输出 `filmBible/adaptationStrategy/castManifest/meta/continuity/dramaticChange/audienceExperience/payoff/emotionTurn/pacingDecision/temporalFrameTrack`，也不回显 authoritative source、生成合同、技能内容或分析过程。逐秒时间窗、事件覆盖索引、speaker 索引和其它机器字段由主机从紧凑 BeatSheet 确定性编译。

提交前在同一上下文复核一次来源覆盖、原文人声回拼、时长合法性、事件连续性、registry 引用、对象状态接力与 allowed fields；直接修订最终对象。运行时只接受最终完整 JSON，不输出 Markdown、解释、完成声明或局部补丁。

复核先回到用户目标，再检查内部计划：逐项找到目标对应的可听文本、可见动作或画面事实。只有标题里写了“讲解”“演示”或“行动号召”、实际事件却没有相应表达时，仍需在本链补写并重新分配时长。原稿未提供不构成用户输入缺口；确实未知的价格、成分、权限等事实才保留为未知，不用虚构承诺填满声音。讲到哪个对象或细节，当前事件就应让观众看到它；观察全貌与局部细节需要各自足够的可见范围和动作时间。先在全片确定表达和动作的时间关系，再切技术窗口，不让各段自行重写目标或重复开场。

这次复核必须同时摊开全部 beats，比对相邻段的末事件、首事件、关键帧、对象持握/位置和逐字口播，再回看 `chapterArc`：删除重复开场与无新增信息的展示，把后段提前发生的结果放回所属事件。连续场景的末态与下一入口描述同一个动作相位；明确时间/空间跳跃则由父计划写出变化、转场与新状态，不能把“同一剧情线”误解成所有片段同一机位或同一场景。镜头与事件的开始/结束时刻描述实际发生的阶段，不用一个覆盖多秒的总动作替代中间变化。修订发生在本 Agent 的创作链内，不新增宿主语义判分、检索配额或质量门禁。

对象注册字段类型：`referenceImageNodeIds`、`referenceAssetIds` 为字符串数组；`identityInvariant` 为非空字符串。可选的 `forbiddenTransfer`、`scale` 若提供，必须是非空字符串，不能是数组或 null；没有该说明时省略字段，不填占位值。

## 用户节奏与动作因果的冻结顺序

先核对本轮显式要求及 agents 从 Account user preference facts、真实记忆中选出的长期偏好，再写风格与时间设计。把材质画风、主体物理速度、剪辑频率、摄影减速分开：水墨、混合媒介、高武或“电影感”都不自动要求慢动作。旧 styleFacts 的建议与用户节奏冲突时，在父级冻结前修订建议，不能将冲突交给 writer 以改写剧情解决。

对已确认的疯切、极快节奏，按连续攻防分配动作时间：入线、接触/避让、立即反作用、位移或失衡、借势再攻。以不等长短镜和有动作依据的遮挡、方向、接触点、声音交接实现华丽转换；不可把“疯切”换成固定两秒镜头、视频帧率或一秒若干招的配额。没有新的约束、选择或结果时，不反复安排锁剑推压、蓄力、摆架，也不将大量总时长给慢落武器、倒地和收剑。用户本轮明确需要角力或慢放时按新要求设计，不篡改原文关键事件。

冻结前把每段最后一个 storyEvent.exitState、exitState、endKeyframe 与下一段首个 entryState、startKeyframe 放在一起比较；动作方向、持物、伤势、地面材质、空间破坏和未完成动势必须能相接。关键帧从最终事件链派生，不能保留前一版故事的横斩、落点或伤势。制胜动作的施力者、接触目标、实际后果必须明确，使 writer 不需要另编胜负原因。此为父 Agent 创作自检，不是后端语义门禁。

资产计划的完整 prompt / negativePrompt 是执行文本唯一来源；identityAnchors / prohibitedDrift 是同源身份元数据，宿主不得把列表拼接成另一份提示词。作者在同一响应提交前按精确对象身份，将 name、identityInvariant、完整提示词和身份元数据逐项与源事实对照并修订矛盾；不得按数组位置或相似职业复制另一对象的属性。

序列时间坐标：作者只决定 beats.durationSeconds、拍序、每段转场和必要 temporalDirectives；segments.startSeconds/endSeconds 与序列总时长由宿主按段时长累计生成，禁止为修正累计时钟改写已决定的剧情与段时长。temporalDirectives 仍使用真实绝对时间窗口。

## 发声身份与呈现方式

先按“实际说了几次”建立唯一声音台账，再决定每次发声如何被听见。原文消息的朗读、广播、电话、画外对白仍是来源发声；on_screen/off_screen/voice_over 是呈现方式，不是新增声音的理由。`mixed` 表示来源发声与额外创作发声并存，不表示两种声源或两种呈现方式并存。只有来源发声时使用 `source_speech_only` 且 `lines: []`，原文内容只在 speechLedger 中保存一次。确实需要新增人声时，逐项确认新增内容或有意再次发声的剧情作用，再放入 narrativeAudioPlan；不得复制原文行、换一个 lineId 后当作新增旁白。

冻结前按观众实际听到的顺序通读“来源发声 + 新增发声”。同一句话因来源台账与叙事音频两处登记而重复，必须在本 Agent 内修正；原文确实重复两次的发声应保留两次，不能按字符串相同删掉。重新安排发声时长和段间交接，语速描述必须与实际分配一致，不能用舒缓的说明掩盖赶读。交接比较的是同一动作的相位：本段抵达边界、下一段越过边界时，本段末事件和关键帧不能提前完成下一段动作。

### 同轮资产作者的职责合同

当本节点要求 `assetPlans` 时，在同一创作链消费 `tapcanvas-scene-card` 后产出场景参考计划。人物在场状态与空间身份分别表达：地点使用稳定名称和空间不变量；人群密度、拥挤、排队及表演留在 beats 的原有事件与对象状态中，现有 clip writer 已负责把这些内容写入视频。不得通过删剧情、改成空无一人的视频，或额外建立补人物流程来满足无人场景卡。

场景 assetPlans 必须提供 `sceneCard` 的 `sceneProfileVersion/sceneAssetRole/sceneOccupancy/sceneLightingSpec` 结构，分别为 `scene-card/v1`、`space_anchor`、`none` 和场景 Skill 编译的完整物理灯光合同。它与 `identityAnchors/prohibitedDrift` 一起进入持久节点；scene 项不携带角色 `identityBoardSpec`。人物和场景分别采用提交 schema 中对应分支，不为满足字段而虚构另一类资产。提交前按场景 Skill 同时复核名称、正向提示词、负向提示词和身份锚点，确保它们都表达无人空间，但原 Beat 仍保留完整表演事实。

一键成片的场景 authoring 分支只提交 `role/identityAnchors/prohibitedDrift/sceneCard`。可执行空间描述写入 `sceneCard.spacePrompt`，同图排除项写入 `sceneCard.negativePrompt`；不提交通用顶层 `prompt/negativePrompt`，以免剧情表演描述直接流入生图。投影器仅把这两个已创作字段逐字映射为图片执行字段，并校验往后各跳仍与原字段相同，不生成或改写语义。场景 Skill 上文的独立画布节点 `prompt` 仍表示这份空间描述在节点上的落点。


### 原文发声引用与新增发声

音频计划需要描述一条已有原文发声时，使用 `narrativeAudioPlan.lines[].sourceLineId` 指向当前 beat 的源台账 `lineId`。这是一条对已有发声的引用，不增加一次发声；其正文、说话人、呈现方式以源台账为准。只有实际新增的一次发声才令 `sourceLineId` 为 `null`；提交 schema 要求显式声明该字段。`afterSourceLineId` 只表示新增发声的插入位置，不能替代来源引用。

提交前逐条核对新增 lines 的来源：它是否已经在当前 beat 的源台账发声过？如只是原文消息朗读、内心声或画外呈现，引用原 lineId，或从新增 lines 移除并保留源台账。若剧情确实要求再次说同一句话，保留独立新增事件并说明再次发声的剧情作用。不要为了达到下游事件数量而机械重复原文。修订时沿用当前草稿，以稳定身份定位；重复身份使用报错中的数组位置修改，保留其它已完成内容。


## 来源盘点与物理切片分离

sourceBeatLedger 的一项是来源义务，不是一个固定 15 秒的物理片段。先从完整原文逐项盘点独立信息、话轮、思考、选择、因果与结果，再把其实际演出分配到一个或多个 beats/storyEvents。禁止从先写好的短版 beats 反向生成同样短的来源账本来证明完整；账本 summary 的存在不能代替画面或声音承载。紧凑输出只减少重复字段和无效修饰，不减少原文内容、必要反应或戏剧展开。

原文长话轮超过一个技术窗口时，在自然分句处拆成有序逐字片段，分别用稳定 lineId 和 clipIndex 分配；按原话轮拼接后正文、标点、说话人完全守恒。不合并跨越他人插话的发声，不因长句无法放入单个 Clip 而删句或提高语速。完整展开版先补充有来源依据的表演、心理可见化、铺垫和兑现，再推导总时长；同一来源单元可以被多个相邻 Clip 接续。

speechLedger 只登记原文人声，且每一条都必须逐字来自 canonical 原文（按序出现）。把原文对白改写成摘要、合并句意或自造一句“原文台词”，都属于台账来源失真：宿主会逐字比对并拒绝，这类压缩语应写进 `narrativeAudioPlan` 作为新增叙事人声。原文段落之间的换行或引号本身不算改写，逐字内容守恒即可。

复核时独立重读原始来源，逐段寻找真实承载，特别检查尚未进入自己账本的内容。明确区分用户要求的总时长、仅供讨论的估计区间与供应商单 Clip 上限。没有整体限时授权时不能将估算上界、旧 run 结果或成功样例当作压缩目标。


逐段引用合同（v22）：全局 objectRegistry 的引用是该对象的素材池，不是每段输入。每个 objectStates 显式提交 referenceAssetIds 与 referenceImageNodeIds 两个数组，选择当前段所需的有序子集，禁止省略后继承全集。已有引用的可见对象至少选择一张适用原图；没有已有引用的新增对象填写两个空数组，由原资产计划物化；referenceRole=none 对象也填空数组。整片的素材覆盖不等于每段重复全素材。逐段语义取舍与自检遵循 material-grounding，宿主只验证结构、成员身份并传递选择。

## 视觉方向的同链继承

先消费随声明依赖加载的 `cinematic-feel-director` 共同视觉基线。用户没指定影调时，整片作者也负责依据故事和媒介设计共享的光色、材质与构图方向，标明它是作者选择；有已确认项目方向则继承。无需询问用户选风格或额外生成风格图。

现有根 schema 不增加 filmBible：把共享视觉核心及场景变化写入各 beat 的 `visualIntent`，在 `assetPlans[].prompt/negativePrompt` 中按身份、场景、道具职责编译相同方向。剧情里未出现的灯光或空间实现，只能在本轮允许的原创设计范围内决定；已有资产、来源和项目事实始终优先。用于识别的中性角色/道具身份板不烘焙成片情绪光；场景和技术俯视底图仍保持其用途。

每段 visualIntent 是传给 writer 的事实输入，但不会自动成为供应商正文；writer 必须把适用内容写进 lighting/materialResponse/composition 等真正生成字段。复核实际资产提示词和 beat 输入是否共用同一方向，避免只有总述有风格而各资产仍泛化。创作质量不足在当前作者上下文内修订，不交给宿主语义闸门。
