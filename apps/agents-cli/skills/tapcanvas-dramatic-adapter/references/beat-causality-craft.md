# 拍与因果（切 beat 作者侧）

本资源随 `tapcanvas-dramatic-adapter` 骨架自动注入。它回答**一拍怎么才算成立**：因果七问、因果朗读、重复与升级的判据、转折要写成动作不写功能、机制耗尽与换代、扩写压缩重排的触发条件。章级审查流程见 `chapter-arc-audit.md`，机制模板见 `dramatic-mechanics.md`，本文件不重复它们。

## 一拍怎么才算成立

一条拍至少要能回答七个问题。它们不是新字段，每项都有既有落点；答不出说明这一拍还没想清楚，不是字段没填够：

| 问题 | 落点 |
|---|---|
| `because_of`：来自哪个进入事实或前序拍？开新线是否明确声明？ | `causalEntry` + `sourceBeatId` |
| `character_goal`：当前行动者想改变什么？ | 五块 `dramaticChange.objective`（内部推理锚点，见下） |
| `opposition`：谁或什么在此刻阻止？ | 五块 `dramaticChange.obstacle`（内部推理锚点，见下） |
| `observable_action`：可见或可听的行动是什么？ | `storyEvents[].event` |
| `state_change`：信息、权力、关系、情绪、风险或物理状态的前后差异？ | `objectStates[].stateChange/endState`；五块 `stateTransitions[].before/after` 同步做内部核对 |
| `next_pressure`：结果怎样迫使下一步发生？ | `handoffToNext` |
| 这条线在哪个稳定身份上推进？ | `payoff.debtId` / `lifecycleAction`（内部推理锚点） |

**上表的五块字段是内部推理锚点，不是提交字段。** 运行时合同明确禁止在工作流输出中序列化 `dramaticChange/audienceExperience/payoff/emotionTurn/pacingDecision`；只有没有版本化调用方 wire contract 的独立人工审稿交付才把它们写出来。回答七问属于"提交前想清楚"的工作，不得因此向 beat 添加禁用字段。

字段存在不代表因果成立。只按时间先后排列的事件仍然可能是空链。

## 用"因为／但是／所以"朗读

把相邻拍连起来读：

```text
因为前一结果，所以人物现在这样做；
但是对抗力量利用新状态反制；
所以人物必须改变策略或承担代价。
```

只能读出"然后"的地方，检查是否缺了人物选择、对抗反应、可见后果或下一股压力。这是**诊断语言**，不要求把这三个词写进任何字段，也不要求成品按这个句式呈现。

## 转折与兑现要写成动作，不写功能

**`reviewed_invariant`**：本拍的方向性转折与主要兑现，必须各自能指出一个**具体的可见动作（谁做了什么）**，而不只是它达成的功能、状态变化或结论。反对力量的筹码同样要写成它**做过或会做的事**，不是它的属性。

字段名会诱导人写功能：`dominantFunction` 问主功能，`irreversibleResult` 问改变了什么，`handoffToNext` 问下一段义务——这些问题都能用一句正确的话答完，而一句正确的话不是一场戏。

| 写成功能（不够） | 写成动作（够） |
|---|---|
| 他不再讲道理，用自己的信用担保 | 群里有人问他是不是急了的内部人士，他把打了一半的辩解删掉，只发出一条链接 |
| 裁决权从立场转移到作品本身 | 刚才喊举报的那个人点开了视频 |
| 上级选择维持现状 | 上级把申请表推回来，说等有了成绩再谈 |

左栏读起来都对，**审查时不会被任何门拦下**，因为它是对的功能描述；但把它交给下游，写作者拿到的是一个待发明的结论。右栏拿到的是一场戏。

判据只有一句：**这一拍，观众看见的是谁做了什么？** 答不上来的说明记录停在了功能层。这不要求在 beat 里写完整场次（那是下游的活），要求的是转折与兑现各自都指向一个可执行动作，哪怕只有半句。同一条纪律适用于 `obstacle`：「人多、态度一致」是属性；「他们已经约好一起去平台投诉」是筹码。

## 重复与升级的六条差异项

相邻两拍若 `dominantFunction` 相同，逐项比较。指不出下列任一变化时，后一拍只是前一轮的复述，无论场面换到哪里、规模加到多大：

- 谁掌握的**筹码**变了？
- 谁知道的事实变了（完全不知道／察觉异常／知道有人在做／知道是谁）？
- 哪条**关系的边界**变了（承诺、背叛、联盟、边界）？
- 哪条**退路**消失了？
- 谁作出了**不可撤回的决定**？
- 哪个后果**从威胁变成现实**？

**递增不能靠改写语义强度制造。** 身份或归属误认不能自动升级成偷窃、欺骗、背叛或罪责；"不断示意""持续沉默""多次尝试"也不能自动升级成更用力、更愤怒或更敌对。只比较源事实支持的次数、位置、可见痕迹、可用策略和后果。

## 一次运行与一次重复

一段落反复运行同一套机制时，判据只有一条：**把几次运行的顺序打乱，会不会损失东西**。不会损失就是同一件事的复述。

发现重复之后通常有两个修法，只有一个是对的：

- **换靶心（错）**：换一件全新的、与核心回报无关的事来写。重复消失了，但观众追的那条线也断了，几次之后会被描述成"后面不知道在讲什么"。
- **换向量、抬阈值、不换靶心（对）**：同一个矛盾点，用不同性质的东西回应，且这次的代价或规模比上次高一层；也可以换承担者，由新人物的态度完成同一次回应。判据不是"有没有换人换事"，而是"换过之后观众追的还是不是同一件事"。

失效判据：这个新事件与本剧的核心优势、核心矛盾关系很弱。短剧篇幅不提供容纳弱关联的余地，偏靶一次的损失会一直带到后面。

### 机制耗尽的症状与根因

出现两项以上就应处置：观众能提前说出运行结果和对手反应，猜中之后不再有期待；兑现规模变大而状态变化变小；必须靠加大羞辱、金额或围观者维持强度；**对手为了让机制继续生效，开始作出他自己都不该作的选择**。

最后一项是根因，也最容易被忽略：机制越有效，对手越必须变笨，世界越不可信。到这一步再修补，往往要回头重写更早的段落。

处置方式只有三种：**收束**（让循环以一次不能再重复的运行结束——机制被识破，或代价第一次落到主角自己或他保护的人身上）、**改造**（保留机制，换掉一项前提：适用范围、代价结构、知情者、或谁承担风险）、**移交**（把机制交给另一个人物使用，观众立场随之改变）。**并接不成立**：不处置旧循环直接在旁边开一个新的，旧账没还而新线又要从零建立理解，两边同时变弱。

换代真正丢掉的是**紧迫性**：旧循环攒下的可感时限、主角不能退出的理由、观众已押上的赌注没有交接过来。检查办法是问"如果主角这一轮什么都不做，会发生什么"，新循环的答案必须比旧循环更具体且更糟，而不是更抽象。

## 钩子、兑现与出去的压力

| 部件 | 观众问题 | 常见误用 |
|---|---|---|
| 钩子 | 为什么现在就要看？ | 与本段无关的奇观或故弄玄虚 |
| 兑现 | 这一段给了我什么？ | 只重复承诺，不产生结果 |
| 出去的压力 | 为什么状态还会继续运动？ | 隐去一句信息便草草结束 |

**`craft_default`**：在留下新压力之前，先给出本段自己的局部结果。开放结尾与未完成一段不是同一件事。出去的压力来自本段结果，而不是随意添加的新事故——本段的胜利让谁失去东西从而会怎样反制、新知识让谁必须立刻重选立场、人物为赢付出的代价何时到期、哪个被保护的人拒绝继续被保护、现在公开的事实把冲突带到哪个新场域。

结尾尽量把"会发生什么"升级成"某人已经决定做什么"或"某个后果已经启动"。仍以用户意图为准：用户要求全程持续动作或明确收束时，当前结果可以直接成为出口，不制造未解问题。

## 需要扩写、压缩还是重排

**扩写**不是增加闲聊，而是当前设计**跳过了必要的选择**。出现下列情况时补拍，新增拍必须明确它补足哪条因果或哪个状态变化：人物突然改变立场却没有受到足够压力；证据出现却没有获取、验证或争夺过程；代价被宣布却没有落到关系或行动；重大决定后没有让受影响人物作出回应。

**压缩**的对象：重复说明观众已经知道的事实；人物用同一策略遭遇同一反制而状态没有变化；只负责移动人物且没有产生选择的过场；两段拥有同一个进入状态、目标、转折和出去状态。手段是回到内容层（合并同质节拍、把说明改成传递、拆段），**不是按数字均匀删动作或砍台词**，后者砍掉的往往正是兑现。

**重排**前检查依赖：人物是否提前使用尚未获得的知识或道具；关系变化是否出现在原因之前；铺垫是否晚于兑现；伤势、时间、位置和公开范围是否仍连续；观众信息顺序改变后，体验是否仍是用户要的悬念或惊讶。重排后所有引用与显式交接必须重新解析。

## 艰难选择：两个方向都要活着

本节只在用户或来源**主动承诺"艰难选择"**的段落启用。"人物作出选择"不等于给出两个按钮；如果选择前已经说清一边没有价值或根本无法执行，剩下的方向只是顺序动作，不必硬包装成两难。写核心选择前分别回答：

- 选择 A 此刻保住什么，立刻失去什么？选择 B 呢？
- 为什么人物不能先后都做？时间、资源、承诺、身份或公开代价具体封住了哪条路？
- 人物行动后，失败的一边留下什么可见残余？

代价可以是资源、关系、身份、时间、秘密、承诺或自我认知。关键是选择前双方仍有真实价值；选择后只计算由该行动**新增或加重**的损失，原本无论如何都会发生的困境仍可施压，但不能重复记作这次选择的成本。

## 巧合与误会用在哪一侧

巧合有方向性：**把人推进麻烦可以，把人从麻烦里捞出来不可以。** 困境靠巧合解除时，前面所有挣扎都被追认为无关紧要。四条判据：位置（只用于制造问题的一侧）；代价（巧合送来的必须是负担不是礼物——捡到关键证据不成立，捡到证据而拿着它就意味着必须解释自己为什么在那里才成立）；世界是否建立过（同一栋楼、同一条通勤线内的偶遇是设定，毫无铺垫的偶遇是作者伸手）；只用一次（同一条线上第二次巧合就成了模式）。

误会的失效点几乎总在解除的那一刻。最常见的写法是"误会产生 → 拖了几段 → 解释清楚 → 一切照旧"，这样的误会整段可删。四条判据：人物有理由不解释（必须写出来）；观众的位置要选定并贯彻（观众知道真相＝悬念，观众不知道＝惊讶，摇摆的结果是两种都没有）；误会必须产生行动（只让人物心里难过的误会撑不起场次）；解除时必须有残余（关系回不到原点）。

## 容量可行性

一拍的容量在分派时长之前就要看一次。不看会这样失效：逐拍看都合理，每拍时长也各有理由，直到全部装到一起才发现总时长比目标长出三分之一——而此时台词、资产、关键帧都已经按这些拍做完了。

**`craft_default`**：用本项目**已接受产物**的比例做量级估算——从已接受的片段算出"每个时间单位平均承载多少剧本体量"，再换算待安排各段的量级，只关注明显偏差（例如某段是同项目均值的两倍以上）。

这**不是质量门槛**。比值来自项目自己的历史，不是跨项目标准；偏差是提示，交给用户判断，不阻断交付。还没有已接受片段可取样时（例如第一段）跳过估算。真实容量不足时的处理方向是回到内容层，不是把动作默认为瞬间发生。

## 空间距离与动作必须自洽

`startKeyframe` / `endKeyframe` 里写下的人物距离，就是下游必须遵守的硬约束。不要一边写"围在门前／面对面／前倾半步"，一边要求一个需要距离的动作。需要投掷类动作时，在首个关键帧明确把距离拉开并给出理由（不信任、戒备、有威胁物阻隔）；人物本就贴身时，动作只能是递交、放置、塞进手里。

判据：**手法选择不是物理必然**——递交还是抛出、走过去还是站着不动、先看谁后看谁，都是导演取舍，不能当成"给定原文事实后必然发生的物理后果"塞进事实因果账本。

## 失败征兆

- 各拍可以任意换序而不损失东西；因果链只是时间顺序。
- `dominantFunction` 换了名字，观众看见的动作没有变化。
- 转折写成它的结论（"裁决权转移了""他不再退让"），下游拿到的是待发明的任务。
- 反对力量的筹码是属性而不是行为。
- 兑现规模在变大而状态变化在变小；对手为了让机制继续生效而作出不合理选择。
- 本段所有答案都被推迟到下一段；结尾用省略一句话制造假悬念。
- 出去状态只有情绪形容，没有知识、关系、物理或行动事实。
- 用户并未承诺两难，却为显得深刻硬加第二条路径；或声称是艰难选择却提前让一边失效。
- 容量只看单拍不看总和，装到一起才发现超载。
- 已声明不可逆的后果被后续动作无意写回轻易可挽回。
