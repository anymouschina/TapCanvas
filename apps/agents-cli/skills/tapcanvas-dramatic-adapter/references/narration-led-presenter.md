# 口播讲解与真实音频对齐

用户要人物口播、商品讲解、旁白驱动演示，或已有录音需要配画面时按需读取。本参考帮助整片作者决定声音、人物与画面怎样共同表达本轮内容，不增加新输出合同、固定制作顺序、审批或质量闸门。

## 先分清声音来源

用户提供了真实录音，或本轮已授权合成的配音已经取得真实资产后，才可将该音轨作为媒体编辑的主时钟。时长取实际探针，发声与停顿回到实际音轨；文字稿、估算语速、待生成的音频节点与计划时长不能冒充录音证据。没有真实音轨时，依据用户意图和当前动态 schema 做创作与时长规划，不为满足本参考额外合成配音。

用户要求逐字口播时，保留正文、说话人和发声方式，数字、专有名词及外语的读法出现疑问时回到用户事实或实际音轨核对。画面说明、动作与语气指令不变成朗读正文；画外声音不变成画内人物对口表演。Agent 的转写、ASR、供应商字词时间戳都是派生材料，需注明来源和覆盖范围；它们可以定位候选发声片段，不能自行修改原稿，也不能独立证明实际说出了什么或口型同步。

已有录制媒体的编辑可以使用真实测得的发声区间与停顿安排字幕、切点和强调动画。生成阶段仍严格服从调用方当前章节、Clip 与 writer schema；不得新增或要求逐镜、逐句秒点字段，也不把媒体编辑时码写回不接受这些字段的生成合同。

当前 TTS 的 `audioTimingEvidence` 提供输出身份哈希、时长来源与供应商字词对齐状态。使用前核对其 `audioIdentity` 与本次音频一致；`alignment.status=unavailable` 不具备字词时间证据。分段拼接保留的 `segments` 只描述原始片段，不能累加成最终编码音轨的精确对齐。需要技术测量时可按 `tapcanvas-api` 合同调用 `tapcanvas_media_diagnose`，独立检查最终托管音视频；源配音探针与字词时间戳不能代替最终节目测量。

## 身份、素材与表达职责

人物身份来自用户授权的真实肖像、角色卡或明确人物事实，音色来自明确声音选择；不能从外貌推断声音，也不能把参考图视为声音克隆授权。当前操作已有授权时直接复用，仅确实缺少不可推导的权限或身份事实时请求补充，不另立通用审批环节。

逐段判断谁实际入画、谁实际发声、需要什么演示证据，再映射到现有对象、素材绑定与发声合同。人物可连续承载讲述，商品细节、操作过程或实际资料画面承担说明；同一对象的参考身份与原始资产 ID 保持可追溯。文字稿里提到的性能、经历或效果不因讲述而成为已证实素材事实，不借案例更换用户素材，也不为每一段机械插入人物、字幕或演示镜头。

## 真实媒体编辑与供应商边界

剪辑时分别辨认成片中的放置位置、保留长度和源素材读取位置。开场或上一段长度发生变化，只移动需要移动的成片位置，不把连续人物素材的源位置归零；检查相邻段是否重复读同一句、漏掉尾音或重新开始同一动作。字幕和强调跟随实际发声，阅读余量与安全区域由当前画面和用户目标判断，不套用上游固定秒数。

供应商有真实单次时长或参考音频限制时，可在已确认的录音停顿处选择技术切点，分别记录实际音频区间、请求时长与计费回执。请求时长取整等规则以该供应商当前合同为准；没有可用停顿属于当前分段方案的诊断，Agent 在授权范围内继续调整合法方案，不能据此删句、加速、换模型或终止整条目标。生成规划没有录音时，不伪造“实测停顿”。

复用已受理任务的原回执查询结果，避免重复提交与重复计费。用户明确要求新尝试时使用独立尝试身份，保留原资产、提示词与记录；用户选择自行重跑时停止代替用户提交。付费试片与额外修复只有本轮范围支持时才执行，不把“先试片”变成所有任务的必经流程。

## 用分层证据描述交付

根据当前任务选取必要证据，不要求每次跑完整检查：

| 证据 | 可以证明 | 不能单独证明 |
|---|---|---|
| 提交回执、任务 ID 与供应商状态 | 动作受理、处理中或供应商返回结果 | 已落画布、已合成、用户目标完成 |
| 真实输出 URL 与节点回读 | 资产已存储、结果落点和实际版本 | 能全程播放、正文准确或口型同步 |
| 实际输出探针与完整解码记录 | 时长、尺寸、帧率、流布局和可解码范围 | 人物身份一致、内容正确、声音与嘴形一致 |
| 原始音轨、声道与响度测量 | 实际有何声音、是否重复路由、测得的响度/峰值 | 从源配音推断最终成片响度，或从混音推断口型修复 |
| 带真实时码的连续视听观察 | 所观察区间的人物、发声、嘴形、素材切换与遮挡 | 静帧推断动态口型，局部抽样推断整片一致 |

如需响度处理，目标来自用户或当前平台的明确要求；测最终混合节目及实际交付版本，区分源配音与最终声道。单声道复制成双声道、原视频与外部配音同时保留等情况会影响最终声音，不能只用源配音测量宣称成片合格。黑帧、静止画面或接缝检测只报告实际事件与观察范围，由 Agent 结合表达判断是否需要修订；故意留黑、静态资料与画面停留不自动成为质量失败。

混音只改变音轨，不改变已经生成的嘴形。参考音频参与音画生成也不等于结果已经精确同步；需要时回看真实成片的可听发声与嘴形，记录具体差异。没有专用口型修复能力或真实修复回执时，不能把换音轨写成“修复了口型”。

以本轮 `expectedDelivery -> deliveryEvidence -> deliveryVerification` 收口：用户要成片时，文本方案、提交成功、单段视频或混音结果只能证明各自动作；依据真实合成输出、落点及必要的观察说明已完成部分和剩余部分。未获得某层证据就如实写未核验，不伪造检查结果。已经产出的媒体全部保留，后续诊断与修订只追加证据或新版本，不阻止已有结果交付，不因语义观察不满意而回滚、覆盖、丢弃或把总体任务变成 blocked/failed。
