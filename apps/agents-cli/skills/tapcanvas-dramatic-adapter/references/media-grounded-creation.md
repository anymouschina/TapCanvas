# 从真实素材与创作需求建立可拍事实

本方法用于来源是创作简报、产品素材、操作演示等场景。由 Agent 阅读完整用户意图后判断是否适用，不按关键词、本地 route 或输出类型选择。

## 区分用户要求、素材事实与允许创作的部分

- 用户给的是创作任务时，指令说明应交付什么，不是现成故事或逐字口播。设计完整作品的委托包含为其表达目标撰写必要内容，不以用户是否逐字说出“口播”或提供稿件为授权条件。声音策略由 Agent 理解完整目标后决定；来源没有对白不等于要求无声，用户明确要求静音或不增写时则保留限制。来源台账记录已有发声，不能裁决原创权限，具体字段遵循自动加载的 runtime-beat-sheet-contract.md。
- 原小说已有台词时继续遵守原文发声台账；创作需求中新写的口播进入 `narrativeAudioPlan` / 当前动态合同的声音字段，不冒充逐字原文。
- 总时长、产品范围、演示形态、声音和结果落点保留在同一任务合同。直播演示需要自然讲解与实际展示，不自动套小说冲突、悬念结尾或品牌形象片。

## 媒体观察与对象归并

`canvas-facts.selectedNodeFacts` 保存明确选中节点的已有描述与关联资产 ID；`metadata` 中的描述和旧 prompt 是来源元数据，不是视觉分析结论。结合项目许可快照解析同一素材身份，正文仍以 `authoritativeSources` 为准。`missingSelectedNodeIds` 表示输入选择未解析到节点，须如实记录该缺口，不能编造对应商品或把无关正文替换成其来源。

读取本次授权的图片候选 ID。`selected=true` 是明确选择；`selected=false` 是可供判断的候选，不代表不可读，也不代表必须使用。用户要求使用画布素材但未手动点选时，由 Agent 核对可见候选并选择，不要求用户为了让系统看图而再点选。

文字事实不足以确认对象时，通过 `tapcanvas_analyze_image` 询问当前任务真正需要的观察，消费成功分析及其 `provenance`。禁止把名字、旧 prompt、图片就绪状态当成观察结果。对已成功分析的相同图片和问题复用回执，改变观察问题时才考虑追加分析；失败没有视觉事实，不能凭空补齐，也不能用重复相同调用等待配置自行恢复。

按可见结构、标识、视角和用户资料判断多图关系：同一对象多视角、不同款、套装部件或使用情境。不能把图片数量当商品数量。同一对象的必要视角保留为同一个 `objectRegistry` 对象的多图引用；不确定的关系明确保留为不确定，不强行归并。

## 用证据提炼利益与演示

在同一 Agent 上下文建立简短事实台账，逐项区分：

- **直接观察**：形状、表面纹理、结构、可见操作与空间关系。
- **来源声称**：图片中可读的材质标签、参数与宣传文字，保留原文及来源 ID；不能说成独立实测结论。
- **推断**：依据外观或结构作出的判断，保留依据和不确定性，不能升级成确定参数或性能。
- **未知**：无法从素材确认的成分比例、材质等级、功效、认证、价格、优惠、销量等。

材质视觉质感不等于化学成分或质量等级。只将有依据的事实转成“特征 → 使用者利益 → 可见演示 → 对应口播”。利益是否成立由 Agent 结合完整事实判断，不用通用“耐用、舒适、高级”填充。可创作主播、场景与呈现方式，但不能发明产品结构、功能或商业承诺。

缺少用户明确要求的关键事实且无法推导时，先完成已支持的对象归并、展示规划与脚本部分，集中提出最小必要问题；说明具体哪句材质/参数无法确认。已受理任务与已有资产保留。补充输入继续同一逻辑任务，不要求重新上传已有图片或重启生产。

## 交接与自检

本台账是创作依据，不另造平行 BeatSheet schema，也不是运行时质量闸门。将采用的视觉事实与精确来源 ID/分析回执引用，映射到当前动态合同已有的对象不变量、`essentialCausality` 及来源说明；可拍展示映射到 `storyEvents`、关键帧和对象状态；逐字口播与说话方式映射到声音合同。只传下游需要的事实，不复制整份工具报告。

提交前核对用户要求的产品范围、总时长、口播、材质及利益说明是否得到具体承载。说到细节时镜头有对应细节，讲到操作时动作可见；多段沿用同一商品身份。实际媒体交付需要真实成片及声音执行证据；脚本、提示词或供应商受理本身不是成片。自检偏差在同链修订，不以评分、字数、关键词、检索命中数阻断任务。
