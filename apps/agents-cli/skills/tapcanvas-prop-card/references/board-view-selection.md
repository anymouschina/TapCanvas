# Prop Board View Selection

本参考只在创建或重建 `prop-card/v1` identity anchor 时读取。它帮助 agent 选择最小充分视图集合，不规定固定面板数量、画幅、背景颜色或文字标签。

## 可用视图职责

| viewRole | 解决的问题 | 何时使用 |
| --- | --- | --- |
| `hero` | 整体轮廓、比例、主材质与主要部件关系 | identity anchor 通常需要 |
| `front` | 正面接口、开口、标记与对称关系 | 正面是操作面或辨识面时 |
| `side` | 厚度、弧度、握持距离与部件前后层级 | 扁平物、武器、容器、设备常需要 |
| `back` | 背部固定、扣件、背带、走线与非对称事实 | 背面承担穿戴或连接功能时 |
| `top` | 口径、开槽、按钮、容器内部可见面 | 顶面承担交互或形态判断时 |
| `underside` | 底座、支点、轮组、固定孔与落地结构 | 支撑与受力取决于底部时 |
| `interaction_detail` | 手、身体或另一部件如何抓握、插接、开启、承托 | 交互方式不由整体视图充分表达时 |
| `mechanism_detail` | 合法可动部件、内部走线、卡扣、折叠或能量路径 | 来源明确存在内部机构且剧情会使用时 |
| `material_detail` | 磨损、纹理、接缝、铭刻、裂纹或表面状态锚 | 局部细节承担识别、线索或连续性时 |

## 选择原则

1. 先用 `hero` 建立整体身份，再只添加能消除真实歧义的视图。
2. 几何歧义优先选择正交/反向视图；交互歧义优先 `interaction_detail`；材料线索优先 `material_detail`。
3. 只有来源或设计合同明确存在内部机构时才使用 `mechanism_detail`。普通器物不得为了“专业感”强加 X 光、齿轮、能量核心或蓝图。
4. 尺度有来源时使用 `source_dimensions`；只有相对尺度时使用 `relative_scale_reference`；完全未声明时使用 `source_unspecified`，不得发明精确数字。
5. 多视图共享同一 canonical 轮廓、比例、部件数量、材质分区和基态。状态 variant 不借重画视图改变身份。
6. 图片模型不擅长可靠排字，因此结构字段与节点元数据承担标签；生成图默认 `readableTextVisible=false`，不要把说明文档画进资产。
